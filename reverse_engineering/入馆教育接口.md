## 1. 登录链（App 内全自动，复用学校统一认证 TGC）

```
App 已登录(TGC) → getServiceRedirectUrl(casServiceUrl)
  → 302 https://ssl.jxufe.edu.cn/cas/login?service=<casapi 入口>(带 ticket)
  → http://casapi.nczxst.com/Index/Login?targetUrl=%7Bbase64%7D…&ticket=ST-…
  → 302 http://casapi.nczxst.com/Index/Info
  → 200 纯跳转页: <script>window.location.href='http://tsgxs.jxufe.cn/web/User/cblogin?userid=<学号>&name=<姓名>&xyname=<学院>'</script>
  → 预热 tsgxs 会话(见下) → GET cblogin → 302 /Web/User 且下发 uid
  → POST /Web/User/SelectTheme {uid, tid} → {"Success":1,"Msg":"登录成功"}
  → 进入闯关首页 /Web/User
```

**CAS service（常量，service 必须 http，https 会报「未认证授权的服务」）**

```
https://ssl.jxufe.edu.cn/cas/login?service=http%3a%2f%2fcasapi.nczxst.com%2fIndex%2fLogin
  %3ftargetUrl%3d%7bbase64%7daHR0cDovL2Nhc2FwaS5uY3p4c3QuY29tL0luZGV4L0luZm8%3d
```

（base64 解码 = `http://casapi.nczxst.com/Index/Info`）

### 三个必须遵守的约束（踩坑记录）

1. **Cookie 必须按域隔离**：casapi（nczxst.com）与 tsgxs 都签发同名
   `ASP.NET_SessionId`。把 casapi 的会话 cookie 一起发给 tsgxs，会让 tsgxs 返回
   登录页（实测 47797 字节）而非已登录页。App 内 `TsgxsAuthRemoteDataSource`
   维护 `Map<host, Map<name,value>>` 的 jar，只发对应 host 的 cookie。
2. **跨域进 tsgxs 前必须预热**：`GET /Web/User` 匿名会 302 到 `/`（根页下发
   `from=0`），带 `from=0` 再取 `/Web/User` 才是 200 登录页，并签发 tsgxs 自己的
   `ASP.NET_SessionId`。cblogin 会把登录态绑到该会话上，顺序不能颠倒。
3. **cblogin 之后仍需 SelectTheme**：`POST /Web/User/SelectTheme {uid, tid}` 才是
   真正的「登录」，响应 `{"Success":1,"Msg":"登录成功"}`；成功后前端 JS 直接跳
   `/web/user/Index`。响应会重新下发 `uid`，需合并并持久化。

### 关键 cookie

| cookie | 说明 |
|---|---|
| `ASP.NET_SessionId` | tsgxs 自己的会话（必须来自 tsgxs 域，勿被 casapi 同名 cookie 覆盖） |
| `from=0` | 进入登录页的前置标记；缺失时 `/Web/User` 恒 302 到 `/` |
| `uid` | **账号级**鉴权标识（实测稳定，多次登录值相同） |

### 单点登录

tsgxs 为单点登录：带他人 `uid` 或旧会话访问会返回 103 字节页
`alert('您的账号已在别处登录，您被迫下线，请重新登录！');window.location.href='/web/user/Logout'`。
App 已识别该页并抛 `TsgxsSessionExpiredException`（提示重新建立会话）。

## 5. 会话登录链补全:首次登录的 `success=-2` 分支(2026-09-11)

### 5.1 症状与根因

App 报「考试状态获取失败：入馆教育会话已失效(HTTP 302)」，且换账号后变成
「cblogin 未完成，会话 Cookie 仅 `[ASP.NET_SessionId,from]`(缺 uid)」。

App 侧逐跳诊断(`%TEMP%\tsgxs_login_trace.log`)实证:

```
跳[0] 302 casapi /Index/Login?ticket=ST-*** -> /Index/Info
跳[1] 200 http://casapi.nczxst.com/Index/Info      ↳ JS跳转 -> tsgxs /web/User/cblogin?userid=…&name=…&xyname=…
    预热[0] 302 /Web/User -> /            预热[1] 200 /  Set-Cookie: from=0      预热登录页 200 /Web/User
跳[2] 302 /web/User/cblogin?userid=2000000002&… -> /Web/User?success=-2&uid=<uid>   ← 无 Set-Cookie: uid
跳[3] 200 /Web/User?success=-2&uid=<uid>           终点页 52561B（登录页外壳）
    登录态校验 200 len=51886 Cookie=[ASP.NET_SessionId,from]                      ← 仍是匿名态
```

登录页 JS(`/Web/User` 匿名页内嵌)给出各分支语义:

```js
if (res.Success === 1 || res.Success === 2) { $('.login_kuang').hide(); … window.location.reload(); }
else if (res.Success === -2) {                    // 统一认证已过，但还没选皮肤(角色)
    uid = res.Uid;                                // uid 由服务端放在跳转地址查询串里
    if ($('#tid').length > 0) { theme({ uid: res.Uid, tid: $('#tid').val() }); }
    else { $('.login_kuang').hide(); $('#themeBox').show(); }   // 弹「选择版式」
} else if (res.Success === 3) {                   // 学校已开启多次考试
    layer.confirm('系统已开启多次考试，是否需要重新考试？…', { … btn: ['是','否'],
      cancel: function () { $.post('/Web/User/RLogin', { uid: res.Uid }, function(){ window.location.reload(); }); } });
}
// theme() = POST /Web/User/SelectTheme {uid, tid}；Success===1 后 window.location.href='/web/user/Index'
```

结论：**cblogin 的分支取决于该账号是否选过皮肤**

| 账号状态 | cblogin 响应 | uid 从哪来 |
|---|---|---|
| 已选过皮肤(老账号，如主账号 / 微信抓包账号) | `302 /Web/User` | **`Set-Cookie: uid`** —— 无需额外步骤 |
| **首次登录**(如 2000000002 某同学) | `302 /Web/User?success=-2&uid=…` | 只在跳转地址查询串里,**不下发 cookie**;必须 `POST /Web/User/SelectTheme {uid,tid}` 才算登录完成 |

不补 SelectTheme 的后果：会话永远匿名态 —— 首页/章节页仍 200(匿名可看)，但
`/Web/Exam`、`/Web/Center/MyGrades`、排行榜一律 **302 `/web/user/logout`**。

皮肤 id(`input[name=tid]`，登录页三选一，默认勾选第一个)：
书生版 `5d037bb3-12c5-4554-a3c2-d128766dd025`(checked) / 战士版 `e3e409c4-7b51-4a75-a58f-92201dd6e660` / 校园版 `7d11523c-e79c-4b9f-b119-5b40a750b90d`。
学习进度为账号级，三皮肤共用。

### 5.6 「必须学完每个线索才能答题」= 后端门控 + 后门「补全线索」原理(2026-09-11 实测)

**结论:硬门控在服务端,前端只是显示用门控。**

| 时刻 | 服务端 `isVisitAll`(第 1 章) | `/Web/Exam?cid=` |
|---|---|---|
| 线索未学完 | `exam('false', …, 1)` | **302 → `/html/401.html`** |
| 学完 4 个线索后 | `exam('true', …, 1)` | **200 / 11630B,下发开考记录** |

- 客户端一行没改,只是用户把 4 个线索看完了 → 服务端自己把标记翻真、主动放行。
- 逐章实测(`tools/_tsgxs_gate_matrix.py`):第 1 章地图 200 / 答题页 200;第 2–5 章地图与答题页**双双 302 →
  `/html/401.html`**(顺序锁:上一章考试未通过)。
- 前端那层:章节地图内联的 `exam('<isVisitAll>', '<本章id>,<下一章id>', <examinations>)` 是**服务端写进 HTML 的数据**,
  网页 js 与 App 的 `canStartExam` 都只是照它决定按钮亮不亮 → 手敲 URL 可跳过,但跳过后**拿不到
  `examRecordDetailsId`**(服务端签发的开考记录号,`POST /web/Exam/GetAnswer` 必带),照样提交不了。
- 答案刷新:`GET /web/Exam/GetQueOpt?id=` 在开考前的 `answer` 恒空串、`iscorrect` 恒 false(连已通过章节亦然)——
  答案只能靠提交后服务端回吐。

**服务端靠什么记账「线索已学」**:全站没有独立的「标记已学」接口 —— 内容页 HTML 里没有任何 ajax / beacon
(仅内联倒计时 `#djs`、`isuser` 与新手引导 `loading.js`→`introJs`;`/Areas/Web/pc/js/zsb/js/intro.js` 是 404),
且**章节地图上节点的 `chapter grayscale` 不是已读标记**(`isVisitAll=true` 时 4 个节点仍全是 grayscale;
`sprite` 类名如 `tsggk` 才是语义)。唯一能解释标记翻真的动作 = App 逐条打开内容页(只有 GET),
即 **服务端在 GET 内容页时落库**。

**后门「补全线索」实现**(普通模式不做此步):
- `TsgxsRepository.sweepClues(account, {chapterId, themeId, dwell, onNodeFetched})` → 逐节点 GET 内容页

  (`total/fetched/alreadyLearned/verified/verifyAttempts`,`ok`、`summary` 供 UI 如实播报);
- `presentation/tsgxs_clue_sweep_action.dart` 的 `runClueSweep(ref, {chapterId, onProgress})` 为两个界面共用的编排
  (顺带写本地已浏览记录 + invalidate 章节相关 provider);
- 入口两处:① 答题页后门模式 —— 进入时若服务端拒开考则**自动补全并重开**一次,后门卡片里也有手动
  「补全本章线索」+ 进度条 + 结果行;② 章节页被「还不能开始答题」拦下的弹窗 → 「后门:一键补全并答题」→
  `TsgxsClueSweepScreen`(整页进度,成功后以 `initialMode: backdoor` 直接进答题页);
- 探针:`tools/_tsgxs_exam_gate_probe.py`(换 11 种入口/参数/方法试答题页)、`_tsgxs_gate_matrix.py`

- **仍未闭环的一环**:尚未观测到一次「纯 GET 扫描使 `isVisitAll` 由 false 翻 true」的干净实验
