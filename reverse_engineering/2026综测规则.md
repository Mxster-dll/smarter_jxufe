> 依据：《江西财经大学本科生综合素质测评办法》（江财学工字〔2024〕27 号）+ 2026 学生综合素质测评通知附件（表 8~表 21）。
> 用途：App「综测计算 + 材料管理」功能实现参考。分值以本文为准；竞赛目录见原文件 JS `CONTESTS`/`CONTESTS_ALIAS` 常量（移植时照抄）。

## 周期与程序
- 每学年一次：非毕业学年每年 9 月对上一学年；毕业学年每年 5 月。
- 程序：学生自评（填表 + 加分项**原始证明材料**）→ 班级评议（民主评议无记名打分，去最高最低 5% 取平均）→ 学院核查 → 公示 ≥5 天 → 部门审核 → 学校审定。
- 弄虚作假：扣加分、通报、当年度综测不合格（第十八条）。

## 单项等次 gradeOf(score, rank)（第十条）
- score < 60 → **不合格(fail)**；≥75 且 rank≠below → **优秀(ok)**；≥65 且 rank≠below → **良好(good)**；否则 **合格(pass)**。
- rank：前30% top30 / 前30~60% top60 / 60%后 below / 未知 unknown（unknown 视同非 below，按分数判断，结果偏乐观）。
- 体育红线：体测 <60 直接 fail（tGrade = tScore<60 ? fail : gradeOf(tTotal, rank)）。

## 综合等次（表 2，代码 order）
```
tml = [体育,美育,劳育] 等次
若 d==fail 或 z==fail           → fail
否则若 tml 中 fail ≥2            → fail
否则若 d==ok 且 z==ok 且 tml 全 ∈{ok,good} → ok
否则若 d,z ∈{ok,good} 且 tml 无 fail      → good
否则                                → pass
```

## 自动源按学年取数（用户 2026-09-16 裁定「综测按学年算」）

测评学年 `yearEnd` 的窗口 = `[yearEnd-1]-09-01 ~ [yearEnd]-08-31`（`zc_models.dart` 的 `zcYearWindowContains` / `zcDefaultYear` / `zcYearLabel`）；材料归属本就按此过滤，**两处自动源也改为按同一窗口**：

| 自动源 | 旧口径（跨学年累计） | 新口径（单学年） | 实现 |
|---|---|---|---|
| 智育·加权成绩 | `weightedGradeRankingProvider(1)` 教务「全部课程加权」（typeId 1 所有学年） | 学期码落在该学年的课程，`Σ(成绩×学分)/Σ学分` | `lib/features/zongce/domain/zc_year_sources.dart` 的 `zcWeightedForYear(grades, yearEnd:)`，数据 = 成绩缓存 `gePriorGradesProvider`（离线） |
| 劳育·志愿时长 | 全部第二课堂活动 `recognizedHours` 求和 | 活动日期落在学年窗口的活动时长 | `zcVolunteerHoursForYear(acts, yearEnd:)` → 复用 `volunteerHoursStats(acts, xn: yearEnd - 1).currentYear` |

- 学期标识解析 `zcSemesterStartYear(String)`：短编号 `'251'/'252'/'253'` → 2025（学段 3 = 第二阶段仍属同一学年）；完整名 `'2025-2026学年…'` → 2025；**认不出 → null，不参与「属于哪个学年」的判定**（但在加权里并入该学年，见下面 2026-09-17 条）。
- provider 形态：`zcAutoWeightProvider` / `zcAutoVolunteerProvider` 均为 `FutureProvider.family<double?, int>`（参数 = 学年结束年），页面传 `_year`，刷新按钮同时失效底层源（`gePriorGradesProvider` / `volunteerActivitiesProvider`）。
- 取不到 → **null → 界面回退手动填写，不显示 0**（与「入馆教育会话不可用不算未通过」同一约定）。
- 实测（账号 2000000000，成绩缓存 26 门）：25 门带学期码（全为 251/252）+ 1 门学期码为空（`程序设计实训`）；**2025-2026 学年（yearEnd 2026）课程加权 = 91.85964912280701**，与成绩页「课程加权」逐位相同；yearEnd 2025 / 2027 均 null（该学年没有学期码明确的课）。
- 守卫 = `test/zc_year_sources_test.dart`（学期码解析 / 学年内加权与窗口边界 / 志愿窗口边界 / 空与脏值 → null / 源码守卫：family 形态、`_year` 传参、旧文案与 `weightedGradeRankingProvider` 不得回归）。
### 智育必须是「课程加权」而不是「推免加权」（用户 2026-09-17 裁定）

用户原话：「综测页智育部分自动获取的成绩应该是课程加权，而不是推免加权」。三套口径实测（同一账号，成绩缓存 26 门）：

| 口径 | 公式 | 全学年 | 2025-2026 学年 |
|---|---|---|---|
| 课程加权（成绩页 `_calcAvgScore`） | `Σ(成绩×学分)/Σ学分`，排除 `kExcludedGradeCourses` | 91.85965 | 91.85965（该生全部课都在此学年） |
| 推免加权（成绩页 `_calcRecommendationScore`） | `0.7×主干课均分 + 0.3×非主干课均分`（主干/非主干取自培养方案 `CourseImportance`） | 91.90833 | 91.92255 |
| 旧的智育口径（按学年、丢掉认不出学期的课） | 同上但按学期码过滤且丢弃 `semester` 为空者 | — | 91.89091（少 1 门 2 学分课 → 与课程加权差 0.03） |

- 结论：智育**从来没用过推免口径**；对不上的原因是「学期码认不出的课被丢掉」。
- 修法 = `zcWeightedForYear` 把 `semester` 认不出的课**并入该学年**（与成绩页课程加权同样不过滤掉这些课），但**若该学年一门学期码明确的课都没有则仍返回 null**（免得一门无学期码的课把每个学年都凑出一个分）。
- 界面文案（`zongce_screen.dart` 智育①note）= 「取该学年成绩缓存（课程加权口径，与成绩页「课程加权」一致，非推免口径），留空即用自动值；也可手动覆盖」。
- 守卫 = `test/zc_year_sources_test.dart` 的「学期认不出的课并入该学年」例（含「不能单独凑出一个学年」）。

- 注：教务加权接口本身没有「任意学年」档位（typeId 只有 1 所有学年 / 2 上学年 / 3 上学期 / 4 分流 / 5 毕业 / 6 辅修 / 7 推免），故按学年只能由**本地成绩缓存 + 学期码**自行加权。
