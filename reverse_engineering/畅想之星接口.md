> 反逆向时间：2026-09-12 ~ 09-14。来源：微信「蛟湖阅读」宫格 →「畅想经典阅读」应用
> （`v1.chaoxing.com/wechatSet/...` 302 到 `m.cxstar.com/?wfw_token=…&fidEnc=…&mappId=12340323`）。
> 抓包产物：`%TEMP%\mitmflows_cx_20260912-114859\flows.flows`（11.7 MB / 409 flows）；
> 前端主包 `%TEMP%\_cx_js\main.b5875c38.js`（5.78 MB 混淆）。

## 1. 站点与调用约定

| 项 | 值 |
|---|---|
| API 域 | `https://m.cxstar.com`，**所有接口都在 `/api` 前缀下** |
| 裸路径后果 | 命中 React SPA 壳（3327 B HTML，`<div id="root">`），恒 HTTP 200 |
| 静态资源 | `https://p.cxstar.com/readerv2/…` |
| 鉴权 | **`Authorization: Bearer <JWT>`**（同一串也作为 cookie `mtoken` 下发/回传） |
| 会话寿命 | JWT `exp - iat = 86400`（24 小时） |
| 入口参数 | `wfw_token` / `fidEnc` / `mappId` 是**智信侧包装参数，SPA 不读**（主包 0 命中），不能当会话令牌 |

> 早期误判：以为鉴权头是 `userToken`、cookie 是 `token`。抓包实测纠正为 `Authorization: Bearer`。
> `wfw_token` 六种传法（Cookie `token=`/`wfw_token=`、头 `userToken`、`Authorization`、query）都不能换到个人身份。

## 2. 认证链（三条）

### 2.1 个人会话 = 学校统一身份认证（App 已实现）

```
GET https://m.cxstar.com/login
  → 302 https://ssl.jxufe.edu.cn/cas/login?service=http%3a%2f%2fua.cxstar.com%2funiauth%2foutLogin%2flogin517%3fgotoUrl%3d2
  → CAS 校验 ticket（项目既有 TGC 换票，service 必须 http）
  → https://ua.cxstar.com/uniauth/outLogin/login517?…
  → 回跳 https://m.cxstar.com/…?token=<个人 JWT>   ← 个人 token 落点之一
     或 Set-Cookie: mtoken=<个人 JWT>              ← 落点之二
```

- 个人身份实测：`GET /api/user` → `userName=517_<学号>`、`realName=某同学`、`schoolId=1cdceffd0000020bce`；
  JWT claims `loginType=7 / type=1 / uid=517_<学号> / cc=517`。
- App 实现：`lib/features/cxstar/data/datasources/cxstar_auth_remote_datasource.dart`
  （`casServiceUrl` 常量 + `establishSession` 逐跳抓 token：**回跳地址 query → Set-Cookie → 正文** 三处扫描，
  SPA 壳（含 `<div id="root">`）里的 token 不采信，避免把 localStorage 旧串当新会话）；
  仓库 `cxstar_auth_repository.dart`（按账号持久化 `cxstar_tk_<账号>`，票据一次性 → 失败重走整链一次）；
  `getSessionToken()` **不抛异常**，失败返回 null 由上层降级。
- 有效 TGC 才能换证：headless 测试无法过 MFA，需在 App 内正常登录一次
  （`app_data/auth.hive` 的 `TGC|<账号>` 键刷新）。缓存 TGC 失效时 CAS 返回 200 登录页（约 169 KB）。

### 2.2 校园网 IP 免密（公用账号，非个人）

```
POST /api/auth/ip_login   （JSON body {}）
→ {"code":"1","text":null,"token":"<JWT>","expiration":7200,"isNeedTX":false}
```
- claims `loginType=3 / uid=IPUSERjxcdadmin`，`realName=IP用户`；**全校公用账号**。
- 其 `readsummary` 是**全校聚合**：`readCount=2160`、`readMinutes=273329`（个人对照：12~13 本 / 1321~1323 分钟）。
- 只能作为兜底展示，**不能用于学分口径**；App 界面必须标注「校园网公用账号 · 全校聚合数据」。

### 2.3 其他（不可用/未打通）

- CARSI：`ua.cxstar.com/uniauth/outLogin/wayFless?token=…` → `spoauth2.carsi.edu.cn` → IdP 发现页；
  **江财 IdP `https://idp.jxufe.edu.cn/idp/shibboleth` 证书 2019-12-20 ~ 2022-03-20 已过期**，
  `…/idp/profile/SAML2/Redirect/SSO` 返 400 Stale Request → 该路对全校用户都是坏的。
- 微信 OAuth：`GET /api/auth/wechat?openid=` → 303 `open.weixin.qq.com/connect/oauth2/authorize?appid=wxc8cd3bc45b9952ff…`，
  App 拿不到 openid（同 GUID 困境）。
- `/api/auth/wechat/ticket?url=…` 返回的是**微信 JS-SDK 签名**（noncestr/timestamp/signature），不是票据接口。
- `POST /api/auth/login`（JSON）存在但字段被混淆挡住：`{"code":"-1","text":"appLoginError:图书馆选择错误或用户名密码错误"}`。

## 4. 阅读计时机制（用户最关心：「时长要能正常计入」）

阅读器页面 `/book/<bookId>/pdf`（React SPA + pdf.js）会发：

| 接口 | 说明 |
|---|---|
| `GET /api/books/<id>/read?page=N&isNewPdf=1&from=default&pinst=<pinst>&nonce=<uuid>` | 取分页内容，返回 `content` = `https://mirrorxz.cxstar.com/newcxstarapi/api/OnlineEBook?filePath=…` |
| `GET /api/books/<id>/pdfContent?typecode=ebook&pageno=N&bookId=<id>&pinst=<pinst>` | 原始 PDF 字节（`%PDF-1.4…`） |
| `GET /api/books/<id>/read/progress` | `{"page":N}` 上次读到第几页 |
| `POST /api/books/<id>/read/progress` | body `{"page":1,"paragraph":0,"charIndex":0,"logId":"","percent":0}` → 200 空体（翻页上报） |
| `GET /api/books/<id>/state?now=<ms>&ipToken=null&pinst=<pinst>` | `{"sJFlag":true,"ipLogin":false,"read":true,"isbn":"…"}` |
| 另有 | `catalog?filetype=0`、`hotcomments?size=1`、`user/bookmarks/<id>`、`SearchFullTextCount` |

**结论：阅读时长由服务端按在线阅读行为累计（翻页/取内容请求都会计入），客户端不上报时长字段。**
因此只要 App 内阅读走同一套 `read?page=` / `read/progress` 请求，时长就会正常计入个人账号；
用 IP 公用账号阅读则会记到公用账号上（所以必须先切个人会话）。

## 7. 阅读器（原生渲染 + 阅读计时，2026-09-14）

### 7.1 请求签名
- 阅读器接口全部要 `nonce` / `stime` / `sign` 三参数，**缺任一恒 404**（IIS 404 页）。
- 算法（逆向自 `p.cxstar.com/readerv2/static/js/main.b5875c38.js`，offset 1578501 的 `_0x351c9b`，
  密钥藏自校验 IIFE 字符串表的 `MTIzNDU2`）：

  ```
  sign = MD5("123456" + nonce + stime).hexdigest().toUpperCase()   # nonce = uuid4, stime = 秒级时间戳
  ```

  抓包 8 条真值 8/8 命中；线上实测 200。与页码 / 书号 / pinst / 令牌**无关**。

### 7.2 单页口令（本次新破解）
- 每页正文是**独立的单页 AES-128 加密 PDF**：`/Type /Page`=1、`/V4 /R4 /Length128 /CFM AESV2`，iText 5.5.13.1。
- **用户口令 = `md5("<bookId>-<pageno>")`（小写 hex，逐页不同）**：

  | 页 | 字节数 | 口令（md5） |
  |---|---|---|
  | 1 | 227350 | `81a2d0f0b7e99ec671094e4b1b8db3fb` |
  | 49 | 739385 | `6746799b0ae16cd82cc595152f595ea7` |
  | 60 | 478565 | `1e1105c1f4403b8a0d48abb7a276063e` |
  | 100 | 512531 | `830e1502444910ece3d819c0bcc4a94b` |

- 破解路径：`pdfjsLib.getDocument({...})` 调用点（bundle 内 `'cMapUrl':'/pdf/cmaps/'` 处）写着
  `'password':_0xcde644()(_0x2c926f)['toString']()`，其中 `_0x2c926f = <query>['bookId'] + '-' + <query>['pageno']`
  （形如 `query[bookId]-query[pageno]`），`_0xcde644()` 是 crypto-js 的 md5 模块 → 得到上述公式。
- 校验：**空口令被拒**（`pikepdf`(qpdf) 报 `PasswordError: invalid password`，pypdf 官方解密器同样失败）→
  口令确实非空；用上表口令在 `pikepdf 10.13.0.post1` 与 `pypdf 6.14.2` **两套独立实现**上均解密成功，
  并抽出中文正文（如 p100 = 「图 ３ — １７ 不同的公共支出规模…」）。
- 破解前的错误假设（别再走）：口令在 `/read` 响应里（实测只有 `content`(死链) / `logId` / `token` /
  `totalPage` / `trialPage` / `watermark`，无口令字段）；口令 = `read` 的页级 `token`（p60 的 token
  是 UUID，仍解不开）；口令 = pinst / ISBN / 书号 / 水印 / JWT 分段（26 项候选全灭）。

### 7.3 接口清单（都要 7.1 三参数）
| 用途 | 请求 |
|---|---|
| 阅读会话 | `GET /api/books/{id}/read?page=N&isNewPdf=1&from=default&pinst=…` |
| 单页正文 | `GET /api/books/{id}/pdfContent?typecode=ebook&pageno=N&bookId=…&pinst=…` |
| 目录 | `GET /api/books/{id}/catalog?filetype=0` |
| 续读位 | `GET /api/books/{id}/read/progress` / `POST` 同路径 `{page,paragraph,charIndex,logId,percent}` |
| 阅读资格 | `GET /api/books/{id}/state?now=<ms>&ipToken=null&pinst=…` |

鉴权 = `Authorization: Bearer <个人 JWT>`；请求带 `Referer: https://m.cxstar.com/book/<id>/pdf`。
接口必须在 `/api` 前缀下（裸路径返回 SPA 壳）。`/read` 的 `token` 字段与试读无关（page 1 为 null、
页码 ≥ `trialPage` 为稳定 UUID），**不是**口令。

### 7.4 阅读计时机制（用户硬要求，已实测）
- 时长由**服务端**按在线阅读行为累计，**客户端不上报时长**；`POST read/progress` 非必要。
- 受控实测（2026-09-14，`%TEMP%\_cx_timing.py`）：

  | 阶段 | 行为 | 墙钟 | `readMinutes` |
  |---|---|---|---|
  | A | 取 1 页（`/read`+`pdfContent`）后**完全空闲** | 120s | **+1** |
  | B | **只发 `/read`**（不拉正文）×3，间隔 30s | 120s | **+1** |

  总计 1351 → 1353 分钟、今日 14 → 16 分钟 → 结论：**会话内每 60 秒一次轻量 `/read` 心跳即可持续入账**，
  无需重复拉正文（省流量）；入账粒度约 1 分钟，且**结算有延迟**（10 秒内连续请求可能 Δ=0），
  所以不要向用户承诺「1 页 = 1 分钟」。

- **是否存在「同一页停留超时就不计入、必须翻页」的封顶？（用户 2026-09-14 提问，已实测否定）**
  受控实验 `tools/_cx_dwell_timing.py`（个人会话，在读图书《邓小平与中国特色社会主义》，22:00–22:15）：

  | 阶段 | 行为 | 逐分钟 `readMinutes` |
  |---|---|---|
  | A（8 分钟） | **同一页**（page=3）每 60s 一次 `/read` 心跳，不翻页 | 1491 → 1492 → 1493 → 1494 → 1495 → 1496 → 1497 → 1498（**每分钟稳定 +1**），第 8 分钟读数跳到 **1514（+23）** |
  | B（5 分钟） | 拉 page=4 正文（64233B）+ 上报进度，之后继续每 60s 心跳 | 1514 → 1516 → 1517 → 1518 → 1520 → 1522（仍是约 1/分钟，未见加速或减速） |

  → **结论：没有「每页 / 每次翻页」的时长封顶**。同一页停留 8 分钟里 `readMinutes` 与 `todayReadMinutes` 同步 +1/分钟；
  翻页既不是入账的必要条件，也不会让入账变快。**应继续保留 App 的 60 秒心跳**（它是「停留也在计」的手段）。
  A 阶段第 8 分钟那次 **+16 的突跳是服务端批量结算**（同一秒 `readMinutes` 与 `todayReadMinutes` 一起跳 +23），
  与既有「结算有延迟」结论一致 —— 所以 App 底部「今日已计 X 分」可能几分钟不动、然后一次跳好几分钟，
  这**不是**计时失效，界面文案已按此口径（`_refreshTodayMinutes` 每 5 次心跳刷一次）。

- ⚠️ **Windows 构建坑**：`pdfrx` → `pdfium_flutter` 的 `windows/CMakeLists.txt` 用
  `file(DOWNLOAD https://github.com/bblanchon/pdfium-binaries/releases/download/chromium%2F7520/pdfium-win-x64.tgz)`
  拉 pdfium，本机 GitHub 直连失败会留下 **0 字节 tgz**，随后报
  `file COPY cannot find "build/windows/x64/pdfium/chromium%2F7520/bin/pdfium.dll"`。
  修法：用 `https://ghfast.top/` 前缀手工下同名 tgz，解压到
  `build/windows/x64/pdfium/chromium%2F7520/`（需含 `bin/pdfium.dll` 与 `include/`）后重建即可
  （CMake 检测到文件存在会跳过下载）。
- ⚠️ **测试环境坑**：`PDFIUM_PATH` 指向**含 `%2F` 的构建目录**时 pdfium 加载失败
  （`Failed to load dynamic library 'pdfium.dll' … error code: 126`）；把 dll 复制到干净路径
  （如 `D:\Temp\pdfium\pdfium.dll`）再指向它即可。桌面 App 自身不受影响（CMake 已把 dll 复制到
  `build/windows/x64/runner/Debug/pdfium.dll`，运行时按 exe 同目录加载）。

### 9.1 接口（均在 `/api` 前缀下）

| 用途 | 请求 | 关键点 |
|---|---|---|
| 分类字典 | `GET /api/system/categories?pinst=<pinst>` | **必须带 `pinst`**，缺参数恒 **500**；返回体是**字典不是 data 列表** |
| 分类书单 / 检索 | `GET /api/categories/{categoryId}/books?page=N&size=20&pinst=<pinst>&sortField=orderno&sortType=DESC&keyword=&Publishers=&Authors=&Pubdates=&Types=&Aggs=false` | `keyword` 即检索词（urlencode 中文可用）；`page` / `sortField`（`readNum` 亦可）实测有效 |

| 读者对象 | `GET /api/system/readerobject` | `[{"id":"benke","readName":"本科"},…]`（本次未用） |

## 10. 修复记录

- **`Bad state: Pdfrx getCacheDirectory is not set. Please set it to get cache directory.`（2026-09-14，用户实测报错）**
  根因：`PdfDocument.openData` 是 engine 层直调，**不会**像 `PdfDocumentRef` 那样自动 `pdfrxFlutterInitialize()`，
  而 `Pdfrx.getCacheDirectory` 只由 `pdfrxFlutterInitialize()` 设置
  （`pdfrx-2.2.24/lib/src/pdfrx_flutter.dart:37` → `Pdfrx.getCacheDirectory ??= getCacheDirectory;`）。
  修法两处（幂等）：`lib/main.dart` 在 `WidgetsFlutterBinding.ensureInitialized()` 之后加
  `unawaited(pdfrxFlutterInitialize());`；`cxstar_reader_screen.dart` 的 `_CxstarPageViewState._open()` 首行
  `await pdfrxFlutterInitialize();` 再 `PdfDocument.openData(...)`。
  注：Dart（非 Flutter）模式用 `pdfrxInitialize()`（优先 `PDFIUM_PATH`，否则从网络下载 pdfium）。

- **阅读器翻页 off-by-one（2026-09-14，用户实测「一般只能从第一页翻到第二页，内容变了，但是底部的页码还是显示 1，并且不能继续翻页，往回翻也不行」）**
  根因：`PageView.onPageChanged` 回调的是**从 0 开始的索引**，而
  `lib/features/cxstar/presentation/cxstar_reader_screen.dart` 的 `_onPageChanged(int page)`
  直接 `_currentPage = page` → `_currentPage` 恒比真实页码小 1，三处症状同源：
  底部栏显示旧页码；`onNext` 恒 `_jumpTo(1+1)` = `jumpToPage(1)`（= 第 2 页，停在原地）；`onPrev` 的
  `_currentPage > 1` 恒 false → 按钮禁用，翻不回去。续读位上报的页码也一律少 1。
  修法：`final page = index + 1;`；`_jumpTo(int page)` **自己落 `_currentPage`**（不依赖 `jumpToPage`
  是否派发滚动通知，页码与按钮立刻一致）；新增 `_step(int delta)` 与桌面键盘
  `← → / PageUp / PageDown`（`CallbackShortcuts` + `Focus(autofocus: true)`）；新增 `_zoomed` 状态，
  放大时 `PageView.physics = NeverScrollableScrollPhysics()`（否则 `InteractiveViewer` 与 `PageView`
  抢手势），子页通过 `onZoomChanged` 上报，换页 / jump 自动退出缩放。
  实测（临时 widget 探针，用完已删）：`InteractiveViewer(panEnabled: false)` 作为 `PageView` 子项
  **不影响**拖拽翻页（连续拖拽 `onPageChanged` 依次 1、2、3）；`jumpToPage` **会**触发
  `onPageChanged`（`controller.page` 同步更新）→ 说明 off-by-one 是唯一根因，不是手势冲突。
  守卫：`test/cxstar_reader_paging_test.dart`（3 例，假数据源驱动真实 `CxstarReaderScreen`：
  拖拽翻页后页码同步 / 上一页·下一页按钮与页码一致 / 末页「下一页」禁用）。踩坑：`find.byTooltip`
  命中的是 `Tooltip` 自身，要断言按钮可用性需 `find.ancestor(of: byTooltip, matching: byType(IconButton))`。

- **数据不会自动刷新（2026-09-14，用户实测「不论是阅读界面右下角的时长还是总览卡片的时长，都无法自动刷新，前者必须重进阅读才刷新，后者必须点击重新获取令牌，然后才刷新数据」）**

  根因（两条独立）：
  1. **总览卡**：统计挂在缓存型 `cxstarOverviewProvider`（`FutureProvider`）上 —— provider 不被
     `invalidate` 就永远返回同一份缓存，`CxstarScreen` 重建也不会重新取数；此前唯一的失效点是
     用户手点「统一身份认证 / 手工令牌 / 重试」或下拉刷新。
  2. **阅读器右下角**：`_ping()` 里写的是 `if (_pings % 5 == 0) unawaited(_refreshTodayMinutes());`
     —— 心跳 60 秒一次 × 5 = **5 分钟**才刷一次统计，看起来就像「不刷新」。

  修法：
  - 新增 `lib/core/navigation/page_auto_refresh.dart`：
    - `appRouteObserver`（`RouteObserver<ModalRoute<void>>`，在 `lib/main.dart` 的
      `MaterialApp.navigatorObservers` 注册）→ 提供「上层路由被弹出」的事件源；
    - `PageAutoRefresher`（**组合式挂件**，`with RouteAware, WidgetsBindingObserver`）：
      `start()` 在 `initState` 里注册前后台观察者 + 首帧后刷新一次，`subscribeRoute(context)`
      在 `didChangeDependencies` 里订阅本页路由（`didPopNext()` → 刷新），
      `dispose()` 注销。**为什么不做成 mixin**：`RouteAware` / `WidgetsBindingObserver` 是接口形态，
      mixin 里的 `this` 传给 `subscribe(...)` / `addObserver(...)` 会报
      `argument_type_not_assignable`，而用 `implements` 又被迫实现那几十个回调（且随版本增加）。
    - `invalidateIfLoaded(ref, provider)`：**首次加载中（`isLoading && !hasValue`）跳过**，
      否则 `build` 刚发起的请求会被立刻重发一遍（页面首帧双重请求 + loading 闪烁）。
  - `lib/features/cxstar/presentation/cxstar_screen.dart`：`ConsumerWidget` → `ConsumerStatefulWidget`，
    挂 `PageAutoRefresher(onRefresh: _refreshOverview)`（`_refreshOverview` =
    `invalidateIfLoaded(ref, cxstarOverviewProvider)`）→ **进入 / 从阅读器·书架返回 / 回前台**都自动取新数据。
  - `lib/features/comprehensive_service/presentation/jh_read_screen.dart`：同样改造，`_refreshAll()` 依次失效
    `cxstarOverviewProvider` → `readCreditScoreProvider` → `readCreditProgressProvider` → `jhReadRecordsProvider`
    （**顺序有意义**：`readCreditProgressProvider` 内部用 `ref.read(cxstarOverviewProvider.future)` 取数，
    cxstar 失效晚了会读到旧值），下拉刷新也复用同一方法。
  - `cxstar_reader_screen.dart`：`_ping()` 改为**每次心跳都** `_refreshTodayMinutes()`（60 秒一次），
    并新增 `_todayUpdatedAt`；底部栏文案变 `今日已计 X 分 · HH:mm 更新`。
    为什么显示更新时刻：平台统计是**批量结算**的（几分钟不动然后一次跳好几分钟），
    只显示数值会让用户分不清「没刷新」与「刷新了但平台还没结算」。

  守卫：`test/cxstar_auto_refresh_test.dart` ——
  ① 首次进入只取一次数（不重复请求，`userCalls == 1`）；
  ② 卸载再进入（provider 命中缓存）必须重取；
  ③ 从子页面返回必须重取（书架入口，走 `_openChild`）；
  ④ 切后台不刷 / 回前台必刷；
  ⑤ 阅读器：`pump(60s)` 一次心跳后 `summaryCalls` 增加，且随 `todayMinutes` 变化显示
  「今日已计 11 分」→「今日已计 12 分」，并含「更新」字样；
  ⑥ `PageAutoRefresher` 通用机制守卫（最小宿主 + 裸路由 push/pop → `didPopNext`）；
  ⑦ **真实流程镜像**：宿主 → 畅想之星（被 push 的子路由）→ 阅读器 → 返回 → 必须重取，且
  10 秒 / 45 秒 / 150 秒三次结算补刷都要发生。

- **返回时仍看到旧数值（2026-09-14 第二轮，用户原话：「现在只有进入畅想之星页面时会刷新，
  我希望从阅读页，点击返回畅想之星页面时，也会刷新」）**

  排查结论（**不是**观察者没触发，先证伪再改）：
  - 手动镜像测试（宿主 → 畅想之星被 push → 推子路由 → pop）**通过**，说明
    `RouteObserver.didPopNext` 在真实结构下确实会触发；`lib/main.dart:61-64` 也确认
    `navigatorObservers: [appRouteObserver]` 已注册。
  - 于是「返回不刷新」的真实成分是两条：**(a) 返回那一刻取到的仍是结算前的旧值**
    （平台统计批量结算，实测同一分钟内读数不动、过几分钟一次跳好几分钟 → 用户随后重进页面
    才看到新值，误以为是「只有进入时才刷新」）；**(b) 刷新过程不可见**
    （`AsyncValue.when(skipLoadingOnRefresh)` 让重取期间继续显示旧值，链路上还有
    `/api/user` + `/readsummary` + `/readings` 三个串行请求，1–3 秒内没有任何反馈）。

  修法：
  - `cxstar_screen.dart` 三处子页面入口（AppBar 书架 / `_RecordsCard` 阅读器 / `_ShelfEntryCard`）

    **立即** `_refreshOverview()`，再 `_refreshAfterReturnSettle()` 按
    `const List<Duration> cxstarReturnSettleDelays = [10s, 45s, 150s]`（**累计**）各补刷一次
    （`_settleScheduled` 保证多次返回不叠加）。用 `await push` 的确定性取代对路由观察者的依赖。
  - **本页不再 `subscribeRoute`**（`didChangeDependencies` 重写已删）：它的子页面全部由
    `_openChild` 打开，返回时机确定；两条路都留着会重复刷新 —— `ref.invalidate` 不同步生效，
    光靠「正在加载就跳过」拦不住同一 tick 内的第二次触发（这也是没在 `invalidateIfLoaded` 里

  - 统计卡底部新增「正在更新统计…」（`overviewAsync.isLoading`）与

- **总阅读时长** = `readMinutes`（**分钟，无秒**）；`readDays` 阅读天数、`readNo` 阅读次数、
  `longestTime`/`longestDate` 单次最长。
- **完成时间** = `finishReadTime`（形如 `2026年09月09日`），**仅已读完的书有值**，配合 `isFinish`。
  实测 16 本里 10 本已读完（`finishReadTime`/`finishReadNo` 有值），其余为 `null`。
- ⚠ **`/api/user/readings` 的 `ifReadFinish` 不可用作读完判据**：分页响应里实测恒为 `null`
  （`GetReadTJ` 的 `readData` 里恒为 `false`），用它做「已读完」标记会**永远显示「阅读中」**
  —— 以 `readreport.isFinish` / `finishReadTime` 为准（App 记录行的胶囊已按此修正）。
- **秒级数据不存在**（已排除）：`/api/books/{id}/readtime`、`/api/user/readtime/{id}`、
  `/api/books/{id}/readreport/details`、`/api/user/readreport?bookId=` 全部 **404**；
  `?filetype=3/4` 与 0/1/2 同构。要秒级只能取学分平台 jhread 的 jd 明细「总阅读时长(秒)」
  （按书名聚合的另一套数据）。
