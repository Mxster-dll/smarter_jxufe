# 阅读学分平台（蛟湖阅读学分）接口归档

> 数据源站点:`https://jhread.zhixinst.com`(智信「阅读学分平台」,与入馆教育 `tsgxs.jxufe.cn` 同厂商同技术栈:ASP.NET MVC + 学校统一认证)。
> App 实现:`lib/features/read_credit/`,展示入口并入现有「蛟湖阅读」页顶部(`lib/features/comprehensive_service/presentation/jh_read_screen.dart`)。
> 抓取与核对时间:2026-09-11。

## 1. 入口与页面

用户给的微信入口地址:
```
https://jhread.zhixinst.com/?wfw_token=<token>&fidEnc=367a7ebfe6db2cb0&mappId=12340328&openid=&enc=
```
- `wfw_token` / `fidEnc` / `mappId` 只是微信服务号入口参数,**不需要**——App 走统一认证后同样的页面直接可达(实测 `wfw_token` 缺失/过期都不影响)。
- 首页 `/Web/ReadMain/Index`:标题「阅读学分平台」,含学分说明全文与「学分查询」入口。
- **学分查询页 `/Web/ReadMain/Score`**:5 项达标 + 学分状态。
- 明细页 `/Web/Read/Index/{pt|jd|rg|xx}`(普通阅读 / 经典阅读 / 入馆教育 / 信息素养)。
- 留言页 `/Web/FeedBack`;注销 `/Web/CASLogin/LoginOut`。

匿名访问 `/Web/ReadMain/Score` → `302 /Web/CASLogin/Login` → `302 https://ssl.jxufe.edu.cn/cas/login?service=…`。

## 2. 登录链(已实测打通;App 内全自动)

1. TGC → `AuthRepository.getServiceRedirectUrl(casServiceUrl)` → 带 ticket 的回调地址;
2. `GET http://jhread.zhixinst.com/Web/CASLogin/Login?targetUrl=…&ticket=ST-…` → `302 https://jhread.zhixinst.com:443/Web/ReadMain/Index` → `200`,并下发平台自己的 Cookie:
   `ASP.NET_SessionId` / `uid` / `token` / `uNickName`;
3. 之后业务页凭该 Cookie 访问;失效时一律 `302 /Web/CASLogin/Login`(再跳 CAS)。

**⚠ service 必须 http**(与 tsgxs 同一个坑):平台自己下发的是
`https://jhread.zhixinst.com:443/Web/CASLogin/Login?targetUrl={base64}https://jhread.zhixinst.com:443/Web/ReadMain/Index`,
直接用会被 CAS 判为「**未认证授权的服务**」(HTTP 200 错误页、无 ticket)。换成
`http://jhread.zhixinst.com/Web/CASLogin/Login?targetUrl={base64}…`(targetUrl 内层仍保持 https)即拿到 ticket。实测变体矩阵:

| service 形态 | 结果 |
|---|---|
| `https://jhread.zhixinst.com:443/…`(平台原样) | 200「未认证授权的服务」 |
| `https://jhread.zhixinst.com/…`(去端口) | 200「未认证授权的服务」 |
| `http://jhread.zhixinst.com/…` | **302 + ticket** ✅ |

App 中的常量(`lib/features/read_credit/data/datasources/read_credit_auth_remote_datasource.dart` 的 `ReadCreditAuthRemoteDataSource.casServiceUrl`):
```
https://ssl.jxufe.edu.cn/cas/login?service=http%3a%2f%2fjhread.zhixinst.com%2fWeb%2fCASLogin%2fLogin%3ftargetUrl%3d%7bbase64%7daHR0cHM6Ly9qaHJlYWQuemhpeGluc3QuY29tOjQ0My9XZWIvUmVhZE1haW4vSW5kZXg%3d
```
其中 `aHR0cHM6Ly9qaHJlYWQuemhpeGluc3QuY29tOjQ0My9XZWIvUmVhZE1haW4vSW5kZXg=` = base64(`https://jhread.zhixinst.com:443/Web/ReadMain/Index`)。

会话 Cookie 按 host 隔离(与 tsgxs 同规):CAS 域的 TGC 不发给平台,平台域的 `ASP.NET_SessionId/uid/token` 不发给 CAS。

## 3. 学分查询页结构(`GET /Web/ReadMain/Score`,UTF-8)

服务端渲染,**无 JSON 接口**。每项一个 `div.title` + 紧随其后的 `div.info`:

```html
<div class="title">
    普通阅读：<span class="titleFalse">未通过</span>
    <span style="…">更新时间：2026年09月03日</span>
    <a href='/Web/Read/Index/pt' style="…">详细列表</a>
</div>
<div class="info"> 电子阅读[<span class='infoOrange'>2</span>] 纸质阅读[<span class='infoGreen'>0</span>]</div>
…
<div class="title">蛟湖文化活动：<span class="titleTrue">通过</span>
    <span style="…">更新时间：2026年04月01日</span></div>   <!-- 无 info 行、无明细链接 -->
<div class="title">学分状态：<span class="titleFalse">未获得学分</span></div>
```

- 状态 class:`titleTrue`=通过 / `titleFalse`=未通过(学分状态行同款)。
- `div.info` 取值:`电子阅读[2] 纸质阅读[0]` 或 `无信息`(后者 App 视为 null)。
- **蛟湖文化活动**没有「详细列表」链接,App 侧 `ReadCreditKind.culture.hasDetail == false`。

## 4. 明细页表格(`GET /Web/Read/Index/{pt|jd|rg|xx}`)

标准 `table > thead/th + tbody/td`。列名由服务端决定:

| kind | 列 |
|---|---|
| pt 普通阅读 | 一卡通号 / 姓名 / 学院 / 专业 / 班级 / **已读完图书书名** / 完成时间 / **总阅读时长(秒)** / 所属厂商 |
| jd 经典阅读 | 同上(未达标时 0 行) |
| rg 入馆教育 | 一卡通号 / 姓名 / 学院 / 专业 / 班级 / **闯关结束时间** / **是否通过** / 所属厂商 |
| xx 信息素养 | 一卡通号 / 姓名 / 学院 / 专业 / 班级 / **学习视频数量** / **时长(秒)** / 完成时间 / 所属厂商 |

pt 实测 3 行:2 行电子阅读(书名如「学习通电子阅读20260802-3201」、完成时间、`7201` 秒、厂商「普通阅读-京东阅读」)+ 1 行纸质借阅(无书名、时长 0)。前 5 列为本人身份列,`App 只在页首展示一次`(`kReadCreditIdentityHeaders`)。

## 5. 学分构成(平台首页原文,App 内 `readCreditRules` / `readCreditNotice` / `readCreditUpdateHint`)

- 蛟湖阅读学分**共 1 分**,由四部分构成,应于大学本科**三年级结束前**完成;四部分全部完成后修满,由图书馆统一出具证明。
- 第一部分 经典阅读:经典电子阅读平台在线阅读 **10 册**图书,且阅读**总时长 ≥ 20 小时**。
- 第二部分 普通阅读:纸质借阅(按实际借阅册数)+ 电子阅读(按平台认可读完册数)累计 **≥ 10 册**。
- 第三部分 入馆教育:入馆教育平台在线自主学习并**通过平台测试**(即 `tsgxs.jxufe.cn` 的闯关)。
- 第四部分 信息素养:信息素养平台在线视频学习,小视频数量 **≥ 20 个**。
- 平台提示:学习前**必须先登录**;学分**更新时间分别是 5 月份和 11 月份**。

## 7. 更新 fixture / 复核口径的方法

1. 从 App Hive(`app_data/auth.hive`,box `auth`,key `TGC|2202502xxx`)取 TGC:`tools/_read_tgc.dart`(`dart run tools/_read_tgc.dart`,值只落 `%TEMP%\_tgc_<账号>.txt`,不打印);
2. python(requests,`trust_env=False`)按 §2 用 TGC 换票(service 用 **http**),逐跳收集平台 Cookie;
3. `GET /Web/ReadMain/Score` 与 4 个 `/Web/Read/Index/*` 落盘 → 掩码学号/姓名后替换 `test/fixtures/jhread_*.html`。

> 注意:同账号多客户端会互相顶下线(平台单点登录),python 探针跑完若 App 报会话失效,重进页面即自动重建会话。

### 8.1 两档口径的定义（为什么必须分两档）

平台学分查询页（汇总）**只在 5 月与 11 月更新**（平台首页原文），而明细表是随学随更新的；
入馆教育（tsgxs）与图书借阅在 App 内本来就有实时源。因此界面同时给两个数：

| 部分 | 要求 | 实际口径（App 侧实时） | 平台口径（汇总页） |
|---|---|---|---|
| 第一部分 经典阅读 | 10 册 + 总时长 ≥ 20 小时 | 名著明细表实时统计（册数 = 行数、时长 = `总阅读时长(秒)` 求和 / 3600） | 只有达标状态（平台**不提供**计数 → 该进度条无平台值） |
| 第二部分 普通阅读 | 纸质 + 电子累计 ≥ 10 册 | 电子阅读 = 明细行按「所属厂商」不含「纸质」计数；纸质借阅 = **学生个人数据中心 `borrowCounts['本年']`**（拿不到才回退明细里的纸质行） | `电子阅读[x] 纸质阅读[y]` 汇总计数 |
| 第三部分 入馆教育 | 通过平台测试 | **App 内五章闯关实时状态**（`tsgxsExamStatusProvider(chapterId).state == TsgxsExamState.passed` 计数 / 章节总数） | rg 明细（闯关结束时间 / 是否通过，常为 0 条） |
| 第四部分 信息素养 | 学习视频 ≥ 20 个 | 明细表 `学习视频数量` 求和（另给累计时长） | 只有达标状态 |
| 附加 蛟湖文化活动 | 无量化要求 | 无（不画进度条） | 达标状态 |

### 8.4 三次改版（用户 2026-09-11：一条进度条叠两档 + 总成绩圆环）

用户原话：「由于服务端数据一定晚于实际数据，所以我们要在一个进度条上显示服务端数据和实际数据，其中灰色表示实际数据，红色表示服务端数据，然后红色条覆盖在灰色条上；蛟湖阅读页还要显示一个总成绩卡片，显示一个圆环，分成四部分，然后哪部分完成就亮起那部分，并显示一个是否获得学分的胶囊」。

- **进度条改单条双档**（`lib/features/read_credit/presentation/read_credit_progress_section.dart` 的 `ReadCreditPartCard._barBlock`）：`ClipRRect` + `LayoutBuilder` + `Stack` 三层 —— 轨道（`surfaceContainerHighest`）→ **灰条 = 实际**（`readCreditActualBarColor = Color(0xFFBDBDBD)`，宽度 = `actualRatio`）→ **红条 = 服务端**（`readCreditServerBarColor(context)` = `colorScheme.primary` 校红 #C3282E，宽度 = `remoteRatio`，覆盖在灰条之上）。语义：**红条比灰条短 = 服务端还没追上实际进度**；`remoteRatio == null`（服务端无该项计数，如经典阅读 / 信息素养）时只画灰条。同一行同时给两档数值：「实际 7 / 10 册」+「服务端 2 / 10 册」。术语从「平台」统一为**服务端**（chips 变 `实际 已达标` / `服务端 通过|未通过|未提供`，脚注 `服务端：未通过 · 更新于 …`）。
- **总成绩卡**（`ReadCreditProgressSection._creditCard`，取代原学分总卡）：左侧 `_CreditRing`（`CustomPainter`，120×120、`strokeWidth 12`、四段各 `2π/4 − 0.14` 弧度、从 12 点方向顺时针；未完成段画 `outlineVariant` 灰底，完成段用自己的 `readCreditPartColor(kind)` 亮起；圆心 `x/4` + 「部分已完成」）+ 右侧学分状态胶囊（`bundle.creditGranted / creditText`，已获得绿 / 未获得橙）+ 四部分图例（彩色圆点 + 名称 + 已完成/未完成）+ 蛟湖文化活动状态行 + 底部两档口径说明（含图例说明「灰 = 实际 / 红 = 服务端」）+ 刷新按钮。
- **新增域层口径**（`lib/features/read_credit/domain/read_credit_progress.dart`）：`ReadCreditProgressBundle` 增 `completedCount`（四部分完成数，文化活动不计）、`creditGranted`、`creditText`、`creditParts`（过滤掉文化活动的 getter）；顶层 `bool readCreditPartCompleted(ReadCreditPartProgress part)` = **实际口径优先**（`actualMet != null` 用它），缺席才回退 `remoteMet ?? false` —— 圆环亮起与完成计数的唯一口径。
- 四部分配色登记在 `lib/features/read_credit/presentation/widgets/read_credit_ui.dart` 的 `readCreditPartColor(kind)`：经典 #2E7D32 / 普通 #1565C0 / 入馆 #00B8D4 / 信息素养 #EF6C00 / 文化活动 #795548。
- 守卫测试（`test/read_credit_progress_test.dart`，共 25 例）：圆环中心 `1/4` + 「部分已完成」、图例「已完成」1 / 「未完成」3、胶囊「未获得学分」、`find.byType(ReadCreditPartCard) == 4`（用卡片类型计数替代按标题计数，因总卡图例里也有同名文字）、点入馆教育卡用 `find.descendant(of: byType(ReadCreditPartCard))` 定位（同名文字歧义）、`readCreditPartCompleted` 三态、`completedCount == 4` 与 `creditGranted` 透传。

### 8.5 四次微调（用户 2026-09-11：浅红 + 完成即拉满 + 圆环红色带缝隙）

用户原话：「1. 灰色改浅红；2. 如果平台显示已完成，则红色部分显示最大化；3. 圆环四部分之间应该有明显间隙；颜色应该为红色」。

- **实际那一档的颜色：灰 → 浅红**。`lib/features/read_credit/presentation/widgets/read_credit_ui.dart` 的 `const readCreditActualBarColor`（原 `Color(0xFFBDBDBD)`）**改为函数** `Color readCreditActualBarColor(BuildContext context) => Theme.of(context).colorScheme.primary.withValues(alpha: 0.30)` —— 与「服务端」深红（`colorScheme.primary`）同色相、只用透明度分层，叠加时层次清楚。
- **服务端已完成 → 红条拉满**：`ReadCreditPartCard._barBlock(context, bar, {required bool? serverPassed})`（调用点传 `part.remoteMet`）——`final serverRatio = serverPassed == true ? 1.0 : bar.remoteRatio;`，即服务端标记该项完成时红条 100%，不受它的计数口径限制；同时该行文案由「服务端 x / y」变为 **「服务端 已完成」**（避免"满条却写着 2/10"的自相矛盾）。红条在服务端未通过时仍按真实计数比例画。
- **圆环改红色 + 段间明显间隙**：`_CreditRing` 的 `segments`（`List<({Color color, bool done})>`，每段各自配色）**简化为 `done: List<bool>` + `activeColor: scheme.primary`**；`_CreditRingPainter` 的 `gap` 由 `0.14`（约 8°）加大到 **`0.38`（约 22°）**，每段仍是 `2π/4 − gap`；`shouldRepaint` 改为比较 `done` 列表与 `activeColor`。总卡图例圆点同步改为「完成 = 主题红 / 未完成 = `outlineVariant` 灰」。
- 四部分配色 `readCreditPartColor(kind)` **仅保留给部分卡片的图标盒**（不再用于圆环与图例）。
- 守卫测试（`test/read_credit_progress_test.dart`）：新增 widget 用例「服务端已标记完成 → 红条拉满并显示『服务端 已完成』」——断言文案、`服务端 2 / 10 册` 不再出现，并按渲染尺寸断言「轨道与红条同宽（100%）、浅红那条更短」（收集所有 `Container.color != null` 的宽度排序后比较，不依赖具体色值）。
