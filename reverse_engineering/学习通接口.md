# 学习通（超星）接入 · 接口与链路实测

> 2026-09-19 实测（账号 …2513）。**先说结论：零密码能进，作业与通知两条数据源都已拿到真实数据。**
> 用户给的线索是「智慧江财 → 网络教学 → 江财教学网 → 本科生入口/学习空间 → 学习通」；实测**不必绕教学网**，
> 直接复用项目已有的 **超星统一认证网关** 换证链（`library_sync` 那条）就能拿到 `.chaoxing.com` 的 passport 会话。

## 0. 一句话链路

```
TGC（auth.hive: TGC|<账号>）
  → 网关 init?refer=https://i.chaoxing.com      GET unified-auth.chaoxing.com/login_auth/jxufe/init
  → 302 到学校 CAS，带 TGC 换票（ST-…）
  → 网关 /login_auth/cas/jxufe/index?ticket=ST-…  → 200「跳转中…」页（含 data/time/enc）
  → GET /login_auth/cas/jxufe/login?data&time&enc → {"status":true}
  → 跳 https://i.chaoxing.com?data&time&enc → 302 /base?t=… → 200
  ⇒ 下发 .chaoxing.com 域 passport Cookie（19 个）
```

⚠ **与图书馆链路的唯一差别就是 refer**：图书馆用 `refer=https://findjxufe.libsp.cn/find/sso/login/jxufe/0?pageType=0`，
学习通用 `refer=https://i.chaoxing.com`。网关页的 `jumpToRefer(firstReferer, data, time, enc)` 会把
**`firstReferer` 原样回显**（服务端不改写），所以 refer 是客户端可控的换证落点。

## 1. 会话 Cookie（学习通域）

建立后 `.chaoxing.com` 域上出现（**全是凭据，一律不落日志**）：

```
UID  _uid  _d  vc3  uf  uname  fid  p_auth_token  xxtenc  cx_p_token  DSSTASH_LOG
```

另按目标域分发的辅助 Cookie：`i.chaoxing.com: jrose, spaceFidEnc, spaceFid, spaceRoleId, source`；
`jxufe.fanya.chaoxing.com: JSESSIONID, route, fanyamoocs`；`mooc1.chaoxing.com: jrose, k8s, route`。

- 判活：访问 `https://i.chaoxing.com/` → **302 到 `/base?t=…` 即已登录**；302 到
  `https://passport2.chaoxing.com/login?…` 即失效 → 重新换证。
- **Cookie 按 host 隔离**（与 `tsgxs` / `cxstar` / `libsp` 同口径）：网关域的 `JSESSIONID` / `firstReferer` / `route`
  与目标域的同名 Cookie 不是一回事，不要串。

## 2. 通知消息（**JSON，最干净的一条**）

### 2.1 拿 token

`https://i.chaoxing.com/base`（88481 B，个人空间）页内出现
`https://notice.chaoxing.com/pc/notice/myNotice?s=<32 位小写 hex>` —— 这个 `s` 就是收件箱签名 token，
**直接从页面正则取**（`notice\.chaoxing\.com/pc/notice/myNotice\?s=([0-9a-zA-Z]+)`）。

## 6. 工程侧注意

1. **登录链零密码**：复用 App 内 `auth.hive` 的 `TGC|<账号>`（同 `libsp`），**不需要 WebView、不需要学习通密码**。
   换证 ~4 个请求，可每次同步重建；也可缓存会话并按 302 判活。
2. **凭据纪律**：`p_auth_token` / `xxtenc` / `vc3` / `_uid` / `_d` / `uf` / `uname` 全是凭据；
   网关登录响应还带真名与手机号 → **任何值不进日志/对话**，账号只报后 4 位。`notice` 的 `s` token 同样按凭据处理。
3. **成本**：通知 = 1 个 JSON 请求（+1 次换证）；作业 = **每课 2 个请求**（课程页 + 作业页）。
   当下学期 9 门 → 约 19 个请求。**必须缓存 + 节流**（可照 `cxstarRefreshGateProvider` 的 1 分钟闸门口径），
   或只对「当下学期」的课做作业扫描。
4. **解析**：作业页是 HTML → 走项目既有的 anti_corruption + fixture 测试口径
   （参考 `schedule_html_parser.dart` / `grades_html_parser.dart`）；通知是 JSON → 容错 `as num?`/`as String?`。
5. **会话按 host 隔离**：`unified-auth.chaoxing.com` / `.chaoxing.com` / `mooc1.chaoxing.com` 三域 Cookie 不混用。

### 7.1 Dart 侧真链冒烟（`tool/chaoxing_smoke.dart`，**已跟踪**）

`dart run tool\chaoxing_smoke.dart [--diag]` —— 用本机 `app_data/auth.hive` 的 TGC 把**真服务端**跑一遍
（换票 → 网关桥接 → 会话 → 课程 → 逐课作业（并发 4）→ 通知 → 快照派生），逐项 ✓/✗；
`--diag` 额外把第一门课的课程详情页与作业列表落盘到 `.scratch/xxt_smoke_*.html` 并打出重定向链。

⚠ **它抓到了 python 探针抓不到的坑（因为 `requests` 默认跟跳转）**：`GET /visit/stucoursemiddle`
直接请求返回 **302 + 0 字节**，跟到下一跳才是真课程页 → Dart 首版不跟跳转，导致 35 门课**全部**被判成
「没有作业」且无任何异常。修法 = 业务请求 `followRedirects: true`（换证链保持不跟）。

实测 2026-09-19（该账号）：会话 ✓ / 收件箱 token ✓ / **35 门课**（261 学期 10 · 252 学期 12 · 251 学期 11 ·
无前缀 2）/ 通知 **19 条**（未读 0）/ 最近一条待做截止 2026-09-20 23:59。
⚠ **作业条数是流动值**：同一天 21:0x 跑出「5 门 · 32 条」、21:2x 跑出「7 门 · 44 条」
（待批阅 8 → 17）—— 老师批改 / 新布置会让「有作业的课」和条数在十几分钟内就变，
**别把某个具体条数当断言写进测试**（守卫测试一律用 fixture 的假数据）。

## 8. ⚠ 风控：`202` + 验证码页（**「刷新会刷新没」的根因**，2026-09-19 实测）

请求过密时超星的业务接口**不返回 403，而是返回 `202` + 4527 B 的一张「提示页面」**：

```html
<title>提示页面</title>
<p class="tips-txt">【9010】操作异常，请输入图片中的验证码</p>
```

- 它**长得像一次成功响应**（状态码 202、`Content-Type: text/html`、有完整 HTML 骨架），
  但正文里**没有课程锚点、没有 `getAllWork` 作业入口、没有「暂无内容」** —— 于是任何
  「解析出 0 条就当空」的写法都会把它读成「这门课没有作业」。
- 实测它同时出现在**课程详情页**与**作业列表页**两种请求上（批量扫描时随机命中）。
- ⚠ 它与**会话失效**是两回事：被踢回登录页是 302 + Location 含 `passport2.chaoxing.com`；
  风控是 202 + 验证码页。**换票对风控无效**（风控认的是请求速率与账号）。

### 8.1 触发与恢复（同一会话、同一批课程详情页，逐条实测）

| 打法 | 结果 |
|---|---|
| 全并发 **8 个** | 0 次 |
| 全并发 **16 个** | 0 次 |
| 全并发 **24 个** | **24/24 全中** |
| 触发后每 1 秒探测一次 | **60 秒仍不恢复**（60 次全是验证码页）→ **重试只会延长窗口** |
| 稳态 **1 请求/秒 × 20 个** | 0 次（只发 20 个，**没到预算**） |
| **匀速 2 请求/秒**扫完 35 门课（≈70 个请求） | **第 31 门（≈62 个请求）起整段变验证码页**（第 31-35 门全中） |
| 35 门课 × 2 请求、并发 4（首版无限速，≈64 请求 / 4.3 秒） | 同样在**末尾 6 门**中招 |
| 限速器写错（4 条 lane 共用同一格）时 | 64 个请求 4.3 秒跑完 → **照样触发** |

→ **决定性结论：触发量是「累计请求数（≈60 个/窗口）」而不是速率。** 一次全扫
= 35 × 2 = **70 个请求 > 预算**，无论多慢都必然撞墙。所以「扫全部课程」这个方案
在不改架构时**不可能成立**。

### 8.2 工程结论（已落进 `lib/features/chaoxing/`）

1. **分批轮转**（架构级）：`ChaoxingRepository.maxCoursesPerScan = 20`（每轮 ≤ 40 请求）
   + 游标 `_scanCursor` 滚动 → 没轮到的课沿用缓存旧数据并记 `pendingCourseKeys`，
   下一轮从游标接着扫，两轮覆盖 35 门。**别退回「一次全扫」。**
2. **只有「扫成功」才允许替换**：本轮扫成功（`okIds`）→ 采信（含可信空）；窗口外 / 失败 /
   被拦下 → **旧作业原样搬过来**。这是「刷新不许丢数据」的唯一守卫点。
3. **识别**：`ChaoxingHttpClient.ensureUsable(response, body)` —— 判据 = `statusCode == 202`
   **或**正文含 `请输入图片中的验证码` / `【9010】`；命中抛 `ChaoxingChallengedException`
   （**不复用** `ChaoxingSessionExpiredException`，否则会白白换票并加剧风控）。**每个业务响应都要过**。
4. **可信空二分**（更根本的一层）：真课程页的 `getAllWork` 命中数**恒为 1**（实测 35/35），
   真·空课的作业页会写「暂无内容」（实测 22/35）→ 所以
   「抠不出作业入口」「作业页 0 条且无空标记」「课程清单 0 门」**一律算失败**
   （抛 `ChaoxingPageException`），**绝不返回空列表**。
5. **限速**：`chaoxingMinRequestInterval = 260 ms`，业务请求传 `throttle: true`；
   实现必须是**原子预定下一格**（读-改-写之间不能有 `await`），否则并发下退化成 `lane 数 / 间隔`。
6. **收手 + 冷却**：扫描中一旦撞风控立刻停发剩余请求；进 `challengeCooldown = 120 秒` 冷却，
   期间一个请求都不发（`force: true` 才越得过 —— 手动刷新带、自动刷新不带）。
   本轮已扫到的数据**照样落盘**（没扫到的那些是从上一份快照搬过来的，不会让数据变少）。

### 9.1 聚合待办复核：**web 侧确认没有**（2026-09-20 补测，`.scratch/xt_todo.py` + `.scratch/xt_js.py`）

用户问「为啥要扫描一遍才知道有哪些作业，没有统一接口吗」→ 复核结论 = **通知与课程本来就有统一接口，只有作业没有**。

| 数据 | 统一接口 | 成本 |
|---|---|---|
| 通知 | `GET notice.chaoxing.com/pc/notice/getNoticeList?s=`（JSON） | **1 请求** |
| 未读指示 | `GET i.chaoxing.com/base/getNoticeCount`（`msg` 是布尔） | 1 请求 |
| 课程 | `GET mooc1.chaoxing.com/visit/courses`（HTML，一次 34~35 门） | **1 请求** |
| 作业 | **无** —— 逐课 `stucoursemiddle`（取签名 query）+ `getAllWork` | **2×N** |

补测的负面证据（都是本轮实测）：

1. `POST /mooc-ans/api/workTestPendingNew`（**唯一长得像聚合的那个**，课程列表页 JS 自己用它点红点）：
   web UA / **App UA（`ChaoXingStudy`）** / `mooc1-api.chaoxing.com` 域 —— 三种打法全是 `200` + **`[]`（2 字节）**，
   累计 10 种变体全空 → **它在 web 会话下是死的**，不要再用。
2. `task.chaoxing.com`（线索 = 收件箱壳页全局配置 `"taskHttps":"https://task.chaoxing.com"`，名字像「任务中心」）：
   根路径 **404**（Spring Boot `Whitelabel Error Page`，281 B），猜的 5 条路径（`/api/task/list`、`/pc/task/list`、
   `/task/list`、`/api/todo/list`、`/api/task/getList`）**全 404** → 真实路由没暴露，需从 App 侧 JS 才能挖。
3. `mooc1-api.chaoxing.com` = **超星慕课课程目录**（`title='超星慕课'`，公共课列表），**不是** App 任务 API。
4. 学习空间首页（`i.chaoxing.com/base`）与泛雅 portal 引用的 **23 个 JS bundle 里，没有任何 work/task/todo/pending
   接口字面量**；页面内联 JS 只有 4 条：`/pc/notice/myNotice`、`/base/getNoticeCount`、`/pc/activity/activityList`、
   `/education/student/stuActiveListEducation`。课程列表页内联 JS 只有那条死掉的 `/api/workTestPendingNew`。
5. `/visit/interaction`（旧「全站互动」，疑似聚合页）实测 = **普通课程列表页**（title「课程」，11947 B），不含作业。

**为什么结构上就没有**：作业挂在「课程 + 班级(`classId`)」下，`getAllWork` 的 query 带**每课一份签名**
（`enc` 32hex + `openc` 32hex，实测 35/35 门各不相同）——签名把「这台客户端有权看这门课」编进去了，
所以拿一组 courseId 拼批量请求在协议层就不成立。真正的聚合只可能在 **App 私有 API**（大概率要 `p_auth_token` 签名）。

### 9.2 落地口径：只扫当下学期 + 通知兜底（2026-09-20，用户 A+B 拍板）

既然作业没有统一接口，成本控制的正确做法是**缩小范围**而不是分批轮转：

- **A｜只扫当下学期**：口径函数 = `lib/features/chaoxing/domain/chaoxing_scan.dart` 的
  `chaoxingScanPlan(courses, currentTermCode:)`；`currentTermCode` 由
  `schoolTermCode(currentSchoolTerm(now, terms: offlineSemesterTerms).xn, .xq)` 给出（`261`），
  课程侧用 `ChaoxingCourse.termCode`（`261学期` → `261`）。**学期前缀认不出的课照扫**；
  两条不筛退路 = 学期码为空 / **一门课都不匹配当下学期码**（新学期课程还没建时别把界面变成全空）。
  - **真机实测（2026-09-20，`dart run tool\chaoxing_smoke.dart`）**：学期分布
    `261学期=10 / 无前缀=2 / 252学期=12 / 251学期=11` → 扫 **12/35 门 = 24 个请求、6059 ms、0 风控**
    （24 × 260 ms ≈ 6.2 s，反证限速器在算），通知 19 条、待做 1 条（线性代数）。
    改前同账号 = 70 个请求必然撞墙（第 31 门起整段验证码页）。
  - 代价（用户知情选定）：往期学期不取数 —— 老用户靠缓存里的旧数据继续显示，
    **全新安装只看到当下学期的作业**；界面写「只扫当下学期（12/35 门）」。
  - 课程窗口（20）现在只在「一学期 > 20 门课」时才起作用，且**游标推回 0、每轮同一批全量**。
- **B｜通知兜底**：平台发作业时会自动发 `作业:《课程名》作业标题`（实测标题里就带课程名 + 作业标题）
  → `chaoxingNoticeWorkHints(snapshot)` 取「作业列表还没扫到的那些」，**按标题包含关系去重**
  （已扫到的那条 `9月20日24:00前提交作业` 正是通知标题的后半段）。只认 `作业:` / `作业：` 开头，
  「作业结束提醒」不算。界面 = 主页「通知里的作业提醒」卡片，为空整块不画。
- 模块侧落点：`ChaoxingSnapshot.skippedCourseKeys`（与 `pendingCourseKeys` 分开）、
  `chaoxingCourseScanNote` 第三档「非当下学期，未扫描（只扫当下学期）」、概览卡如实说。
  守卫 = `test/chaoxing_scan_test.dart`(16) + `test/chaoxing_data_test.dart` 端到端 8 例里的
  「往期课一个请求都不发」+ `test/chaoxing_screen_test.dart` 3 例。

## 10. 签到记录（2026-10-09 侦察，用户：「我希望还能接入学习通里的签到记录」）

### 10.3 工程落点与成本口径

- 端点唯一出处 = `lib/features/chaoxing/data/chaoxing_endpoints.dart` 的 `signHost` /
  `signListPath` / `signPagePath` / `signDetailPath`；解析 = `data/anti_corruption/chaoxing_sign_parser.dart`；
  模型 = `domain/chaoxing_sign.dart`（`ChaoxingSignStatus` 三档归类 `isSigned` / `isAbsent` / `isKnown`）。
- **清单走 POST** —— 本模块仍是只读：`ChaoxingHttpClient.post` 只服务这种「站方自己用 POST 查数据」的接口，
  **永不**调用签到提交（`pptSign/stuSignajax`）。
- 成本（用户 2026-10-09 拍板：**自动只扫本学期**、**允许手动全量**）：
  - 自动刷新 = 与作业同一批课程，**每门课多 1 个请求**（本学期 12 门 → +12）；
  - 「我的状态」**点开才查**（1 请求/活动）；
  - 手动「补全全部状态」/「含往期课程一起更新」= 用户明确触发，逐条/逐课发请求，
    撞风控立刻收手、已拿到的照算（见 §8 的请求预算）。
- 真机冒烟（`tool/chaoxing_smoke.dart` 第 4c 步，2026-10-09 实跑）：3 门课 → **11 条签到**（全是 `二维码签到`），
  抽 1 条详情 = `已签 · 2026-10-09 09:51`，且清单条目的状态全部是「未查」（与 10.2-1 一致）。
