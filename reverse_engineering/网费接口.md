# 网费接口（校园网计费 · 智慧江财 wfcz H5 应用）

> 逆向存档（2026-09）。数据源为智慧江财小程序「网费充值」H5 应用
> （wfcz 模块），App 内实现为 `lib/features/net_fee/`。

## 认证链（与校历同款：平台 GUID → 加密 userId）

平台用户标识 **GUID**（微信授权可得，形如 `00000000-0000-4000-8000-000000000000`，
App 内存 Hive box `'wxPlatform'` key `'guid'`，与校历页共用）→ checkAppAuth
换取 **加密 userId（enc，base64 16B）** → 计费业务接口只认 enc，纯学号一律
`E99 异常`。

```
GET https://wxcourse.jxufe.edu.cn/platForm/api/littleProgram/application/checkAppAuth
    ?appid=1586481872684&platformUsername=<GUID>
→ code 200, result.username = <enc userId>
```

- 平台应用 id：`1586481872684`（wfcz 网费充值 H5）。
- checkAppAuth 在平台管理域（`.edu.cn`），业务接口在 `.cn`——同一 Referer/UA 规则。
- 实测 enc 稳定值示例：`AAAAAAAAAAAAAAAAAAAAAA==`（base64，非固定，随时间/账号变化）。

## 请求通用要求

全部请求须携带：

```
User-Agent: <浏览器 UA>（python-requests 默认 UA 被拒）
Referer: https://servicewechat.com/wx70c0beda0bb7b021/143/page-frame.html
```

响应 UTF-8 JSON。

## 接口清单

### 1. 余额

```
GET https://wxcourse.jxufe.cn/1585799510593/pay/account?username=<enc>
```

响应：`{"code":"E00","balance":"12.5","message":"成功","username":"2000000000"}`

- `code`：`E00` 成功（可充）；`E14` 账号不支持（balance 展示 '-'，不可充）；`E99` 异常。
- `balance` 字符串，单位 **元**；`username` 为学号。
- POST form 亦可（E00）；POST json → E99。

### 2. 充值记录

```
GET https://wxcourse.jxufe.cn/1585799510593/pay/detail
    ?start_time=2025-09-13&end_time=2026-09-13&username=<enc>
```

- 时间参数 `yyyy-MM-dd`（小程序端为「查询日 ~ 查询日+24h」窗口；App 取近一年整窗）。
- 响应：`{"code":200,"list":[{"operator_id":6002,"business_type":"增减储值",
  "remark":"<13位毫秒时间戳>","pay_type":null,"fee_type":"增减储值",
  "pay_money":50,"pay_id":806704,"account":"2000000000",
  "pay_time":"2026-06-05 00:25:22"}, ...]}`
- `pay_money` 数字（元）；`pay_time` 本地时间 `yyyy-MM-dd HH:mm:ss`；
  `remark` = 充值时刻毫秒时间戳字符串。
- 仅充值明细（business_type/fee_type 均「增减储值」），无扣费明细——与小程序一致。
- POST form 亦 200；POST json → `code 300`。
- 近一年实测 6 条：2025-09-13 12.5 / 10-12 12.5 / 10-14 12.5 / 11-26 25 /
  2026-02-27 50 / 06-05 50，当前余额 12.5 元。

### 3. 充值（2026-10-09 打通「App 内充值面板」）

**两条候选通道，只有第二条能在 App 里跑**：

| 通道 | 结论 |
|---|---|
| 小程序「网费充值」（wfcz `1586481872684`） | **不可做**：`checkAppAuth` 回的 `typeC == '微信原生'`、`pageUrl` 形如 `/pages/modules/developer/wfcz/view?cardinfo=…&openId=…` —— 它是**微信原生小程序页面**，支付走 `wx.requestPayment`（需该小程序的商户凭据与 openId），App 侧不可能复刻 |
| 校方网页支付页（Dr.COM **WebPay**） | ✅ **唯一可用**：`https://self.jxufe.cn/WebPay/…`，**免登录**（GET 直接给表单），账号与金额都能从 URL 预填 |

**校方支付页实测**（2026-10-09，全程只读，**未下任何单**）：

```
GET https://self.jxufe.cn/WebPay/toRecharge?paytype=3&account=<账号>&amount=<金额>
→ 200 HTML（PC 版充值表单）
```

- `/WebPay/recharge?…` 只是入口：它 **302 到 `toRecharge` 时会把 `amount` 丢掉**
  （实测 Location 只剩 `paytype` 与 `account`）→ 想预填金额必须**直接开 `toRecharge`**。
- **PC 版**（窗口宽 > 768）：金额档按钮 `10/20/50/100/200` + 「其他」输入框。
  `?amount=50` → 服务端把 hidden `amount` 渲染成 `50.0`，`recharge.js` 的 `initAmount`
  本意是选中该档 —— **但它有 bug：档位金额会被打回 10 元，见本节末尾**。
  提交 = `POST ./submitRecharge`
  （表单字段：`csrftoken` / `rechargetype=0` / `amount` / `account` / `cardid` /
  `timepacket*` / `flowpacket*` / `validCode` / `paytype`）。
- **移动版**：`recharge.js` 开头判 `winWidth <= 768` → `window.location.href = "toRechargeM" + 当前 query`
  （**query 原样带走**，所以同一个 URL 两端都能预填）。移动版表单 → `POST toRechargeConfirmM`
  （**确认页里才选支付方式**）。实测 `toRechargeM?account=…&amount=50` → 金额输入框 `value="50.0"`。
- **支付方式只有微信**：URL 传 `paytype=1/2/3/4/5`，页面渲染出的隐藏域**恒为 3**，
  `paytype_group` 里也只有一张 `<img src="resource/images/3.jpg">`（1/2/4 的图标文件在，但没有被渲染）。
- 只读辅助接口 `getExtraInfo`（金额上下限；`recharge.js` 里的兜底是 0.01~500）、
  `checkUser`（账号 → `{result:"E00",name:"…"}`）——**后端直调返回 403**（需浏览器会话 / CSRF），
  且会回**真实姓名**：**App 侧一律不调**，账号校验留给校方页面自己显示。
- App 侧口径 = `lib/features/net_fee/domain/net_fee_recharge.dart`
  （`netFeeRechargeUrl` / 快速档 / 账号与金额两条校验 / `NetFeeRechargeRequest`），
  面板 = `presentation/net_fee_recharge_sheet.dart`（选金额 → 去支付），
  入口 = 校园网页余额卡的「充值」按钮；支付页**内嵌优先**，
  内嵌页导航栏自带「用系统浏览器打开」兜底（微信 H5 支付在 WebView 里调不起微信时用）。

#### 提交流程：`POST submitRecharge` → `wxPaySaoma` 扫码页

真机走了一遍完整链路（2026-10-09，0.01 元订单，**未付款**）：

```
POST /WebPay/submitRecharge   （表单字段见上）
  → 3 秒内落到  GET /WebPay/wxPaySaoma
       订单号：<18 位，形如 20261009000000000123>
       商品名：网费充值<金额>元（账号：<学号>）
       二维码：<img src="resource/qrcode/<订单号>.jpg">      ← 服务端生成的图片
       按钮：  「支付完成」→ ./payReturn?orderno=<订单号>  「返回」→ ./toRecharge
       隐藏域：#orderno
```

扫码页自己的 `resource/js/wxpaySaoma.js`：

```js
var interval = window.setInterval(refreshOrderStatus, 3000);   // 每 3 秒
// GET checkOrder?orderno=…  →  result.result == 1 && result.order.paystate == "3"
//   → window.location.href = "payReturn?orderno=" + orderno;   // 自动跳成功页
```

`checkOrder` 直连返回 **403 Illegal Referer** —— 实测要凑齐三样才通：
页面 Referer + `JSESSIONID` + **`ajaxCsrfToken`**（`pub.js` 的 `$.ajaxSetup` 会给页面上每个
ajax 自动带上它，手写请求最容易漏这一项）。

**App 侧最终走的是这条链的原生复刻**（2026-10-09 三轮 · 不再内嵌网页，二维码画在自己的 UI 里）：

```
① GET  /WebPay/toRecharge?paytype=3&account=X&amount=Y   → JSESSIONID + csrftoken + validCode
                                                           + window.AJAXCSRFTOKEN
                                                           （这一页的 URL = 后面所有请求的 Referer）
② POST /WebPay/submitRecharge（form）                     → 302 Location: /WebPay/wxPaySaoma
                                                           ⚠ 缺 Referer 就是 403 Illegal Referer
③ GET  /WebPay/wxPaySaoma                                 → #orderno（订单号**只在这里**；
                                                             Location 不带它 —— 订单挂在会话上）
④ GET  /WebPay/checkOrder?orderno=…&ajaxCsrfToken=…&t=…
      → {"result":1,"order":{"orderno":"…","paystate":"…"}}
         paystate: "3" = 已支付；未支付实测 "0"（刚下单）/ "9"（放了一小时）
二维码 = GET /WebPay/resource/qrcode/<订单号>.jpg（image/jpeg，约 11.8 KB，带不带 Referer 都行）
         ⚠ 图片**内容** = 微信 Native 支付的 code_url：`weixin://wxpay/bizpayurl?pr=<token>`
           （解真机那张图实测得到，2026-10-09）。服务端**不暴露**这个链接 ——
           `checkOrder` 只回 `{orderno, paystate}`，另试 7 个可能的 JSON 路径
           （getQrCode / qrCode / getOrder / queryOrder / payUrl / getPayUrl /
           wxPaySaoma?orderno=）**全是 404** ⇒ 手机端要「唤起微信」只能在 App 本地解码：
           `features/net_fee/data/qr_pay_url.dart`（`image` + `zxing2`）。
           Android 侧还需在 manifest 的 `<queries>` 里加 `com.tencent.mm`（Android 11+ 包可见性）。
```

唯一实现 = `lib/features/net_fee/data/datasources/net_fee_recharge_remote_datasource.dart`
（`createOrder` / `fetchQrImage` / `fetchPayState`），UI = `presentation/net_fee_pay_screen.dart`；
口径与真机验证见 §21.7。内嵌网页（+ `netFeeRechargePageScript` 的自动提交）**降级为
下单失败时的兜底**。

#### ⚠ 校方页面 bug：URL 预填的**档位**金额会被打回 10 元

`recharge.js` 的 `initAmount` 分支里 `flag` 写反了（`webpay_pt3.html` 那页引的
`resource/js/recharge.js` 第 125–146 行）：

```js
$(".moneyBut").each(function () {
  if (parseFloat(this.value) == initAmount) { changeMoney(this.id); flag = false; return false; }
});
if (flag && !$("#tr_manualMoney").is(":hidden")) { /* 填进「其他」 */ }
else { $("#moneybut1").click(); }   // ← 匹配到档位时 flag 已是 false，也落这里 → 金额变 10
```

headless 浏览器**渲染后 DOM** 实测（2026-10-09，只读、未下单）：

| URL 里的 `amount` | PC 版页面最终 `amount` |
|---|---|
| `50` / `100`（校方档位值） | **`10`** |
| `30`（非档位值） | `30` |

⇒ **要预填档位金额，必须在页面加载完成后注入一次
`changeMoney(<按值找到的档位 id>)`**（App 侧 `netFeeRechargePageScript`，
经 `EmbeddedWebRequest.pageScript` 交给内嵌页）。
移动版 `toRechargeM` **没有**这段逻辑，实测 `value="50.0"` 本来就正确。

### 3.1 充值方式：微信 / **校园卡**（2026-10-09 四轮 · 从小程序 wxapkg 解包读出来的）

**「网费充值」是智慧江财主小程序（`wx70c0beda0bb7b021`）内部的页面**
（`pages/modules/developer/wfcz/recharge/view.js`，`typeC=微信原生`）——
`tools/_wxapkg_unpack.py <版本>` 解开就能读到它的口径（本机缓存版本 145）。

```js
// ① 充值方式列表（只读）
POST https://wxcourse.jxufe.cn/interface/api/interface/getWfczPayType
     {pageNum:1, pageSize:20, accept:"accept"}
  → {"code":1,"result":{"result":{"result":[
       {"dict_key":"weixin","dict_value":"…/1585799510593/pay/h5",      "desc":"微信支付"},
       {"dict_key":"card",  "dict_value":"…/1585799510593/pay/cardPay", "desc":"校园卡支付"}]}}}
     ⚠ **dict_value 就是该方式的充值接口地址**，别写死
// ② 充值
POST <dict_value>  {username, openId, total_fee}
     weixin → 回微信支付参数（小程序 wx.requestPayment）
     card   → 回 {code:0} 即「网费充值成功！」（**提交即从校园卡余额扣**，无密码）
// ③ 校方限制：chargeTypeChange 里写死「校园卡扣费只能给自己充值」
```

- `username`：微信传**学号**、校园卡传 **`enc`（加密 userId）** —— 两者不同，别搞混；
- `openId`：在 `checkAppAuth` 的 `pageUrl` query 里（44 字符 base64，**含 `+`**）。
  ⚠ Dart 侧**不能**用 `Uri.queryParameters` 取（form 语义会把 `+` 解成空格，实测
  `OID+AB=` → `OID AB=`）→ 从 `rawQuery` 正则取 + `Uri.decodeComponent`。
- App 侧唯一实现 = `lib/features/net_fee/data/datasources/net_fee_remote_datasource.dart`
  的 `fetchChargeTypes` / `fetchWfczIdentity` / `payByCampusCard`；
  UI 与二次确认见 §21.7。
- ⚠ **校园卡这条路 App 侧未实测**（真扣款，不能像微信那样「下单不付款」地验）。
- ℹ 小程序里的金额档是 `[50,100,150,200,300,360]`（与 Dr.COM 的 10/20/50/100/200 不同套）；
  范围校验 0.01~500。
