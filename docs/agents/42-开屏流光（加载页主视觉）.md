## 42.3 光效怎么做（一个 `AnimationController` 驱动）

1. **掠光**（主效果）= 一道斜的窄亮带（平行四边形），横掠楼体。
2. **辉光** = 中心三笔同色径向渐变，随周期呼吸（一个周期一次明暗）。

绘制顺序：`建筑 → [ 图层：辉光 + 掠光 → 按位图 alpha 收口 ] → screen 合成`。
**没有地面影**（见 42.4 ⑤）。

### 「只让非透明部分闪」是怎么保证的（用户 2026-10-08 口径）

用户原话：「我希望不是整个图都在闪光，因为是透明图，我希望只是非透明部分闪」。
实现 = **先裁后合**，四步（都在 `_paintLight` / `_maskToImage`）：

1. `canvas.saveLayer(rect, Paint()..blendMode = BlendMode.screen)` 开一个**透明**图层；
2. 图层内画两道光（层内也用 `screen`，保住「提亮而不是覆盖」的观感）；
3. `canvas.drawImageRect(位图, ..blendMode = BlendMode.dstIn)` —— 用位图 alpha 收口，
   图透明的地方从图层里**删干净**；
4. `restore()` 时按 `screen` 合成回画布 —— **`screen` 不碰 alpha**，
   所以裁好的「空白全透明」在合成后依然全透明。

端到端实测（真素材 × 深/浅底 × 7 个相位）：透明区增量**恒为 0**。

## 42.4 ⚠ 五条「别照直觉改」的硬口径（全部踩过，都有实测）

### ① 不能用 `srcIn` 做剪影遮罩

第一版是「`saveLayer` 里先画图，再用 `BlendMode.srcIn` 把渐变裁进剪影」——
**这是错的**：`srcIn` 的语义是「用源的 alpha **替换**目标」，于是**渐变透明的地方
（亮带两侧、辉光半径之外）会把建筑整块擦掉**。逐层二分探针实测：

| 图层组合 | 结果 |
|---|---|
| 图 + 掠光（`srcIn`） | 建筑只剩一道幽灵轮廓，其余全白 |
| 图 + 辉光（`srcIn`） | 整幅糊成白雾（89 KB 空白画面） |
| 图 + 两笔（`srcIn`） | 建筑几乎不可见 |

**要收口就用 `dstIn`**（乘 alpha），别用 `srcIn`（替换 RGBA）。

### ② 也不能只靠 `BlendMode.plus` 加色

`plus` 加色**不看目标**：源色无条件加到画布上，图透明的地方（空白四角）照样被照亮
—— 正是用户反对的那件事。改用 `BlendMode.screen`（滤色）后，目标 alpha=0 处结果恒为 0。
**但 `screen` 只解决了一半**（见 ④）。

### ③ 亮带的倾斜必须做成**几何**（平行四边形），**不许**用 `GradientRotation`

`GradientRotation` 绕 **rect 中心**旋转：一条 `(-260, 0, 260, 376)` 的细长竖带
转过 π/7 后，四角横向甩到 `-328.7 … +68.7` —— 「亮带已经扫出画面」的留白段里
它**又横着探回画面**，实测把左上角从 18 照亮到 **104/255**。

### ④ 行程端点必须再让出 `bandSkew`（`screen` 之后仍会漏光）

即使改成几何倾斜 + `screen`，只让到 `-bandWidth/2` 仍不够：
带子顶边比中心右移 `bandSkew/2`，所以中心到 `-0.1476`（t≈0.1）时
**左上角 = +0.0274，已探进画面**，那一丝最淡的光尾会扫过空白 ——
实测深色底左上角被提亮 **34 色阶**。现在 `bandPosition` 的端点是
`-0.25 - bandSkew → 1.25 + bandSkew`。

### ⑤ 最终收口：辉光 + 掠光整体按位图 alpha 裁（`screen` 管不住形状）

亮带有半幅图宽还带渐隐尾、辉光是一张铺满画布的径向渐变 ——
**它们的边缘必然扫过透明区**，`screen` 拦不住（它只管「目标 alpha=0」，
不管「源该不该出现在这儿」）。实测：只剩 `screen` 时深色底左上角在 t=0.2 被提亮
**18 色阶**。所以必须走 42.3 的「先裁后合」。

⚠ **别在图层里先铺一层不透明白**再 `dstIn`：`dstIn` 是**乘** alpha，
铺白之后 alpha 恒为 1、乘完只剩位图 alpha，光自己的强弱被抹平
—— 实测楼体上几乎看不到亮带。图层本来就该是透明的。

## 42.5 节奏与几何口径

| 常量 | 值 | 含义 |
|---|---|---|
| `period` | 2.6 s | 一个完整周期 |
| `sweepPortion` | 0.58 | 亮带走完全程所占比例；**剩下 0.42 是留白** |
| `bandPosition` | `-0.30 → 1.30` | 归一化位置（0 = 图左边界、1 = 图右边界）；端点含 `bandSkew` |
| `bandWidth` | 0.5 | 亮带宽度占图宽比例 |
| `bandSkew` | 0.15 | 倾斜量（顶边相对底边右移的比例） |
| `peakAlpha` | **0.85** | 掠光峰值加色量（见下方 ⚠） |
| `glowPeakAlpha` | 0.20 | 辉光呼吸峰值（另两笔再乘 0.55 / 0.40） |

**留白是刻意的**：匀速连扫会像加载条，「扫一道 → 停一拍」才像光在流。

⚠ **`peakAlpha` 必须给得高，别凭直觉往下调**：石材面本身就接近白（实测 R≈229/255），
而 `screen` 只能把像素往 255 推 —— 可用余量只有 26 个色阶。峰 alpha 给 0.32 时
楼体上只亮 **+1~6 色阶**，肉眼完全看不出「光在流」（行扫描实测：留白段 229、
亮带正中 235）。给到 0.85 才让扫过处接近过曝成一道亮痕。

⚠ **缓动曲线中点不是 0.5**：`Curves.easeInOutSine.transform(0.5)` 实测
`0.50278319…`（偏 +0.28%），所以扫程过半时亮带落在 0.504174…，**不是**正图心。
在 520 逻辑像素上约 1 像素，肉眼不可见 —— 断言请用 `closeTo(0.5, 0.01)`，
别写成 `1e-9`（会红）。

⚠ **插值滤波器必须是 `FilterQuality.none`**：源图是「大片透明底 + 硬边剪影」，
双三次类滤波（`medium`/`high`）会在透明/不透明边界上过冲，把大片 alpha=0 的区域
滤成 `RGBA(1,0,0,2)` 这种「几乎透明但有色」的像素；本页把源图放大 ×7.5 上下之后，
它们被摊成肉眼可见的灰蒙层（实测白底四角从 255 掉到 1）。

## 42.6 尺寸自适应（2026-10-10 起 = **纯比例 + PC 比例更小**）

> 口径演进三轮，别退回任何一轮：
> ① 最初「屏宽 82% + 封顶 520」—— 手机上占屏宽八成，用户：「动画内容太大，起码缩小一半」→ 砍到 41%。
> ② 砍半时顺手夹了 [`minImageWidth` 110, `maxImageWidth` 300]，**这是错的** ——
>    900 与 1500 宽的窗口都算出 300，看着像没适配。
>    用户：「**我希望图片改用比例大小，而非固定大小**」→ 去掉像素夹取，只留比例 + 防溢出。
> ③ 统一 41% 之后桌面显得偏大（窗口本来宽得多），
>    用户：「**PC 端的比例要比移动端小**」→ 按平台分两档。

`SplashFlowLightStage.responsiveWidth(available, {availableHeight, showTitle, platform})`：

1. 宽度 = **可用宽 × 当前平台比例**：
   - 移动端 `widthRatioMobile` = **0.41**（Android / iOS）
   - 桌面 `widthRatioDesktop` = **0.30**（Windows / macOS / Linux）
   - 判定走 `widthRatioFor(platform ?? defaultTargetPlatform)`，**不用** `Theme.platform`
     （本函数是纯静态计算，守卫要直接调它断言；测试用 `debugDefaultTargetPlatformOverride` 切平台）
2. 受**高度**约束（宽而扁的桌面窗口若只按宽度算会把图竖向撑爆）：
   高度预算 = 可用高 − `titleReserveHeight`(104) / `bodyReserveHeight`(32)，
   再 × `aspectRatio`；
3. 受**两侧留边**约束：最多 `可用宽 − 2×sidePadding`(16)。
   ⚠ 留边是硬约束、**优先于比例**：装不下就画得更小（极端给 0，`SizedBox` 自然零尺寸、
   画笔也会早退），绝不贴边 / 溢出。

**没有像素级的 min/max 夹取** —— 只有「平台比例 + 两条防溢出」。实测：

| 窗口 | 平台 | 图宽 | 占窗宽 |
|---|---|---|---|
| 手机 390×844 | 移动 | 160 | 41% |
| 手机 360×640 | 移动 | 148 | 41% |
| PC 小窗 900×650 | 桌面 | 270 | 30% |
| PC 大窗 1500×950 | 桌面 | 450 | 30% |
| PC 1920×1080 | 桌面 | 576 | 30% |

⚠ 四条「别退回」：
- `widthRatioMobile` / `widthRatioDesktop` / `sidePadding` / `titleReserveHeight` /
  `bodyReserveHeight` 都是**公开常量**，守卫直接引用 —— 别退回内联字面量
  （2026-10-08 把 96 改成 104 时，正因为测试里写死了 96 而红了一次）。
- **别再加回 `maxImageWidth` 之类的固定封顶**：那会让不同宽度的窗口算出同一个值。
  守卫里有两条专门钉这个 —— 「宽度就是可用宽 × 比例（8 档 × 5 平台逐一比对）」与
  「更宽的窗口必须得到更大的图（`widthAt(1500) > widthAt(900) > widthAt(390)`）」。
- **PC 比例必须严格小于移动端**（守卫 `widthRatioDesktop < widthRatioMobile`）：
  桌面窗口宽得多，同比例算出来的绝对值会过大。
- 要调大小只改这两个比例常量（0.41 = 砍半的落点，原 0.82），别在调用点写死像素。

## 42.7 深浅色口径

位图自带配色（石材米白 + 校红瓦），**不随主题反相** —— 深色下是「一张明亮的画浮在深底上」，
这是有意为之：开屏主视觉的价值就在这张图本身。只有一处跟主题走：

- **辉光** = `colorScheme.primary`（浅色校徽红 / 深色亮红档）。
- **掠光本色** = `StatusPalette.splashShine`（略偏冷的白，`#EAF4FF`）。
  **刻意不随主题换色**：建筑不反相，换色只会让两边不一致。为什么不用 `Colors.white`：
  石材面本身就接近 `#EDE7DF`，纯白扫过去差值太小、看不出「在流动」。

⚠ 光效是**穿过主题带**的（透明处不画），所以深色下**没有**「建筑外发光」的光晕 ——
这是 42.3 口径的必然结果，不是漏画。想要光晕就得先想清楚它怎么与「只在非透明部分」共存。

## 42.8 实现细节备忘

- **解码按显示宽度缩放**（`ResizeImage`，目标 = 显示宽 × 1.6）：源图全解约 9.9 MB 像素，
  而开屏最多画到 520 逻辑像素宽。⚠ 用 `ImageStreamListener` 手动解析，
  `ImageInfo` 要 `dispose`；**画之前不能 dispose**（实测会让 `drawImageRect` 静默失败、整幅空白，
  探针踩过一次）。
- **图取不到就退化成「只有标题」**：开屏页不该因为一张图白屏（`onError` 分支）。
- **`controller.repeat()` 不重置 value**（实测探针）：它是把当前值当相位锚点重排
  `_RepeatingSimulation`，所以 `didUpdateWidget` 里改 `period` 后首帧仍显示旧进度，
  下一帧起才按新速度走。开屏页从不改 period，这个一帧交错不必抹平；
  真要「重头播」得显式 `..value = 0` 或 `forward(from: 0)`。

## 42.9 守卫清单（`test/splash_flow_light_test.dart`）

- **素材**：路径在 `assets/images/splash/` 之下、宽高比 = 1848/1336、PNG 魔数（防被 LFS/占位符换掉）。
- **几何**：起点/终点时**整条带子含倾斜的角**都在图外（含 t=0~0.08 起步段）、
  扫程内单调、留白段整条在图右之外、扫程是斜扫。
- **★ 透明处不许变（零容差）**：用**真素材**渲染真画笔，把采样点按源图 alpha 分成
  「透明底」与「楼体」两组，深/浅两底色 × 7 个相位断言**透明区增量 ≤ 1**
  （实测为 0；历史 bug 是 +220 / +34 / +18）。
- **★ 楼体必须被照亮（反向保险）**：同帧断言楼体采样点在**深色底**上有正增量 ——
  否则上一条可以靠「什么都不画」假绿。
  ⚠ 必须在深色底上量：楼体是浅色，浅色底上 `screen` 的读数本来就是负增量。
- **绘制**：整个周期可画、极小画布不炸、零尺寸早退、`shouldRepaint` 语义、图未解码时早退。
- **尺寸**：窄/宽/矮三档 + 极小托底 + 任意输入都有限且合法。
- **动画**：单调推进、一周期后循环、长挂不炸、画布尺寸联动、换周期按新速度走。
- **标题**：默认显示、可关、淡入、图取不到时仍在。
- **深色**：主题色绘制不抛异常，且掠光**不随主题变**。

⚠ `MaterialApp` / `Scaffold` 自带 `FadeTransition` / `CustomPaint`，
凡是要 `.single` / `getSize` 的查找一律先收进 `SplashFlowLightStage` 子树
（否则 `Bad state: Too many elements`）。

⚠ **别用合成图做像素级回归**：合成全透明图会引入与真图无关的杂音
（实测同一段代码用合成图读到 `RGBA(1,0,0,2)`、用真图读到 255）。要量就量真素材。

## 42.10 验证手法（值得复用）

改光效后**不要只看测试绿**，把真图按相位渲染成 PNG 用眼睛过一遍：写一个临时测试，
`rootBundle.load` 真素材 → `instantiateImageCodec(targetWidth: …)` →
逐相位 `SplashFlowLightPainter(...).paint(Canvas(recorder), size)` →
`picture.toImage` → `toByteData(format: png)` 落盘。配套用
`toByteData(format: rawRgba)` 取像素做断言（42.9 的像素回归就是这么来的）。
临时探针用完即删（`test/tmp_*.dart`），别入库。
