## 30. 学习通（超星）只读接入（2026-09-19 立 · 用户原话：「我发现了一个接入学习通内容的方法，原智慧江财网页里有一项叫"网络教学"，然后会跳到江财教学网，然后可以从"本科生入口"/"学习空间"跳到学习通，这样我们就可以接入学习通的作业信息与通知消息了」）

模块 = `lib/features/chaoxing/`（自带 `README.md`）；接口笔记 = `reverse_engineering/学习通接口.md`。

- **用户三问三答（已拍板，别推翻）**：① 范围 = **只读三件套：课程 / 作业 / 通知**（不交作业、不标已读、改任何学习通数据）；② 入口 = **首页服务目录新增「学习通」磁贴 + 独立页**（目录 26 → **27** 条，`HomeServiceGroup.study`，强调色 `FeaturePalette.chaoxing = Color(0xFF0D47A1)`）；③ 成本 = **扫全部课程（≈2 请求/课）+ 本地快照缓存**。
- **登录 = 复用 §23 那条 CAS 换证链，全链只改 refer 一处（零密码）**：`TGC` → `AuthRepository.getServiceRedirectUrl(ChaoxingEndpoints.casServiceUrl)` → 网关 `unified-auth.chaoxing.com/login_auth/cas/jxufe/index?ticket=ST-…` → 「跳转中…」页（页内 `data`/`time`/`enc`）→ `GET /login_auth/cas/jxufe/login?data&time&enc` → `{"status":true}` —— **这一步才下发 `.chaoxing.com` 域级 passport**（`UID/_uid/_d/vc3/uf/uname/fid/p_auth_token/xxtenc/cx_p_token/DSSTASH_LOG`）→ 跳 `https://i.chaoxing.com?data&time&enc` → 302 `/base?t=…`（**收件箱 token 就在这一页**）。网关页 `jumpToRefer(firstReferer, …)` 把 `init?refer=` **原样回显** → 落点客户端可控，这就是「同一条链换个 refer 就能拿学习通会话」的原因。
  - ⚠ **用户给的「智慧江财 → 网络教学 → 江财教学网」只是线索**：ehall（`ehall.jxufe.edu.cn`）登录后**一个会话 cookie 都不下发**、9 个应用清单接口全 404 → 那条路不通，别再去试。
- 地址**唯一出处** = `lib/features/chaoxing/data/chaoxing_endpoints.dart`（含 `fid = '1412'`，当前链路用不到，只在将来要走 `passport2.chaoxing.com/login?fid=1412` 时用）；守卫 = `test/chaoxing_parser_test.dart` 的「端点与换证链守卫」组（CAS service 必须是网关那个百分号编码串 / refer 必须是学习空间 / 桥接参数回代）。
- **Cookie 必须按域匹配**（`SessionCookieJar`）：passport 是 `Domain=.chaoxing.com` 的**域级** Cookie，要发给 `i.` / `mooc1.` / `notice.chaoxing.com`；换证中间那几跳（`JSESSIONID`/`firstReferer`/`route`）是 **host-only，绝不外泄**（混发会把会话搞坏，`libsp` 踩过）；同名时**更具体的域赢**。
  - ⚠ `hasPassport` 认**三件套 `UID` / `_uid` / `p_auth_token`**（实测网关那步三个一起发；只认后两个会在服务端换写法时静默判成「没登录」——首跑因此挂 2 例）。
  - **会话不落盘**：`ChaoxingStore` 只存业务快照（box `chaoxing_<账号>`、key `snapshot`），凭据只在内存。
- **取数与解析口径**（细节见模块 README 与逆向笔记）：课程 `GET mooc1.chaoxing.com/visit/courses`（⚠ **每门课有两个 `stucoursemiddle` 锚点，封面那个在前且为空** → 两趟扫描、先认 `a.courseName`）；作业入口 = 逐课从 `stucoursemiddle` 抠 `data="/work/getAllWork?…&enc&openc"`（**每课 enc/openc 都不同**）；作业列表 = `GET /mooc-ans/work/getAllWork?<原样 query>` 的 **HTML**（⚠ query 必须**原样拼进 URL**，走 `queryParameters` 会再编码 → 签名对不上）；通知 = `GET notice.chaoxing.com/pc/notice/getNoticeList?s=<token>` 的 JSON（发件人字段是 **`createrName`**、已读是 **`isread`** 小写 r；**只有第一页 20 条**，翻页未破解）；红点 `i.chaoxing.com/base/getNoticeCount` 的 `msg` 是**布尔不是条数** → **不用于界面计数**。
  - **作废**：`POST /mooc-ans/api/workTestPendingNew` 恒返回 `[]`（7 种变体全试过）→ 别拿它当「待做作业」筛选器。
- **容错与刷新**：作业**逐课并发 4 路**，单课失败沿用上一次的旧作业并记进 `failedCourseKeys`；通知失败**沿用旧通知**（只把 `noticesAvailable` 置 false）；课程清单取不到 → 整次抛错。**任何失败都不落盘**（只有「取全了」的快照才 `store.save`）；`chaoxingMinRefreshInterval = 1 分钟` 闸门（口径同 §3 畅想之星：模式 = `lib/features/chaoxing/data/chaoxing_gate.dart` 的 `ChaoxingRefreshGate`，窗口起点 = 上一次**真的取到新数据**的时刻）。
- ⚠⚠ **风控挑战页 = 「刷新会刷新没」的根因（2026-09-19 四轮 · 用户原话：「作业、课程有时刷新会刷新没」）**。请求过密时超星回 **`202` + 4527 B** 的 `<title>提示页面</title>` + `【9010】操作异常，请输入图片中的验证码`；它**长得像成功响应**（`validateStatus` 全放行）但正文里没有课程锚点、没有 `getAllWork` 入口、没有「暂无内容」。首版一律当**空结果** → 那几门课的作业**静默消失**、残缺快照又被无条件写进 Hive（**好缓存一起没**）、若命中 `/visit/courses` 则**课程也空**。
  - **实测口径**（同一会话同一批课程详情页）：全并发 **8 / 16 个 → 0 次**；**24 个 → 24/24 全中**；触发后**每秒探测、60 秒仍不恢复**；**匀速 2 请求/秒扫 35 门课 → 第 31 门（≈62 个请求）起整段变验证码页**；稳态 1 请求/秒 × 20 个 → 0 次（只发 20 个，没到预算）。→ **触发量是「累计请求数（≈60/窗口）」而不是速率**：一次全扫 = 35 × 2 = **70 个请求 > 预算，必然撞墙**（慢到 2 请求/秒也一样）。**不能靠重试**（窗口 ≥ 60 秒，重打只延长）。
  - **① 分批轮转**（架构级，**别退回全扫**）：`ChaoxingRepository.maxCoursesPerScan = 20`（每轮 ≤ 40 请求，留余量）+ 游标 `_scanCursor` 滚动，没轮到的课**沿用缓存旧数据**并记 `pendingCourseKeys`，下一轮从游标接着扫 → 两轮覆盖 35 门。构造参数 `scanWindow` 可覆盖（≤ 0 或 ≥ 课程数 = 该轮全扫，测试/工具用）。
  - **② 只有「扫成功」才允许替换**（合并口径唯一实现在 `_fetchAllWorks`）：本轮扫成功（`okIds`）→ 采信，哪怕是可信空；窗口外 / 失败 / 被风控拦下 → **旧作业原样搬过来**。**这是「刷新不许丢数据」的守卫点** —— 首版只在 `failed.isNotEmpty && previous.works.isNotEmpty` 时按课 id 回填，且把「发过请求」当成「扫成功」（`scannedIds` 加在请求之前），失败的课照样丢（本轮实测 3 例失败）。
  - **③ 识别**：`ChaoxingHttpClient.ensureUsable(response, body)` = 风控页 → 抛 **`ChaoxingChallengedException`**（与 `ChaoxingSessionExpiredException` **必须分开**：风控换票没用），再判登录跳转。判据 = 「**状态码 202** 或正文含 `请输入图片中的验证码` / `【9010】`」双保险（防它改码/改文案）。**每个业务响应都要过它**。
  - **④「可信空」二分**（比识别更根本）：`worksOf` 抠不出作业入口、作业页 0 条且无「暂无内容」、`courses` 解析 0 门 → 一律抛 **`ChaoxingPageException`**（= 失败），**绝不返回空列表**。实测依据：真课程页 `getAllWork` 命中数恒为 1（35/35），而**真·空课**是「抠得出入口 + 作业页写「暂无内容」」这一档（22/35 门课）—— 两者必须走不同分支。
  - **⑤ 限速 + 冷却**：`chaoxingMinRequestInterval = 260 ms`（全局一条队列；业务请求传 `throttle: true`，换证链不排队；单测传 `Duration.zero`）。⚠ **实现必须原子预定下一格**（读-改-写之间不许有 `await`）—— 首版「读上次时刻 → 睡够 → 写时刻」在 4 条 lane 下一起醒来一起发，实测退化成 **4 请求/间隔**（64 个请求 4.3 秒跑完，风控照样触发）。撞风控后停发剩余请求 + 进 **`challengeCooldown = 120 秒`**（`challengeCooldownLeft` 早退，期间**一个请求都不发**）；`refresh({bool force})` —— **手动**下拉/点刷新带 `force: true`，**自动**刷新不带。
  - **⑥ 界面如实说**：概览卡那行 = 「共 N 条作业记录 · **只扫当下学期（12/35 门）** · N 门课扫描失败 · 另有 N 门课本轮没跑到 · 学习通限流，本轮沿用上次数据 · 通知暂不可用」（对应 `skippedCourseKeys` / `failedCourseKeys` / `pendingCourseKeys` / `throttled` / `noticesAvailable`）—— 不让用户猜「没作业」还是「没扫到」。⚠ 「只扫当下学期」那一段**只在真有课被跳过时才印**（`currentTermCode` 为空 = 不筛时不印，否则会说假话）。
  - **落盘口径**：课程清单取不到 → 整次抛错、不落盘；作业批次个别课失败 / 撞风控 → **照常落盘**（那些课的数据是从上一份快照搬过来的，落盘不会让数据变少）。
  - 守卫 = `test/chaoxing_data_test.dart`「★ 风控截断 → 已扫到的照算 / 没扫到的沿用旧数据」「★ 分批轮转」「★ 可信空压过旧数据」「★ 限速器在并发下依然成立」+「换证链不排队」。
  - 顺带：`ChaoxingHttpClient.looksLikeLoginPage(body)` 仍在（200 吐登录壳的少数接口），但**当前链路只用 `ensureUsable`**。
- ⚠⚠ **风控修完仍会丢数据：并发双扫 + `previous` 为 null（2026-09-20 · 用户原话：「我明明有一项线性代数的作业，为什么提示没有作业」）**。真机取证（Hive 逐帧回溯 + VM Service 读实时状态）查到**两条互相独立**的缺陷，都不在上一条的覆盖范围内：
  - **① 两个 `refresh` 并发跑**：页面侧有三条触发路径（首帧 `post-frame` → `_autoRefreshAll`、`RouteAware.didPopNext`、`_openChild().then`），而 1 分钟闸门**只在「真的取到新数据」之后**才记账 → 刚失败 / 刚进页面时根本拦不住重复触发。证据：Hive 里两帧快照**相差 280 ms**（`works=13` 与 `works=29`、`pending=15`/`19`、都 `throttled=true`）—— 两份 ~40 请求同时打，**双双撞风控**，后写的那份还盖掉前一份。修法 = `ChaoxingController.refresh` **单飞**（`Future<void>? _inFlight`，已在飞的那次直接 `return running`，第二次拿到的是**同一个 Future**）→ **去重闸门必须建在控制器里**，别指望页面侧自己收敛。
  - **② `previous` 是 null**：`_refreshOnce` 里 `final previous = state.valueOrNull ?? await repository.cached();` —— 首帧自动刷新在 `build()` 读完缓存**之前**触发，`state` 还停在 loading → 仓库那条「只信扫成功、其余沿用 previous」**整条失效** → 本轮没扫到的课（线性代数在课程表第 5 位、`pendingCourseKeys` 里就有它）连**磁盘缓存里那条作业一起丢**。⚠ 最容易漏的一环：仓库侧逻辑没错，错在**喂进去的 previous 是空的**。
  - **③ 界面口径补一半（用户那句话的另一半）**：「本轮未扫到」不许说成「没有作业」。唯一出处 = `ChaoxingSnapshot.isCoursePending / isCourseFailed / unscannedCourseKeys / unscannedCourseCount` + `domain/chaoxing_text.dart` 的 **`chaoxingCourseScanNote(snapshot, courseKey)`**（未扫到 → 「本轮未扫到（学习通有请求配额，下次进入补扫）」；失败 → 「本轮扫描失败，显示的是上次数据」；**正常扫过哪怕真没作业 → 空串、不挂备注**）。三个渲染点：`ChaoxingCourseRow` 的 `note` 参数、`chaoxing_courses_screen.dart` 的副标题 + 展开正文（**空课正文只在「正常扫过」时才敢写「这门课没有作业记录」**）、主页「待做作业」空态（`另有 N 门课本轮未扫到，可能有遗漏`）。
  - 守卫 = `test/chaoxing_data_test.dart`「★ 控制器：单飞 + previous 兜底」3 例（假仓库 `implements ChaoxingRepository`，只实现控制器用到的成员；并发两次 `refresh` 必须 `identical` 且 `refreshCalls == 1`；把 `cached()` **挂起**（延迟而非返回 null）制造「build 还在读缓存」的竞态，断言 `previous` 非空且带着旧作业）+ `test/chaoxing_screen_test.dart`「★ 未扫到的课如实说」2 例。
  - ⚠ **定位手法（日志不可靠时的替代）**：`flutter run` 重启会**截断日志**、`debugPrint` 什么都不剩 → 改从 **Hive 逐帧回溯**（同一 key 在 Hive 里是**追加**的：`raw.find(b'{"courses"')` 拿到的是**最旧**那帧，要 `re.finditer` 扫全部、把每帧的 `fetchedAt` / 条数 / 关键字段打出来）+ **VM Service 读实时状态**（`ProviderScope.containerOf` 沿 `visitChildren` 找容器再 `read(provider)`）两边对。⚠ VM `evaluate` 两个坑：**被闭包捕获的局部变量不做空安全提升**（要先 `final c = found; if (c == null) …` 再 `c.read(...)`，否则报 `Method 'read' cannot be called on 'ProviderContainer?'`）；`valueAsString` **会截断**（≈100 字符）→ 长结果拆成多次短查询。
- ⚠⚠ **「为什么要扫一遍才知道有哪些作业」→ 只扫当下学期 + 通知兜底（2026-09-20 · 用户提问：「为啥要扫描一遍才知道有哪些通知作业，没有统一接口吗」，随后 ask_user_question 选定 A+B）**。先纠正前提：**通知与课程本来就有统一接口，只有作业没有** —— 通知 = `notice.chaoxing.com/pc/notice/getNoticeList?s=`（JSON，**1 请求**）；课程 = `mooc1.chaoxing.com/visit/courses`（HTML，一次 34~35 门，**1 请求**）；作业 = **逐课** 2 请求（`stucoursemiddle` 抠签名 query → `getAllWork`）。**结构上就不可能有聚合**：`getAllWork` 的 query 带**每课一份签名**（`enc`/`openc` 各 32hex，35/35 门各不相同，签名里编着「这台客户端有权看这门课」）→ 一串 courseId 拼批量请求在协议层不成立；唯一长得像聚合的 `POST /mooc-ans/api/workTestPendingNew`（课程列表页 JS 自己用它点红点）**恒返回 `[]`**（web UA / App UA / `mooc1-api` 域共 10 种变体全空）；`task.chaoxing.com`（收件箱壳页配置里的 `taskHttps`）根路径 404、猜的 5 条路径全 404；学习空间与泛雅引用的 23 个 JS bundle 里**没有任何** work/task 接口字面量。**所以解法是缩小范围而不是分批轮转**：
  - **A｜只扫当下学期**：唯一口径 = `lib/features/chaoxing/domain/chaoxing_scan.dart` 的 **`chaoxingScanPlan(courses, currentTermCode:)`**（仓库唯一入口，别在 `_fetchAllWorks` 里再判一次）→ `targets` / `skipped`。`currentTermCode` = `chaoxingRepositoryProvider` 里 `schoolTermCode(currentSchoolTerm(DateTime.now(), terms: offlineSemesterTerms).xn, .xq)`（**与课表/校历同源口径**），课程侧用 `ChaoxingCourse.termCode`（`261学期` → `261`）。**学期前缀认不出的课照扫**（实测 35 门里 2 门无前缀，多为实训/通识）。两条**不筛**退路：`currentTermCode` 为空；**一门课都不匹配当下学期码**（新学期课程还没建 → 照筛会让界面变成「一条作业都没有」）。**真机实测 2026-09-20：12/35 门 = 24 个请求、6059 ms、0 风控**（学期分布 `261学期=10 / 无前缀=2 / 252学期=12 / 251学期=11`）→ 窗口装得下整个课程池、**游标推回 0、每轮都是同一批全量**（不再「两轮才凑齐」）；`scanWindow=20` 只在「一学期 > 20 门课」时才轮到，那时才恢复轮转 + `pendingCourseKeys`。⚠ **代价（用户已知情选定）**：往期学期不再取数，全新安装只看得到当下学期作业（界面写「只扫当下学期（12/35 门）」）。
  - **新字段 `ChaoxingSnapshot.skippedCourseKeys`**（+ `isCourseSkipped`，JSON 往返与旧缓存缺键容错）：**必须与 `pendingCourseKeys` 分开** —— 那个是「排上了、下次会扫」，这个是「**有意不扫、下一轮也不扫**」。`chaoxingCourseScanNote` 三档文案：失败 → 「本轮扫描失败，显示的是上次数据」；未扫到 → 「本轮未扫到（学习通有请求配额，下次进入补扫）」；**非当下学期 → 「非当下学期，未扫描（只扫当下学期）」（守卫断言这一档不得含「下次」）**。
  - **B｜通知里兜一刀**：`domain/chaoxing_text.dart` 的 `chaoxingNoticeIsWorkPost`（**只认 `作业:` / `作业：` 开头**；「作业结束提醒」是已结束不是发布）/ `chaoxingNoticeWorkTitle`（剥前缀与《课程名》）/ **`chaoxingNoticeWorkHints(snapshot)`** = 平台发的作业通知里、**作业列表还没扫到**的那些；**去重口径 = 该课已有作业的标题是否出现在通知标题里**（实测作业那条 `9月20日24:00前提交作业` 正是通知标题 `作业:《261学期 线性代数（工）》9月20日24:00前提交作业` 的后半段）→ 已扫到的不重复显示；`courseId` 为空的通知直接跳过（挂不上课程）。界面 = 主页「通知里的作业提醒」卡片（`kChaoxingPreviewWorkHints = 3`，**为空整块不画**），行点开走既有的 `showChaoxingNoticeDetail`。
