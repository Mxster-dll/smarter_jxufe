### 31.7 教务「参数会不会把 cookie 弄失效」对照实验（2026-09-20，结论：**不会**）

- 起因：用户原话「经常导致凭证失效，是不是查询参数的问题，我们的教务系统有这样的特性：有些查询参数错误会导致cookie失效」。
- 做法（在 App 内、用真实会话、`currentImsDioProvider`）：6 组参数各发一次 `/kbbp/dykb.GS1.jsp?kblx=jsikb`，**每组前后各插一次最小探活**（`/jw/common/getStuGradeSpeciatyInfo.action?xh=`），并记录 `ImsSession` 的 `issuedAt` 判断期间有没有换票。六组 = 生产 42 字段整校区 / 只去掉 `nj·hidNJ·isNjQuery` / 最小集 / 楼房 35 / 单间 `1000752` / 最小集 + 楼房。
- 结果：**6/6 都返回真实 HTML（整校区 2 523 624 B / 2 066 551 B，楼房与单间是「无数据」模板 2.6 KB），没有一次 alert 页，13 次请求之间会话始终 alive，`issuedAt` 一次都没变** ⇒ 「参数错 → cookie 失效」**未复现**，`buildReportFields` 不需要按这个假设改。
- 真正的失效链（实测）：**磁盘上的 JSESSIONID 常常在启动时就已经过期**（`peek()` 拿到的票 `probe()` 直接判 expired）→ 第一个业务请求被服务端回 547 B 的 `<script>alert('温馨提示：凭证已失效，请重新登录!');` → `ImsAuthInterceptor` 换票（CAS 往返实测 ~0.7 s）+ 用新票重试 → 成功。`ImsSession.renew()` 并发去重（`_inflight`），**失败时只置 `phase = failed`、不 `forget()`** ⇒ 只有 CAS / TGC 侧真的失败（要 MFA / TGC 过期）时才会连续「凭证已失效」，那属于登录链路而不是查询参数。
- ⚠ **工具坑（我复现出的假象）**：探针里**不要一次读票、多处复用**。我第一版把 `imsAuthLocalDataSource.read(account)` 读到的票一次性写进 `dio.options.headers['Cookie']`，结果 13 个请求全带着那张已死的票 → **14 次换票**（看着像「App 在疯狂失效」）。正解：每个请求前重新 `read(account)`（或直接用 `ImsSession.jsessionId / ensureReady()`），一次实验里 `issuedAt` 只在第一发变化。
- ⚠ **跨客户端借用会话不可行**：用 python `requests` 带上 App 当前同一个 `JSESSIONID` 打教务，**一律回 alert 页**（哪怕同一时刻 App 侧 `probe()` = alive）。要验教务行为，只能在 App 内（`currentImsDioProvider`）或用**自己**走 CAS 登录拿到的会话。

### 31.10 节次选择器的「连接 / 断开」过渡（2026-09-20 九轮，用户原话：「我希望为查无课时间功能内的节数选择器添加动画，尤其是两段连续选中的段被连接时，以及单一连续段被分开时」）

**目标**：点中间那一格把两段红接上、或点掉一整段中间的一格把红拆开时，红要**看得见过程**，而不是瞬间跳变。

**唯一实现**（都在 `lib/features/ims/public_query/`）：
- 领域层 `domain/classroom_free.dart` 的两个纯函数：
  - `classroomPeriodJointSegments(from, to, {count})` —— 过渡分段：只有**两态都勾中**的连续节次合成一段，其余各自独立；
  - `classroomPeriodJoints(from, to, segments)` —— 过渡里要动的「缝」，返回 `({int left, int right, double fromRed, double toRed})`（值只有 1 / 0；两态一样的缝**不返回**）。
- 页面 `presentation/classroom_free_screen.dart`：`AnimationController _jointAnim`（`kClassroomJointDuration = 220ms`）+ `Set<int>? _jointFrom`（过渡起点）+ `_periodSelector`（`AnimatedBuilder` 包住整段选择器）+ `_PeriodJointPainter`（缝上的桥接覆盖层）。

**两条恒等式是这套动画的地基**（守卫逐条钉住）：`classroomPeriodJointSegments(a, a) ≡ classroomPeriodRuns(a)`、`classroomPeriodJointSegments(b, b) ≡ classroomPeriodRuns(b)` —— 于是 **t=0 的画面等于按下前、t=1 等于按下后**，起止都不会「跳一下」。

**四条口径（改之前先读）**：
1. **几何一格都不动**：「合并段内部间隔 = `Wrap.spacing` = `kClassroomChipGap`」这条老不变式就是动画可行的前提（合并前后总宽一致 → Wrap 的折行结果也一致）。渲染结构仍是**一张 Wrap**，桥接件只是画在它之上的一层 `CustomPaint`。
2. **视觉一律由 `alpha` 决定，不由胶囊的 `selected`**：`selected` 是**提交态**（点下去那一刻就变了），而过渡第一帧上「刚被点掉的那一格」看起来还得是红的。⚠ 因此 `_periodRun` 的 `labelColor` / `labelWeight` / `side` 三个都必须**显式**传给胶囊 —— 交给它按 `selected` 自己判，第一帧就会闪一下「红底 + 灰字 + 描边」。
3. **只有稳态才走 `_chipFill` 的 canvasColor 路子**：`alpha == 1` 时与从前**逐值相同**（红由外层容器出、胶囊透明、`canvasColor` 也染红 —— 八轮那条 1px 细线的解法）；`0 < alpha < 1` 时反过来让**格子自己**涂一层带 alpha 的红（`fill:` 参数），免得同一块红被容器 + 胶囊叠两次、深浅不匀。端点值不经过 `Color.lerp`（浮点近似会让收尾差一点点）。
4. **桥接件向两侧各侵入 `kClassroomJointInset = 8`（= 圆角半径）**：缝只有 6px，两侧格子各有 8px 圆角 —— 不侵入就必然在四个角露白。它按**缝的中心**向两边生长（实心红比半透明红叠白底干净），缝那一带没有任何胶囊覆盖，所以画在 Wrap 之上既补缝又不盖字。窄屏折行时两格不在同一行 → 那条缝这一帧不画。

**触发点**：`_togglePeriod`（点）、`_beginPeriodDrag`（拖动起手，之后每次落到新格子只换终点；`_startJointTransition` 在过渡没跑完时**不重起**，否则 t 归零会往回弹）、`_resetPeriodsToNow`（起点取 `_renderedPeriods` —— 那一刻 `_periodsTouched` 正要翻牌，别处拿不到旧集合）。

**守卫**（`test/classroom_free_test.dart` 6 例 + `test/classroom_free_screen_test.dart` 3 例）：
- 领域层：端点恒等式（含空集 / 全集 / 完全换一套 7 组）、接上与拆开的分段形状、缝的方向（0→1 / 1→0）与「两态一样的缝不返回」、整体换一套、拖动多选、越界容错；
- 界面：① 连过去的两端（第一帧仍是两段 + 中间那格灰字带描边、`selected` 已是 true、覆盖层就位；中段格子自带 `0 < a < 1` 的红且文字在灰→白之间；末帧 `Run-1-5` 实心红 + 覆盖层摘掉）；② 拆开同理（第一帧 `Fill-3` 仍是**精确的红**、白字、无描边，中段红在退）；③ **像素级硬证据** —— 拆开的第一帧把 1..5 整块区域扫一遍仍然处处同色（`_scanSolidRect`，复用八轮那套 `_capturePixels`）。
