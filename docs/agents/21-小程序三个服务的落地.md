## 21. 小程序三个服务的落地（2026-09-16 · 用户原话：「本科生成绩单实现到现有的成绩页」「还有一个网络服务，整合到现有网费功能里，网费功能的名字改成『校园网』」「还有一个『我的邮箱』功能，做成独立功能」）

### 21.0 通用侦察法（**先读这一条，别再抓包**）

智慧江财是**门户式（低代码）小程序**：所有服务都是门户后台下发的条目，条目里带真实地址。
**只要已配置平台 GUID，就能把全部门店列出来**（实测 2026-09-16，49 条）：

```
GET https://wxcourse.jxufe.cn/platForm/api/littleProgram/application/getHotAppsByPlatformUsername?platformUsername=<GUID>
GET …/getNewAppsByPlatformUsername?platformUsername=<GUID>
GET …/getMyAppsByUserDefaultRole?platformUsername=<GUID>
→ {code:1,success:true,result:[{appName,appId,applicationId,url,classify,count}…]}
```

单条服务的**完整元信息**（含 memo 说明与带签名入口）走 `checkAppAuth`：

```
GET …/api/littleProgram/application/checkAppAuth?appid=<appId>&platformUsername=<GUID>
→ {code:200,result:{name,memo,typeC:'H5',isCredible,pageUrl:'…带 cardinfo/openId 签名…',username:'<加密账号 enc>'}}
```

- `result.username` = **加密账号（enc）**，H5 的 `?userId=` 参数；`pageUrl` = H5 入口（`useVersion 2.0` 时由服务端按会话签发）。
- 本账号实测条目：本科生成绩单 `1741570971384`／本科生在校证明 `1741570790414`／网络服务 `1575336885141`／我的邮箱 `wx0bc2c17d023b213d`（**跳独立小程序**，门户侧只有账号类接口）／网络故障报修 `1575430876461`。
- 报文头（全部这些接口都要）：`Referer: https://servicewechat.com/wx70c0beda0bb7b021/143/page-frame.html` + 浏览器 UA（仓库已有 `deviceProfileRepositoryProvider.userAgent`）。
- 侦察脚本（可重复跑，**只读**）：`tools/_wxapkg_unpack.py`（PC 微信 wxapkg 解密解包，需 `<PYTHON>`）、`tools/_wxapkg_scan.py`（全分包关键词检索）、`tools/_wx_mail_probe.py` / `_wx_apps_probe.py` / `_wx_cert_probe.py` / `_wx_netsvc_probe*.py` / `_wx_email_probe*.py`（本轮新增：从已解密包与门户接口挖邮箱 / 成绩单 / 网络服务），报告落在 `.scratch/wx_*.txt`。

### 21.1 本科生成绩单（成绩页入口）

- **官方只有「邮箱投递」，没有下载接口**（教务处 2025-05-20 上线口径，H5 = `/jxufeLayuiApp/certificate/undergraduate/scoreIndex.html`）：
  - `POST https://wxcourse.jxufe.cn/layuiApp/score/verifySecondMajor`（form `userId=enc`）→ `{status,message:",1,2"}`：**message 从下标 1 起按 `,` 切**，`1`=有主修、`2`=有辅修（本账号实测 `,1`）。→ 报表类型 `1` 主修(中)、`11` 主修(英)、`2` 辅修(中)、`22` 辅修(英)。
  - `POST …/layuiApp/score/bkscj`（form `userId`/`email`/`courseId`）→ `{status,message}`，**服务端把盖章 PDF 发到该邮箱**。
  - 在校证明同构：`POST …/layuiApp/studentCertificate/bks`（form `userId`/`email`）。
- **⚠ enc 必须按 form 编码提交**：enc 形如 `AAAAAAAAAAAAAAAAAAAAAA==`，H5 里专门写了 `if(username.indexOf("=")!=-1||username.indexOf("+")!=-1) username=encodeURIComponent(username)`。Dio 的 `data:{}` + `Headers.formUrlEncodedContentType` 与之同口径（`+`→`%2B`、`=`→`%3D`），守卫 `test/transcript_test.dart` 断言请求体里出现 `userId=…%3D%3D`。
- **本机网络取不回 PDF**：学生邮箱 `stu.jxufe.edu.cn` 的 993/143/443/25 **全 timeout**（`mail.jxufe.edu.cn` 仅 :25 通），IMAP 代取方案不可行 → 用户 2026-09-16 拍板「发送后我自己去邮箱下载」，**不要再试图做本地落盘**。邮箱 Web 入口仅校园网可达。
- 实现：`lib/features/ims/grades/domain/transcript_report.dart`（`transcriptReportTypes` / `transcriptEmailValid` / `kTranscriptVerifyUrl`）、`data/datasources/transcript_remote_datasource.dart`（`fetchEncUserId` / `fetchReportTypes` / `sendTranscript`，DioException 统一转 `TranscriptApiException`）、`data/providers/transcript_providers.dart`（`transcriptEncUserIdProvider` / `transcriptReportTypesProvider` / `transcriptDefaultEmailProvider`）、`presentation/transcript_sheet.dart`（弹层：类型下拉 + 邮箱 + 发送 + 学信网链接）。
- **入口位置 = 筛选栏下方一行 `TextButton.icon`（`Key('grades_transcript_entry')`）**，位于 `grades_screen.dart` 的 `_buildTranscriptRow`，**不要塞进 AppBar**：内嵌（侧栏模式）时成绩页不画导航栏（§19），按钮必须落在内容里。
- **邮箱默认值 = 学生邮箱地址**（`transcriptDefaultEmailProvider`）：**首选**邮箱接口给的权威值（`myMailboxProvider`），**回退**登录账号（= 学号）+ `@stu.jxufe.edu.cn`。⚠ **别用学籍 `serialNo` 拼**：实测本账号 `serialNo = 201600000000`（12 位学籍号），而学生邮箱是 **10 位学号** `2000000000@stu.jxufe.edu.cn`（首版用 serialNo，真机验收直接暴露成错的邮箱地址）。

### 21.2 网络服务（并入「校园网」页第二段 · 2026-09-16 二轮已打通**真数据**）

- 本体 = 广州热点 Dr.COM **「用户自助服务系统」**（`https://wxcourse.jxufe.cn/1575336885141/`），
  身份 = 小程序 `applicationId 196 / appId 1575336885141 / classify '6' = 生活`，`type 3`（H5）。
- **登录链（关键就一个参数，别再试别的）**：
  `checkAppAuth(appid, platformUsername=GUID)` → `result.username`（enc 学号）+ `result.pageUrl`
  → **`GET <pageUrl>&userId=<urlencode(enc)>`** → 302 且 `Set-Cookie: JSESSIONID=…` → 之后只带
  `Cookie: JSESSIONID=…` 即可。此前「只带 pageUrl 自带 cardinfo/openId」一律 302 回 `/login/`，
  根因 = 小程序 `pages/modules/app/detail/view.js` 会**追加 `userId`**（`jwtToken` 传空串也行，
  `accessKey/colleageCode/jssdk_url` 可省 —— 逐项实测过）。
- **会话失效**：业务请求返回登录页（含「用户自助服务系统」且含 `name="password"`）→ 自动重登一次并重试；
  仍失败则报「会话已失效」。**CSRF**：写操作 token **每页现取**，两种写法都要认
  （`var AJAXCSRFTOKEN = '…'`、`"ajaxCsrfToken=" + '…'`、隐藏域 `name="csrftoken" value="…"`）。
- **⚠ 第四个坑（真机才暴露的静默空数据）**：这套服务端**有一半接口不回 `Content-Type`**
  （实测 `dashboard/getLoginHistory`、`bill/getMonthPay`、`bill/getPayMent`、`bill/getOperatorLog` 完全没有该头），
  Dio 便**不做 JSON 解码**→ 返回 `String` → `networkList(String)` **静默变空列表**，
  界面显示「暂无记录」而服务端其实有数据（近期上网记录 / 历史账单都中招）。
  修法 = 全链路 `ResponseType.plain` + `NetworkServiceRemoteDataSource._decodeJson`（按正文首字符判 JSON）。
  **教训**：凡「无 content-type 也返回 JSON」的服务端，别依赖 Dio 的内容协商；
  解析器也**不要**把「类型不符」默默当空集合（该抛就抛，否则静默空态骗过测试）。
- **拿数必看的三个坑**：① 账号概览**只能**从 `/dashboard` 的 `window.user` 内嵌 JSON 扒
  （`dashboard/refreshaccount` 是 fire-and-forget，**空响应**）；② `bill/getUserOnlineLog` **必须带
  `startTime`/`endTime`**，`bill/getMonthPay` **必须带 `year`**，否则返回空；③ 账单 `rows` 的结束时间是
  **开区间端点**（= 下期开始、上一期结束 == 下一期开始），学校页面显示的结束日要**减一天**
  （`NetworkMonthBill.endDay`）。
- 实现（`lib/features/network_service/`）：`data/datasources/network_service_remote_datasource.dart`（会话缓存
  + 自动重登 + token 现取 + 全部读写接口，与网费共用 `netFeeDioProvider`）、`data/providers/network_service_providers.dart`
  （整组 provider + `invalidateNetworkService(WidgetRef)` 做**写后对账**）、
  `domain/network_service_models.dart`（容错解析）+ `domain/network_service_format.dart`（**纯格式化，无 Flutter 依赖**，
  由 `presentation/network_common.dart` re-export 给页面）、`presentation/network_service_section.dart`（校园网页第二段）
  + `network_records_screen.dart` / `network_devices_screen.dart` / `network_services_screen.dart` / `network_profile_screen.dart`。
  旧的「只做一个『打开网络服务』按钮」那套（`fetchNetworkServiceUrl` / `netFeeNetworkServiceUrlProvider` / `_buildNetworkServiceCard`）**已删除**。
- **敏感信息口径**：上网密码（服务端下发明文）**默认掩码**、点开才显示、复制取真值；身份证号只显示前 3 后 4；都不写日志。
- **写操作**（报停 / 复通 / 预约套餐 / 解绑设备 / 强制下线 / 改密码 / 改资料）一律
  **二次确认（危险操作红色按钮）→ 提交 → 写后对账刷新**，与选课写操作同口径；文案只在有服务端文案时用它。
- 未做：上网记录导出（`/bill/exportUserOnlineLog`）、在线充值支付流程（微信充值只做「带账号跳学校支付页」）。

### 21.6 不靠点击的 UI 验收法（2026-09-16 新增，很值得复用）

**像素点击测 Flutter 桌面 app 不可靠**（`view_image` 报的中文坐标偏差极大：同一行报 590 与实际 380 差 200+；`mouse_event` 滚轮 Flutter 不接收）。改用 **VM Service 驱动 + 元素树检索**：

1. `tools/_vm_eval.py <ws-url> [library-uri-substring] "<单行表达式>" [--out x.txt]` —— 通用求值探针。
   - ws-url：`(Select-String "$env:TEMP\ge_flutter_run_windows.log" -Pattern 'ws://127\.0\.0\.1:\d+/[^/]+=/ws').Matches[0].Value`
   - **`--out` 必用**：终端直打中文是 GBK 乱码，写文件再 `read`。
   - 表达式必须**单行**；库作用域 = 该库直接 import 的名字（`home_service_catalog.dart` 的库含 `MyMailScreen` / `NetFeeScreen`，但**不含** `GradesScreen` → 后者要用 `grades_screen.dart` 自己的库）。
2. **推页面**（确定性导航，不猜坐标）：
   ```dart
   (() { NavigatorState? nav; late void Function(Element) visit; visit = (Element e) { if (nav != null) return; if (e is StatefulElement && e.state is NavigatorState) { nav = e.state as NavigatorState; return; } e.visitChildren(visit); }; visit(WidgetsBinding.instance.rootElement!); (nav as NavigatorState).push(MaterialPageRoute<void>(builder: (BuildContext c) => const XxxScreen())); return 'pushed'; })()
   ```
   开弹层同理：`showTranscriptSheet((nav as NavigatorState).context)`（在 `transcript_sheet.dart` 的库作用域里求值）。
3. **验内容（硬证据）**：遍历 `Element` 树取 `Text.data` / `EditableText.controller.text`：
   ```dart
   (() { final hits = <String>[]; late void Function(Element) v; v = (Element e) { final w = e.widget; if (w is Text) { final d = w.data ?? ''; if (d.contains('关键词')) hits.add(d); } else if (w is EditableText) { hits.add('EDIT[' + w.controller.text + ']'); } e.visitChildren(v); }; v(WidgetsBinding.instance.rootElement!); return hits.length.toString() + ' :: ' + hits.join(' || '); })()
   ```
   本轮靠它验出：校园网第二段 5 个文本全在树里（⇒ checkAppAuth 现取签名 URL 真机成功）、成绩单弹层的报表类型是**真从服务端拿的**（`主修成绩单（中）`）、以及**一个真 bug**——预填邮箱曾用学籍 `serialNo`（12 位 `201600000000`）。
4. **滚动**：`ScrollableState` 也能遍历到（`s.position.jumpTo(maxScrollExtent)`）；页面里通常有多个 Scrollable（侧栏 / 仪表盘 / 页面自身），用「子树里是否含目标文案」挑对的那个。
5. ⚠ `debugDumpApp()` 在 flutter run 里**只把首页路由那部分写进日志**（有 `MaterialApp`/侧栏、没有 pushed 页面）→ 别用它验 pushed 页面。
6. 截图脚本 `tools/_shot.ps1 -Out x.png [-ClickX/-ClickY] [-Wheel/-WheelSteps]`（自动还原最小化窗口、可选点击/滚轮）仍要跑，但只当「大致观感」；**控件树命中才是硬证据**。

### 21.7 网费充值（App 内充值面板 · 2026-10-09 加）

**用户原话三连**：

1. 「接下来我想扩充网费功能，我希望引入网费充值功能」→ 定档 **App 内完整充值面板**；
2. 「按理说应该输入金额后，直接弹二维码」→ 先做成「内嵌校方页 + 自动提交直达扫码页」；
3. 「**你现在还是内嵌了一个网页，我希望你直接把这个网页里的二维码封装到我们的 ui 里**」
   → **最终形态 = App 原生收银台**：用 `dio` 复刻校方那条四步链路，
   二维码取回来自己画（见下「App 原生收银台」）；内嵌网页**降级为下单失败时的兜底**。

**钱只能走校方通道**（App 不代收、不碰支付凭据）：

- 小程序「网费充值」（wfcz `1586481872684`）的 `checkAppAuth` 回的是 **`typeC='微信原生'`**、
  `pageUrl` 形如 `/pages/modules/developer/wfcz/view?cardinfo=…&openId=…` —— 它是**微信原生
  小程序页面**，支付走 `wx.requestPayment`（要该小程序的商户凭据与 openId），**App 侧不可能复刻**。
- Dr.COM 自助服务系统的「账户充值 → 在线充值」页里**唯一那张卡就是「微信充值」**
  （实测页面 HTML 里 `pick-card` 只有一个），落点 = 校方网页 `self.jxufe.cn/WebPay`。
  这条**能在 WebView 里跑**，于是 App 的价值 = 把「改账号 / 选金额 / 找入口」压成一次选择。

**三条实测口径（缺一条就白跑）**：

1. **直接开 `toRecharge`，不要开 `recharge`**：`/WebPay/recharge?…&amount=50` 302 之后的
   Location 只剩 `paytype` 与 `account` —— **金额预填静默失效**。
   正确的是 `toRecharge?paytype=3&account=X&amount=50`（页面 hidden `amount` 渲染成 `50.0`，
   `recharge.js` 的 `initAmount` 会自动选中该档；金额不在档位里就填进「其他」）。
2. **同一个 URL 管两端**：`recharge.js` 开头判 `winWidth <= 768` 就
   `window.location.href = "toRechargeM" + 当前 query`（**query 原样带走**）→ 手机自动落移动版，
   而移动版同样吃 `amount`（实测 `value="50.0"`）。移动版多一步：**支付方式在确认页里才选**。
3. **支付方式只有微信**：URL 传 `paytype=1…5`，页面渲染出的隐藏域**恒为 3**
   （1/2/4 的图标文件在，但没被渲染）。所以面板里「校方支付页当前唯一开通的通道」不是偷懒。
4. **「二维码」本来就在校方流程里**（真机走了一遍完整链路，0.01 元订单、未付款）：
   `POST ./submitRecharge` → 3 秒内落到 **`/WebPay/wxPaySaoma`（扫码支付页）** ——
   页面上是「订单号 + `<img src="resource/qrcode/<订单号>.jpg">` + 支付完成 / 返回」。
   该页自己的 `wxpaySaoma.js` **每 3 秒 GET `checkOrder?orderno=…`**，
   `order.paystate == "3"` 时自动 `window.location = payReturn?orderno=…`（成功页）。
   ⇒ 用户那句「按理说应该输入金额后直接弹二维码」差的只是**替用户点掉表单上那一次「立即支付」**。

**别做的事**：`getExtraInfo`（金额上下限）与 `checkUser`（账号 → 姓名）**后端直调返回 403**
（要浏览器会话 / CSRF），且后者会回**真实姓名** → **App 侧一律不调**，账号校验留给校方页面自己显示。
金额校验同理：本地只挡「空 / 非数字 / ≤0」，**不复刻校方 0.01~500 的上下限** —— 照抄一定会过期，
抄错了还会把合法金额挡在门外。

#### App 原生收银台（主路径 · 2026-10-09 三轮）

**四步链路**（唯一实现 =
`lib/features/net_fee/data/datasources/net_fee_recharge_remote_datasource.dart`，全部真机实测）：

| # | 请求 | 拿什么 / 坑 |
|---|---|---|
| ① | `GET /WebPay/toRecharge?paytype=3&account=X&amount=Y` | `JSESSIONID` + 页面上的 `csrftoken` / `validCode` / `AJAXCSRFTOKEN`；**这一页的 URL 就是后面所有请求的 Referer** |
| ② | `POST /WebPay/submitRecharge`（form） | **必须带 Referer**，否则 `403 Illegal Referer`（实测踩过）；成功回 `302 Location: /WebPay/wxPaySaoma` |
| ③ | `GET /WebPay/wxPaySaoma` | **订单号只在这个页面里**（`#orderno` 隐藏域）；`Location` 本身不带订单号 —— 订单挂在 **`JSESSIONID` 会话**上 ⇒ 整条链必须共用一份 Cookie，且每次下单都从**干净会话**开始（否则「换个账号再充」会落到上一次的会话里） |
| ④ | `GET /WebPay/checkOrder?orderno=…&ajaxCsrfToken=…&t=…` | `{"result":1,"order":{"orderno":"…","paystate":"…"}}`；**`ajaxCsrfToken` 必带** —— `pub.js` 的 `$.ajaxSetup` 会给页面上每个 ajax 自动加它，手写请求漏了同样吃 403（实测踩过） |

**二维码 = 服务端生成的一张 jpg**：`GET /WebPay/resource/qrcode/<订单号>.jpg`
（实测约 11.8 KB、`image/jpeg`、**带不带 Referer 都能取**）⇒ App 侧**不需要二维码渲染库**，
`dio` 取 bytes + `Image.memory` 显示即可（口径 = `domain/net_fee_recharge.dart` 的 `netFeeQrCodeUrl`）。

**订单状态**（`paystate`）：`3` = 已支付（`wxpaySaoma.js` 判的就是这一位）；
未支付实测见过 `0`（刚下单）与 `9`（放了一小时的那张）。App 每 **3 秒**轮一次（与校方页面同频），
**10 分钟**没动静就停手并提示「订单可能已超时」。

**UI** = `presentation/net_fee_pay_screen.dart`（二级页、裸 AppBar）：进页即下单 → 金额大字 +
**二维码卡片**（白底，深色模式下也贴白）+ 订单号 + 「我已完成支付」（手动查一次）+
「刷新二维码」（重新下单）；查到达 `paystate=3` 切成功态，点「完成」返回并触发余额重取。
**下单失败**才在错误态下面给「改用校方网页支付」（内嵌兜底，见下）。

**真机验证**（0.01 元真实下单、**不付款**；跑的是 App 那份数据源代码）：
`dart run tools/_verify_native_pay.dart` →
`① 下单 → 订单号 …  ② 二维码 → 11708 字节（jpg 头 [255,216,255]）  ③ 轮询 paystate="0"  ④ 再轮询 "0"`。
⚠ 三轮实测共在校方计费系统里留下 4 张 **0.01 元未支付订单**（用户授权；不扣费、会自然过期）。

#### 不是给自己充 → 先确认（2026-10-09 六轮）

**用户原话**：「我希望不是给自己充值时，要弹提示」。

两条路**处理不同**（因为校方规则不同）：

| 情况 | 处理 |
|---|---|
| **微信** + 账号 ≠ 自己 | 弹确认框：「账号 X 不是你的上网账号（Y）…… 充值成功后这笔钱会进对方账号，**退不回来**」→ 确认了才下单 |
| **校园卡** + 账号 ≠ 自己 | **直接拦下**（校方写死「校园卡扣费只能给自己充值」），提示把账号改回来 |

配套还有一处面板修正：**切到校园卡时把账号还原成自己**（与小程序 `chargeTypeChange`
里 `t.account = this.data.currrentUsername` 同款）。少了这一步，用户「先改成别人的账号、
再切校园卡」会留下一个**锁着的别人账号** —— 比不锁更难查（输入框灰着，看不出里面是谁）。

「自己」的口径 = `summary.username`（校园网页第一段余额卡上那个账号）；
拿不到它（连门户兜底都没值）时**不弹确认** —— 判断不了就别拦。

守卫 = 「不是给自己充」组 4 例：切校园卡还原账号 / 微信给别人充先确认且**取消就一个接口都不发** /
确认后才下单 / 给自己充不弹。

#### 两种口径：按金额充 / **充到目标余额**（2026-10-09 五轮）

**用户原话**：「既可以选择充值金额，也可以选择一个目标金额，自动计算要充值的金额」。

面板顶部两个 chip：

| 口径 | 用户给什么 | 真正充多少 |
|---|---|---|
| **按金额充值**（默认） | 充多少钱（10 / **12.5** / 20 / 50 / 100 / 200 / 其他） | 就是这个数 |
| **充到目标余额** | 想让余额变成多少（20 / 50 / 100 / 200 / 其他） | **目标 − 当前余额**（面板里算，规整到分） |

- 目标模式下算式条写成「当前余额 12.5 元 → 目标 50 元，**还需充值 37.5 元**」——
  余额是页面传进来的**快照**，所以文案里必须把「当前余额」写出来，别让用户拿几分钟前的数字当准数。
- 目标 ≤ 当前余额 → 条子变红说「不需要充值」，提交也拦下（不是静默发 0 元）。
- **拿不到余额时目标模式整个不可选**（`onSelected: null`）—— 算了也不准，不如不给选。
- 只影响**输入口径**：`NetFeeRechargeRequest` 里始终只有最终金额，支付方式（微信 / 校园卡）
  与两条支付路径完全不受影响。
- 余额快照来自 `netFeeSummaryProvider`（校园网页第一段那张余额卡，同一个数）。

**守卫** = `test/net_fee_recharge_test.dart` 的「充到目标余额」组 4 例：
目标 50 + 余额 12.5 → 算出 37.5 且提交金额就是 37.5 / 目标不高于余额 → 说清「不需要充值」且不提交 /
拿不到余额 → chip 不可选 / 目标可自定义（60 − 12.5 = 47.5）。

#### 校园卡支付（第二种充值方式 · 2026-10-09 四轮）

**用户原话**：「支持使用校园卡充值网费，是网费充值中有一步选择充值方式」。

**侦察手法（这次靠解包，不是抓包）**：`tools/_wxapkg_unpack.py <版本>` 解 PC 微信里
**智慧江财主小程序**（`wx70c0beda0bb7b021`，本机缓存版本 **145**）的 wxapkg →
「网费充值」是它内部的页面（`pages/modules/developer/wfcz/recharge/view.js`）✅
（`tools/` 已 gitignore，脚本与产物都不入库。）

**从代码里读出来的口径**（`wfcz/recharge/view.js`）：

```js
data: { moneyRange:[50,100,150,200,300,360], choiceChargeType:"", payTypeList:[], chargeTypesUrl:{} }
submit()  → if (!choiceChargeType) 「请选择充值方式」           // ← 用户说的那一步
chargeTypeChange() → 非 weixin 时锁死账号：「校园卡扣费只能给自己充值」
getPayTypeList() → POST /interface/api/interface/getWfczPayType {pageNum,pageSize,accept}
   → {code:1, result:{result:{result:[{dict_key,dict_value,desc}]}}}
     **dict_value 就是该方式的充值接口地址**（别在客户端写死）
recharge(amount) → POST <chargeTypesUrl[choiceChargeType]> {username, openId, total_fee}
   weixin → 回微信支付参数（小程序走 wx.requestPayment）
   card   → 回 {code:0} 即「网费充值成功！」（**直接从校园卡余额扣**）
```

实测那份列表（只读接口，零风险）：

| key | url | desc |
|---|---|---|
| `weixin` | `…/1585799510593/pay/h5` | 微信支付 |
| **`card`** | `…/1585799510593/pay/cardPay` | **校园卡支付** |

**⚠ 两条路不是同一套系统**（这是最容易搞混的地方）：

| | 微信 | 校园卡 |
|---|---|---|
| 走哪 | Dr.COM `self.jxufe.cn`（本模块主路径：下单 → 二维码 → 轮询） | 小程序那套 `wxcourse.jxufe.cn/…/pay/cardPay` |
| 凭据 | 账号 + JSESSIONID | **`enc`（加密 userId）+ `openId`**（都从 `checkAppAuth` 拿） |

**App 侧实现**：
- `data/datasources/net_fee_remote_datasource.dart`：`fetchChargeTypes()`（解析三层嵌套）/

  `payByCampusCard({identity, amount, payUrl})`（返回 `null` = 成功，否则校方文案）。

  选校园卡时出红字警告（提交即扣 / 只能给自己充）。
- `presentation/net_fee_screen.dart`：`_payByCampusCard()` —— **二次确认对话框**
  （校方接口一提交就扣，面板里那段说明不算确认）→ 进度 SnackBar → 成功/失败 SnackBar → 刷新余额。

**⚠ 一个真 bug（测试逮到的）**：`openId` 是 base64 串、**含合法的 `+`**，而
`Uri.queryParameters` 是 form 语义会把它解成**空格**（实测 `OID+AB=` → `OID AB=`）→
必须从 `rawQuery` 正则取 + `Uri.decodeComponent`。解错了校方直接拒。

**守卫** = `test/net_fee_recharge_test.dart` 的「校园卡充值」组 6 例：

不能像微信那样用 0.01 元「下单不付款」来验。要验就得真花一笔钱（用户决定）。

#### 兜底路径（内嵌校方页）要处理的两个坑

以下都是**兜底路径**（`net_fee_pay_screen` 的下单失败分支 / 第二段「微信充值」）的事 ——
主路径走原生收银台，根本不碰网页。

**⚠ 校方页面有个真 bug：预填的档位金额会被打回 10 元（要注入修正）**

实测（2026-10-09 · headless 浏览器**渲染后 DOM** 对照，只读、未下单）：

| URL 里的 `amount` | PC 版页面最终 `amount` | 说明 |
|---|---|---|
| `50` / `100`（校方档位值） | **`10`** | 被页面自己打回第一档 |
| `30`（非档位值） | `30` | 走「其他」分支，反而正确 |

根因 = `recharge.js` 的 `initAmount` 分支里 **`flag` 写反了**：匹配到档位时置
`flag = false`，紧跟着的 `if (flag && !$("#tr_manualMoney").is(":hidden")) {…} else { $("#moneybut1").click(); }`
就落进 `else` → 金额被覆盖成 10 元。后果是**花钱的功能默认错**：用户以为充 50，页面停在 10。

**兜底路径的三条对策**：

1. `netFeeRechargePageScript({amount, submitToken})` —— 页面加载完后注入一次，做两件事：
   - **修金额**：借校方自己的 `changeMoney(<按值找到的档位 id>)` 纠正那个写反的分支；
   - **自动提交**：替用户点掉表单上那一次「立即支付」→ 3 秒后就是二维码页。
   带一次性 token 防重（`sessionStorage['dshSubmit:<token>']`）：脚本每次导航结束都会跑，
   用户点内嵌页的「上一页」退回表单时**不该再下一单**，而 token 由 App 每次「去支付」现生成，
   所以「关掉二维码页、重新来一次」仍会正常下单。纪律 = **幂等**、**无害**
   （`changeMoney` 不在 / 没有 `form` + `input[type=submit]` 就空转）、**不带凭据**。
   它经 `EmbeddedWebRequest.pageScript` 交给内嵌页 —— 内嵌件 2026-10-09 新增的**可选**能力，
   默认 `null` = 行为不变（见 **§40.8**）。
2. 面板上明说「打开后直接是微信收款二维码」+「扫码前请核对二维码上方的金额」——
   因为**走系统浏览器那条兜底路时注入不了**（那是浏览器的事）：既不修金额、也不会自动提交，
   用户得自己在页面上点一次「立即支付」。
3. 从二维码页返回时自动重取余额与记录（`PageAutoRefresher.didPopNext`，见下面「两个别以为」）。

**真机验证（2026-10-09 · Edge + CDP `Runtime.evaluate`，只读、未点「立即支付」）**：

|---|---|---|---|
| `50` | `'10'` ❌ | `'50'` ✅ | `50` |
| `100` | `'10'` ❌ | `'100'` ✅ | `100` |
| `30`（非档位） | `'30'` | `'30'`（脚本空转，未破坏） | — |
| `12.5`（非档位） | `'12.50'` | `'12.50'`（脚本空转） | — |

—— 一行是 bug、一行是补救、两行是「补救不会误伤」。探针：`tools/_webpay_inject_probe.py`
（`tools/` 已 gitignore，不入库）。

**端到端验证（2026-10-09 · 执行的就是 Dart 侧 `netFeeRechargePageScript` 的原文）**：

不付款、会自然过期）。

#### 手机端唤起微信支付（2026-10-09 五轮 · **主路径**的手机端形态）

**用户原话**：「我希望在手机端可以唤起微信支付」。
（桌面端仍是上一节那样显示二维码 —— 电脑上没有 `weixin://` 的接收方。）

**关键发现**：校方那张二维码的**内容**就是微信 Native 支付的 code_url ——
把真机那张图解出来得到 `weixin://wxpay/bizpayurl?pr=<token>`。手机上没有第二台设备可扫，
但这个 scheme 本来就能被系统直接打开 → 微信弹出确认付款页。
**服务端不暴露这个链接**：`checkOrder` 只回 `{orderno, paystate}`，另试 7 个可能的 JSON
路径（`getQrCode` / `qrCode` / `getOrder` / `queryOrder` / `payUrl` / `getPayUrl` /
`wxPaySaoma?orderno=`）**全是 404** ⇒ 只能在 App 本地解码。

**实现三件**：

1. `data/qr_pay_url.dart` 的 `decodeWeChatPayUrl(bytes)` —— `image` 解像素 → `zxing2`
   （纯 Dart 的 ZXing 移植，**本轮新增依赖**，配 `image` 用）读二维码。
   **失败一律返回 `null`**：二维码解不出来不该让整笔充值走不下去。
2. `presentation/net_fee_pay_screen.dart` —— 手机（Android / iOS）进页**自动唤起一次**微信，
   另给一个「打开微信支付」按钮；**二维码降为兜底**（小一号 + 「也可以让另一台设备扫这个码」）。
   桌面端不变（没有 `weixin://` 的接收方，照旧显示二维码让人扫）。
3. `android/app/src/main/AndroidManifest.xml` 的 `<queries>` **必须加微信**
   （`<package android:name="com.tencent.mm"/>` + `weixin` scheme 的 intent）：
   Android 11+（API 30）默认对其它应用不可见，不加就是唤起失败。

**两个实测坑（都会让「唤起」静默失效）**：

- ⚠ **`image` 解 1-bit / 调色板 PNG 时通道值没缩放到 0–255**（给的是 0/1）→ zxing2 看到
  一张全黑图 → `ReaderException`。修法 = 取像素前 `convert(numChannels: 3)`。
  同一张码：**1-bit PNG 解不出来**，RGB PNG / 灰度 PNG / jpg 都能解（校方现在给的是 jpg，
  这条加固是防它哪天换 PNG）。
- ⚠ **`img.decodeImage` 对垃圾字节是抛异常、不是返回 `null`**（喂 3 个字节就炸）→
  必须 try/catch，否则一张坏图能把整笔充值卡死。

**平台分支** = `inAppWeChatPaySupported(platformName)`（android / ios）+
`inAppWeChatPaySupportedProvider`（测试 override 它就能分别覆盖两端）。

**守卫** = `test/net_fee_recharge_test.dart` 的「手机端唤起微信支付」组 5 例：
解码器解出 `weixin://`（fixture = cv2 现生成的 1-bit PNG、334 字节，**不是真机那张** ——
一次性支付 token 不入库，§34）/ 解不出返回 `null` 不抛（空白图 / 垃圾字节 / 空字节）/
手机端进页自动唤起且二维码仍在 / 桌面端不唤起 / 唤起失败给提示但付款路径不断 /
二维码解不出时按钮禁用。

**实现（全部落在 `features/net_fee/`，刻意不碰 `network_service`）**：

- `domain/net_fee_recharge.dart`：`kNetFeeWebPayOrigin` / `kNetFeeWebPayType` / `kNetFeeWebPayPath` /
  `kNetFeeRechargeQuickAmounts`（10/**12.5**/20/50/100/200）/ `kNetFeeRechargeTargetAmounts`
  （20/50/100/200，「充到目标余额」用）/ `netFeeRechargeUrl` / `netFeeNormalizeAmount` /
  `netFeeRechargeAccountError`（照抄校方 `/^[\w@\.\-\$]{1,30}$/`）/ `netFeeRechargeAmountError` /
  `NetFeeRechargeRequest`（`toString` **只报金额与方式**）/ `NetFeeOrder` / `kNetFeePayStatePaid` /
  `netFeeQrCodeUrl` / `NetFeeChargeKind`（微信 / 校园卡）/ `WfczChargeType` / `WfczIdentity` /
  `netFeeRechargePageScript`（兜底路径用）。
- `data/datasources/net_fee_recharge_remote_datasource.dart`：**原生链路唯一实现** ——
  `createOrder`（四步里的 ①②③）/ `fetchQrImage`（取那张 jpg）/ `fetchPayState`（④ 轮询）。
  会话用 `HostCookieJar` 按 `self.jxufe.cn` 单域分桶，**每次下单从干净会话开始**。
- `data/qr_pay_url.dart`：`decodeWeChatPayUrl(bytes)` —— 把二维码 jpg 解成
  `weixin://wxpay/bizpayurl?pr=…`（手机端唤起微信用；失败返回 `null`）。
  依赖 `zxing2`（纯 Dart ZXing）+ `image`；Android 侧另需 manifest 的 `<queries>` 加微信。
- `presentation/net_fee_recharge_sheet.dart`：`showNetFeeRechargeSheet(context, {account, balance})`
  → 返回 `NetFeeRechargeRequest?`（`null` = 取消）。**面板只收集输入、不发任何请求**；
  默认选第一档（与校方 `#moneybut1.click()` 同款），主按钮把金额写出来（「扫码支付 ¥50」）；
  金额下面还有一节「充值方式」（微信 / 校园卡，见上一节）。
- `presentation/net_fee_pay_screen.dart`：**App 原生收银台**（二级页、裸 AppBar）——
  进页即下单 → 金额大字 + 二维码卡片（`Image.memory`，白底）+ 订单号 + 状态说明，
  每 3 秒轮询 `checkOrder`（上限 10 分钟），查到 `paystate=3` 切成功态；
  下单失败才给「改用校方网页支付」。
- `presentation/net_fee_screen.dart`：余额卡底部那行右侧「充值」按钮（`Key('netfee_recharge')`，
  账号为空时**禁用**）→ `_startRecharge` → 面板 → **push 收银台**。
- 兜底路径（内嵌校方页）的两条出路都**不必自己写**：内嵌页导航栏自带「用系统浏览器打开」
  （`inAppWebExternal`），非内嵌平台（macos / linux / web）直接走系统浏览器。

**两个「别以为」**：

- ⚠ **不要为了复用去让 `network_service` import `net_fee`**：第二段那个「微信充值」条目
  （`Key('netsvc_wechat_recharge')`）**保持不动**（它走的是不带金额预填的 `recharge` 入口）。
  原因是依赖方向：`net_fee → network_service` 已经存在（校园网页自己拼第二段），反向再加一条
  就多一个 feature 双向环，而 `core_conventions_test.dart` 的 `maxFeatureCycles = 9` 是**只减不增**的棘轮。
- ⚠ **关掉充值面板本身也会触发一次余额刷新**：`ModalBottomSheetRoute` 被 pop 时
  `appRouteObserver` 同样发 `didPopNext`（守卫量到取数量 1 → 2）。这一次数**有意留下**
  （用户刚离开余额卡，支付前后本来就该看到新值），所以 `_startRecharge` 里**不再**手动
  `invalidate` —— 两条路都留着才是真的重复取数。
