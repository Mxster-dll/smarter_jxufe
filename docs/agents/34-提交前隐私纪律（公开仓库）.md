## 34.1 一分钟版（每次提交前）

```powershell
# 0) 新克隆第一次：启用钩子（钩子文件入库，但 core.hooksPath 是本地配置，不随克隆走）
git config core.hooksPath .githooks

# 1) 守卫测试必须绿（~30 秒；闸门本体，兜底一切形状与已登记的人名/地址）
$env:FLUTTER_ROOT='<FLUTTER_ROOT>'; $env:FLUTTER_SUPPRESS_ANALYTICS='true';
$env:FLUTTER_ALREADY_LOCKED='true'
$dart = "$env:FLUTTER_ROOT\bin\cache\dart-sdk\bin\dart.exe"
$snap = "$env:FLUTTER_ROOT\bin\cache\flutter_tools.snapshot"
Remove-Item build\unit_test_assets -Recurse -Force -EA SilentlyContinue   # 非幂等拷贝 errno 183
& $dart $snap test test\privacy_guard_test.dart

# 2) 眼睛过一遍本次范围（有没有 app_data/、*.hive、抓包、脚本、密钥）
git status --porcelain
git diff --cached --stat

# 3) 提交（装了钩子的话，1 与 2 的机械部分已经自动跑过）
```

⚠ 跑守卫测试前**先停掉运行中的 `flutter run`**（争构建目录会挂死到超时；钩子里遇到超时是「跳过并提醒」而不是「拦住提交」，见 §34.6）。

## 34.4 写代码 / 写测试时用什么值（合成值口径）

**把真实值换成下面这套**（2026-09-21 清洗用的映射，照抄即可）：

| 类别 | 合成值 |
|---|---|

| 学号 | `2202500001` … `2202500008`、`2202400001`、`2202300001` |
| 学籍号（`2016xxxxxxxx` 形状） | `201600000000` / `201600000001` / `201600000002` |
| 身份证 | `110101200001010010`（**校验位合法**，所以看起来像真的） |
| 手机号 | `13800000001` / `13800000002` / `13800000003` |
| 家庭住址 | `江西省南昌市示例区示例路1号示例小区1栋101室` |
| 宿舍地址 | `麦庐园校区示例宿舍楼1楼101室`；中学 `示例市示例中学` |
| 考生号 / 通知书号 | `25360000000001` / `202510000P0000` |
| 口令 | `Test123`（**刻意与原值等长**：`test/network_service_data_test.dart` 的 `networkMaskPassword` 断的是 `'*******'`）/ `Test123456` |
| CAS 票据 / 会话 | `<REDACTED>`（`TGT-…`、`ST-…`、`SESSION=…`、`JSESSIONID=…`） |
| 32 位令牌 | `0123456789ABCDEF0123456789ABCDEF`（**保持 32 位十六进制**，`maskImsToken` 断的是前 8 位 `01234567`） |
| 平台令牌 | `TESTOPENID` / `TESTSESSIONTOKEN…` / `TESTVISITORID…` |

三条硬口径：

1. **别把抓包整段粘成 fixture** —— 要么精简到最小报文，要么把值换掉。这是 2026-09-21 那轮泄漏的**唯一入口**。
2. **改测试输入要重算派生期望** —— `test/course_selection_des_test.dart` 的 DES 对拍值是**按学号算出来的**，换输入后必须按同一实现重算期望值（该文件顶部有「脱敏说明」注释）。
3. **换值要连派生字面量一起换** —— 掩码 / 截断展示是**独立字面量**：`110****0010`（= `substring(0,3) + '****' + substring(len-4)` 的结果）、`01234567`（IMS 令牌前 8 位，`maskImsToken` 断的就是它）都要同步，否则「值换了、掩码还留着」= 影子泄漏。

## 34.5 守卫测试怎么工作（`test/privacy_guard_test.dart`）

- **判据 ① 结构类**（形状 + 白名单）：身份证 / 手机号 / CAS 票据（`TGT-`·`ST-`）/ 会话（`SESSION=`·`JSESSIONID=`）/ 平台令牌（`openId=`·`cardinfo=`）/ 学籍号（`2016\d{8}`）/ 学号（`2\d{9}`）/ 考生号 / 通知书号 / MAC。白名单里**只放合成值与公开的班级编号**（`2503010011`、`2508090211`）。
- **判据 ② 自由文本类**（加盐 SHA-256 摘要黑名单，不落明文）：真人姓名（2~4 字 CJK 词的滑动窗口）+ 真实地址（8 字 CJK 窗口）。其中有两个**与常用词同形**的两字姓名单独放在 `_nameStandaloneDigests`（本册刻意不把它们写出来 —— 写出来就会被自己绊住，实测踩过一次）：只在**贴到中文串边缘**时才算命中，否则「任何东西」「课程进行」这类普通词会被误报成姓名。
- **⚠ 盐不入库（2026-10-11 · 用户裁定「换」）**：盐从环境变量 **`PRIVACY_GUARD_SALT`** 读，仓库里只有 176 条加盐 SHA-256 摘要。
  - **本机设一次**：`setx PRIVACY_GUARD_SALT <盐>`（新开的终端才带上；agent 的每条命令前 `$env:PRIVACY_GUARD_SALT='<盐>'`）。盐的落盘位置在**仓库外**（原 `%TEMP%\gitgrp\guard_salt.txt`）。
  - **没设盐时**：姓名 / 地址两条判据**显式跳过**（用例名里带「跳过：未设置 PRIVACY_GUARD_SALT」，钩子另外打一行 ⚠），形状类判据不受影响。**为什么不像以前那样把盐写在文件里**：盐公开 = 摘要表可被暴力反推（2 字姓名尤其便宜）。
  - **换盐 = 整表重算**：摘要与盐必须配套，改一个就得让另一个跟着变（生成脚本在仓库外，会读 `desensitize.MAPPING` / `namemap.NAME_MAP` / `history_scan_out.txt` 三份含明文的口径）。⚠ **历史里也必须一起换**（本轮就是这么做的：把旧盐算出的 176 条摘要 → 新盐的，用 filter-repo 的 blob 回调全历史替换），否则「文件里是新盐、历史里是旧盐」等于旧盐还公开着。
- **判据 ③ 本机路径痕迹（2026-10-11 立 · 用户「本机痕迹也洗一下」）**：只认**本机那几个根** —— `[A-Za-z]:\\(Users|Project|Temp|Tmp|Program|Keys)\\`；公开仓库只写占位符 / 环境变量（`<仓库根>` / `<FLUTTER_ROOT>` / `<PYTHON>` / `%TEMP%` / `%USERPROFILE%` / `$env:FLUTTER_ROOT`），白名单只有合成测试值 `C:\Temp\`。**不碰** `C:\Windows\…`、URL 尾巴、测试里编的 `D:\pic\…`。落地时一并跳过了三类**不入库**的「含本机路径」文件：`.idea/`（`Dart_SDK.xml`）、`.vscode/`、`ios/Flutter/Generated.xcconfig` 与 `flutter_export_environment.sh`。
- **判据 ④ 提交信息类（2026-10-11 加）**：`git log --all` 的**全部 message** 跑上面同一套判据。**为什么必须单列**：守卫读工作树、钩子只看 index —— **没有任何一层看提交信息**，而 message 随 push **永久公开**。实测这条判据一次报出 4 条 message 的问题（两个两字真人姓名、真机设备序列号、四条令牌/指纹前 8 位 + 第三方密钥前 9 位、一个形状正好是学号的 10 位数字），**这 4 条已按 §34.4 口径改写**。⚠ 它同样管**写 message 的人**：本轮自己的提交信息里引了一次「以 2 开头的 10 位整数」就被打红，只能 amend。
- **判据 ⑤ 抓包凭据（2026-09-21 第 4 轮加 · 2026-10-11 修）**：`sessionToken` / `fpVisitorId` / CAS `execution`。⚠ **判据不要假定两侧引号**：同一个 execution 令牌在抓包整页里是 `value="…"`、在**源码**里却是 `const execution = '…'`（单引号）—— 只认双引号的那版把 `auth_remote_datasource.dart` 的历史 8 个 blob 全放过去了；现在只看**令牌本体**（`<uuid>_<base64>`，长度 ≥100）。
- **扫描范围** = **仓库根递归**（`.`，含 `AGENTS.md` / `README.md` / `TODO.md` 等常驻文档与各平台目录 `android/ ios/ macos/ linux/ windows/ web/`）+ `lib/ test/ docs/ reverse_engineering/ tool/ packaging/`（与 `.` 重叠，按路径去重）。
  - ✅ **2026-10-11 已落地**：此前 `_roots` 只有那 6 个子目录，**根上文件与各平台目录一个都不扫**（补上 `.` 后守卫立刻报出根上 `dorm_sheet_*.json|txt` 的真名）。现在实测扫到 **约 1420 个文件 / 全程约 9 秒**，规模写在那条用例名里。
  - 取文件是**后缀白名单**（`.dart .md .txt .json .yaml .yml .http .kt .kts .java .swift .xml .html .properties .plist .gradle .py .sh .bat .ps1 .cc .cpp .h .cmake .iss .css .js .ts .svg .toml .ini .xcconfig .entitlements .rc`）：二进制天然排除，新后缀不会因为「忘了加进黑名单」而静默漏扫；顺带躲掉 `pubspec.lock` 的 10 位数字与 `.pbxproj` 的 32 位整型极值两类误报。
  - **递归时边走边剪枝**：命中跳过表的目录**不再往下走**（否则会白枚举 `build/` 与 `.probe/` 里几万个文件）。
  - **跳过表 `_skipPaths` 按「仓库根相对路径」锚定**，不是裸目录名 —— 裸名 `app_data` 会连 `lib/features/*/app_data/` 这种同名**源码目录**一起误跳。三类：以 `/` 结尾跳整棵子树、含 `*` 按文件名匹配、其余精确匹配。
  - **扫描面契约用例**（把范围钉死，别再退化）：断言「必须扫到」的代表文件真在集合里（`AGENTS.md` / `README.md` / `CLAUDE.md` / `android/app/build.gradle.kts` / `windows/runner/window_chrome.cpp` / `assets/rules/meta/rules_catalog.json` / `lib/main.dart`），并断言本地数据与误报源**不在**（`dorm_sheet_*`、`tmp.txt`、`sensitive.txt`、`pubspec.lock`、`android/build/…problems-report.html`）。反向验证过：往**仓库根**放探针 `.md`（证件号 / 手机号 / 学号三种形状）→ 守卫逐条指名报出。
  - 为什么要跳构建产物：Gradle 的 `problems-report.html` 里含 Java 的 32 位整型极值 → 被「学号 `2\d{9}`」误报。⚠ **推论：这条判据对"以 2 开头的 10 位整数"普遍误报**，故引用这类数值时不要照抄字面量。
  - **唯一的豁免是守卫自己**（白名单与摘要表里必然写着反面样本）。
- **⚠ 豁免已清零（2026-10-11）**：原先放行 `lib/features/qr_login/data/datasources/wechat_login_remote_datasource.dart`（联邦登录 URL 里写死一个 32 位 `sessionToken`）。复核确认那条 URL 是**死代码** —— 请求查询串由相邻 `data:` 字典里的同名参数生成，写死的字面量从未被使用 —— 已删除该字面量并把该文件纳入管控。**现在全仓没有任何豁免文件**；反向验证过一次：把该形状写回该文件，守卫指名报出（`wechat_login_remote_datasource.dart:122`）。
- **新增真实值怎么加**：跑仓库外的生成脚本重新生成摘要表（脚本**不入库**，因为它含明文；路径见本册 §34.3「含明文的脱敏脚本」一栏）。
- **改了守卫要反向验证一次**：临时把某个真实值写进任意文件 → 守卫必须指名报出（2026-09-21 立档时对证件号 / 手机 / TGT 三条各做过一次；2026-10-11 又对「提交信息」与「仓库根扫描面」各做一次）。

## 34.6 提交钩子 `.githooks/pre-commit`

- **启用**：`git config core.hooksPath .githooks`（**每个新克隆都要跑一次**；仓库里没有 Husky 之类的自动安装，且本仓无 CI）。
- **两层**：① 文件名 / 后缀机械检查（零依赖、秒级）；② 跑 `test/privacy_guard_test.dart`（2026-10-11 起扫描面扩到仓库根，实测**约 10 秒**；需要 `dart` + `flutter_tools.snapshot`，找不到就**只做 ①** 并提示）。
  - ① 的清单（2026-10-11 补）：`app_data/`、`.env*`、`*.hive|mitm|flows|pcap|pcapng|har|jks|keystore|p12|pfx|mobileprovision|pem|key`、`key.properties`、`secret(s).{json,yaml,yml,txt}`、**`tmp.txt` / `sensitive.txt`**（根上那两个含明文的脱敏规则/口令文件 —— 此前只靠 `.gitignore` 保命，现在文件名层也拦一道）、`_rel_scan.py` / `_rel_scrub.py` / `_scrub_rules*.txt` / `gen_guard.py` / `desensitize.py` / `replace_text.txt` / `replace_message.txt`、`*/captures?/`。
  - ⚠ **本机启用状态（2026-10-11）**：`git config core.hooksPath .githooks` **已执行**；端到端验证过 —— 正常提交打印「隐私闸门通过（文件名检查 + 守卫测试）」；`git add -f sensitive.txt` 后钩子立刻拦下（exit 1）。未设 `PRIVACY_GUARD_SALT` 时钩子会多打一行 ⚠（姓名/地址判据被跳过）。
- **逃生口**（都在输出里写明）：
  - `SKIP_PRIVACY_GUARD=1 git commit …` = 跳过 ②，① 仍生效（**默认口径**：确实知道为什么才用）；
  - `git commit --no-verify` = 全跳过。

  ⚠ 钩子的取舍：② 红了**一定拦**（那就是闸门）；但「跑不起来」（找不到 dart / 300 秒超时，多半是与运行中的 `flutter run` 争构建目录）**只提示不拦** —— 否则一次环境抖动就能把人挡在提交之外，纪律迟早被 `--no-verify` 绕过。
- **钩子的盲区（必须知道）**：它扫的是**工作树**（守卫测试读文件系统），不是 index —— 若「工作树里已改好、index 里还留着旧值」（部分暂存），钩子看的是改好的那份。所以 §34.1 的 `git status` / `git diff --cached --stat` 仍然要做。
- 钩子文件**必须入库且带可执行位**（`git update-index --chmod=+x .githooks/pre-commit`；Windows 上本机无所谓，但 Linux/macOS 克隆要靠它）。

## 34.7 真的泄漏了怎么办（止血顺序，别跳步）

1. **先改口令**（最高优先）：泄漏的口令比什么都急；CAS 密码没见到明文，但**票据泄漏 = 有效期内可被冒用**。
2. **工作树脱敏补丁**（本轮做法：显式映射表逐个值替换，保持 LF、保持长度，见 §34.4）→ 提交 → 推送。这一步**不能**撤下已公开的数据，只是止血。
3. **历史改写**：`git filter-repo --replace-text <规则文件> --replace-message <规则文件> --force`。五个坑：
   - 仓库里若留有 `.git/filter-repo/already_ran`（上一次改写留下的），它会弹**交互式 continuation 提示** → 无 stdin 时 `EOFError` → 先把它移走；
   - 不加 `--force` 会报 `Refusing to destructively overwrite repo history since this does not look like a fresh clone`；
   - 它**会删掉 `origin`** → 跑完要 `git remote add origin …`；
   - 正则按 **bytes** 编译：`\u4e00` 直接报 `re.PatternError: bad escape \u` → 汉字边界写成 `(?<![\x80-\xbf])名(?![\x80-\xbf])`。
   - ⚠⚠ **`--replace-text` 规则文件里字符串含 `#` 会毁掉整个仓库**（2026-10-10 实测踩爆）：
     规则文件用 `#` 当注释符，而 `X#Y==>Z` 这行会被解析成「把 `X#` 换成 `Z`」**外加**把单独的
     `#` 换成 `Z` —— 结果是**全仓 476 个文件里的注释符 `#` 全被替换**（Markdown 标题、Python/Dart/YAML
     注释集体阵亡），只能从 bundle 回滚重来。含 `#` 的字面量写成 `regex:X[#]Y==>Z`，
     或干脆**改用回调脚本**：`--blob-callback` / `--message-callback` / `--filename-callback`
     （回调是普通 Python，没有规则文件那层语法；本轮最终就是用它跑通的，
     见 `.scratch/ff_callbacks.py`，另配 21 项自测先证明「只换真值、不碰其它字节」）。
     回调签名：`blob(obj, meta)` 改 `obj.data`、`message(bytes, meta)` 收**bytes**、
     `filename(name)` 返回 `None` 即删该文件。
   - **改写会硬重置工作树** → 未提交的改动会被丢掉，动手前务必 `git diff > wip.patch` 并对每个文件
     留一份**原始字节**副本（`.bak` 风格备份要带全角/中文名时别用 PowerShell 通配，会静默漏）。
    - ⚠⚠ **「先冻 WIP」的那次提交本身可能被钩子拦下**（2026-10-11 实测踩爆）：钩子跑守卫 → 守卫正因**你这次要洗的东西**而红（本轮是两条 message 里的本机路径）→ 提交失败；而 `filter-repo --force` **会跳过它的全部前置检查**（源码里那句 `sanity_check` 只在 `not force and not already_ran` 时才跑）→ 它照样在**脏工作树**上开工，收尾的 `reset --hard` 把未提交改动**全冲掉**（本轮丢了 46 个文件的清洗与盐轮换，靠备份 + 重做救回）。**正确顺序**：`SKIP_PRIVACY_GUARD=1 git commit -m TEMP…` 冻住 → `git status --porcelain` **必须为空** → 再跑 filter-repo → `git reset --soft HEAD~1 && git reset` 还原。
4. **强推 + 验收**：`git push --force-with-lease origin main`（9 个本地分支与 tag 都要覆盖），然后 `git log --all -S'<敏感串>'` 必须为 0；再用 `filter-repo` 之外的独立脚本全历史扫一遍（本轮的 `verify_rewrite.py`：2756 个文本 blob，IDCARD / TGT / ST / SESSION_UUID / JSESSIONID_LONG / OPENID / CARDINFO **全 0**）。
   ⚠ 验收**必须包含一条「没被误伤」的对照**：本轮用「含 `#` 的文件数」当基线（改写前 476 → 改写后仍 476）。只查「真值没了」会漏掉「顺手把全仓搞坏了」。
5. **改写 ≠ 彻底清除**：GitHub 会保留不可达对象，旧 SHA 仍能取到内容（实测 `contents/test/network_service_data_test.dart?ref=ef8038b…` 仍回清洗前的真实口令与真证件号；`commits/81ea406a…` 仍 200）。**唯一彻底办法 = 删除并重建同名仓库**（账号权限动作），重建后 `git push -u origin main --tags` + 覆盖其余分支。
6. **动手前先备份**：`git bundle create --all <备份>.bundle` + 一份 mirror clone（本轮备份在 `%TEMP%\backup\`）。

## 34.9 第三方平台密钥（不是「个人信息」，同样不许入库）

2026-10-10 补。区别于上面几类：这里防的不是**谁的隐私**，而是**别把第三方的密钥
随公开仓库发出去**（对平台是风险，对仓库是「这不专业」）。

| 类别 | 例子 | 怎么落盘 |
|---|---|---|
| 第三方平台签名密钥 | 小程序校历/请假的 bn 签名 `appSecret` | **构建参数注入**：`--dart-define=BN_APP_SECRET=…`，或 `--dart-define-from-file=config.local.json`（该文件已 gitignore，模板 `config.local.example.json` 只有键名） |
| 本机发布令牌 | GitHub release token | 运行时从 `git credential` 读（`packaging/publish_release.py`），不落盘 |

三条口径：

1. **读法固定为 `String.fromEnvironment`**（先例：`lib/core/network/debug_proxy.dart` 的
   `FIDDLER_PROXY`）：值只存在于构建参数里，代码里留的是**键名**。缺值时**要能优雅降级**
   —— 校历/请假的例子是回退内置快照 + UI 明说「未内置平台密钥」，而不是崩溃或静默发假签名。
2. **别想用「仓库内的密文文件」绕过**：`repo_hygiene_test` 明令 `.gitignore` 不得吞掉
   `lib/` 下的源码（2026-09-27 被裸 `tools/` 规则坑过），所以密文放不进 `lib/`；
   放在仓库根又等于「一个没被扫描面覆盖的新文件类型」。**仓库外**才是它的位置。
3. **把「算法」与「密钥」分开钉**：算法用**合成密钥**做金标准向量测（本轮
   `test/wxcal_bn_sign_test.dart`，独立实现算出 `E7EA4B…`），密钥本身永不入库 ——
   这样重构签名器时仍有回归网，又不牺牲秘密。

## 34.10 已知边界（写清楚，免得被当成「已经安全」）

- 守卫只覆盖**已登记**的值：新出现的真人姓名 / 新地址要跑 `gen_guard.py` 补摘要，否则**不会**被拦住。
