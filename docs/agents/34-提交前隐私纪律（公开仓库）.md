# 34. 提交前隐私纪律（公开仓库）

> 2026-09-22 立。用户原话：「我希望这是一个公共仓库，暂时还没人看，但是我希望当我开始宣传之前，
> 项目里不要有可以看到的隐私信息」+「写下来1-3并执行4」（1 = AGENTS.md 常驻一条；2 = 本册；
> 3 = `packaging/RELEASE.md` 改成先跑守卫；4 = 入库 `.githooks/pre-commit`）。
>
> 为什么纪律必须挂在「提交」这个动作上：2026-09-21 那轮清洗查明，泄漏**不是配置失误**，而是写测试 /
> 写逆向笔记时把**真机抓包整段粘进来**了 —— `test/network_service_data_test.dart` 的
> `const String _dashboardHtml`（校园网门户整页 `window.user = {...}`，带 `userPassword` /
> `userIdNumber` / `macAddress`）与 `test/my_mail_test.dart` 的回包（`"pwd":"…"`）都是这么进来的。
> 靠记性拦不住，得靠钩子与守卫测试。

## 34.1 一分钟版（每次提交前）

```powershell
# 0) 新克隆第一次：启用钩子（钩子文件入库，但 core.hooksPath 是本地配置，不随克隆走）
git config core.hooksPath .githooks

# 1) 守卫测试必须绿（~30 秒；闸门本体，兜底一切形状与已登记的人名/地址）
$env:FLUTTER_ROOT='<FLUTTER_ROOT>'; $env:FLUTTER_SUPPRESS_ANALYTICS='true';
$env:FLUTTER_ALREADY_LOCKED='true'
$dart = "$env:FLUTTER_ROOT\bin\cache\dart-sdk\bin\dart.exe"
$snap = "$env:FLUTTER_ROOT\bin\cache\flutter_tools.snapshot"
Remove-Item build\unit_test_assets -Recurse -Force -EA SilentlyContinue   # 非幂等拷贝 errno 183
& $dart $snap test test\privacy_guard_test.dart

# 2) 眼睛过一遍本次范围（有没有 app_data/、*.hive、抓包、脚本、密钥）
git status --porcelain
git diff --cached --stat

# 3) 提交（装了钩子的话，1 与 2 的机械部分已经自动跑过）
```

⚠ 跑守卫测试前**先停掉运行中的 `flutter run`**（争构建目录会挂死到超时；钩子里遇到超时是「跳过并提醒」而不是「拦住提交」，见 §34.6）。

| 层 | 位置 | 拦什么 | 何时生效 |

**不要**把 ④ 当成唯一关口 —— 它只在发版时跑，而提交是每天都在发生的事。

## 34.4 写代码 / 写测试时用什么值（合成值口径）

**把真实值换成下面这套**（2026-09-21 清洗用的映射，照抄即可）：

| 类别 | 合成值 |
|---|---|
| 真人姓名 | `同学甲` / `同学乙` / `同学丙` / `同学丁` / `同学戊` / `同学己`；教师 `教师甲` / `教师乙`；留学生 `留学生甲`；脱敏姓名 `甲**` |
| 学号 | `2202500001` … `2202500008`、`2202400001`、`2202300001` |
| 学籍号（`2016xxxxxxxx` 形状） | `201600000000` / `201600000001` / `201600000002` |
| 身份证 | `110101200001010010`（**校验位合法**，所以看起来像真的） |
| 手机号 | `13800000001` / `13800000002` / `13800000003` |
| 家庭住址 | `江西省南昌市示例区示例路1号示例小区1栋101室` |
| 宿舍地址 | `麦庐园校区示例宿舍楼1楼101室`；中学 `示例市示例中学` |
| 考生号 / 通知书号 | `25360000000001` / `202510000P0000` |
| 口令 | `Test123`（**刻意与原值等长**：`test/network_service_data_test.dart` 的 `networkMaskPassword` 断的是 `'*******'`）/ `Test123456` |
| CAS 票据 / 会话 | `<REDACTED>`（`TGT-…`、`ST-…`、`SESSION=…`、`JSESSIONID=…`） |
| 32 位令牌 | `0123456789ABCDEF0123456789ABCDEF`（**保持 32 位十六进制**，`maskImsToken` 断的是前 8 位 `01234567`） |
| 平台令牌 | `TESTOPENID` / `TESTSESSIONTOKEN…` / `TESTVISITORID…` |

三条硬口径：

1. **别把抓包整段粘成 fixture** —— 要么精简到最小报文，要么把值换掉。这是 2026-09-21 那轮泄漏的**唯一入口**。
2. **改测试输入要重算派生期望** —— `test/course_selection_des_test.dart` 的 DES 对拍值是**按学号算出来的**，换输入后必须按同一实现重算期望值（该文件顶部有「脱敏说明」注释）。
3. **换值要连派生字面量一起换** —— 掩码 / 截断展示是**独立字面量**：`110****0010`（= `substring(0,3) + '****' + substring(len-4)` 的结果）、`01234567`（IMS 令牌前 8 位，`maskImsToken` 断的就是它）都要同步，否则「值换了、掩码还留着」= 影子泄漏。

## 34.5 守卫测试怎么工作（`test/privacy_guard_test.dart`）

- **判据 ① 结构类**（形状 + 白名单）：身份证 / 手机号 / CAS 票据（`TGT-`·`ST-`）/ 会话（`SESSION=`·`JSESSIONID=`）/ 平台令牌（`openId=`·`cardinfo=`）/ 学籍号（`2016\d{8}`）/ 学号（`2\d{9}`）/ 考生号 / 通知书号 / MAC。白名单里**只放合成值与公开的班级编号**（`2503010011`、`2508090211`）。
- **判据 ② 自由文本类**（加盐 SHA-256 摘要黑名单，不落明文）：真人姓名（2~4 字 CJK 词的滑动窗口）+ 真实地址（8 字 CJK 窗口）。其中有两个**与常用词同形**的两字姓名单独放在 `_nameStandaloneDigests`（本册刻意不把它们写出来 —— 写出来就会被自己绊住，实测踩过一次）：只在**贴到中文串边缘**时才算命中，否则「任何东西」「课程进行」这类普通词会被误报成姓名。
- **扫描范围** = `lib/ test/ docs/ reverse_engineering/ tool/ packaging/`；跳过 `.git / build / .dart_tool / app_data / failures` 与二进制后缀；**守卫自己豁免**（白名单与摘要表里必然写着反面样本）。
- **唯一豁免文件** = `lib/features/qr_login/data/datasources/wechat_login_remote_datasource.dart` —— 那里的 `sessionToken` 是学校联邦登录 URL 的**功能常量**（非个人信息），动它会打断微信登录；已单独报给项目所有者，**不在守卫里静默改**。
- **⚠ 盐写在文件里 ⇒ 它是「绊线」不是「保密手段」**（摘要可被暴力反推）。之所以仍这么做：这些值在改写前的公开历史里本来就存在过，绊线的价值是**防止再写回来**。要更严就把盐换成 CI secret / 读环境变量。
- **新增真实值怎么加**：跑 `python %TEMP%\gitgrp\gen_guard.py` 重新生成摘要表（脚本**不入库**，因为它含明文）。
- **改了守卫要反向验证一次**：临时把某个真实值写进任意文件 → 守卫必须指名报出（2026-09-21 立档时对证件号 / 手机 / TGT 三条各做过一次）。

## 34.6 提交钩子 `.githooks/pre-commit`

- **启用**：`git config core.hooksPath .githooks`（**每个新克隆都要跑一次**；仓库里没有 Husky 之类的自动安装，且本仓无 CI）。
- **两层**：① 文件名 / 后缀机械检查（零依赖、秒级）；② 跑 `test/privacy_guard_test.dart`（~30 秒，需要 `dart` + `flutter_tools.snapshot`；找不到就**只做 ①** 并提示）。
- **逃生口**（都在输出里写明）：
  - `SKIP_PRIVACY_GUARD=1 git commit …` = 跳过 ②，① 仍生效（**默认口径**：确实知道为什么才用）；
  - `git commit --no-verify` = 全跳过。

  ⚠ 钩子的取舍：② 红了**一定拦**（那就是闸门）；但「跑不起来」（找不到 dart / 300 秒超时，多半是与运行中的 `flutter run` 争构建目录）**只提示不拦** —— 否则一次环境抖动就能把人挡在提交之外，纪律迟早被 `--no-verify` 绕过。
- **钩子的盲区（必须知道）**：它扫的是**工作树**（守卫测试读文件系统），不是 index —— 若「工作树里已改好、index 里还留着旧值」（部分暂存），钩子看的是改好的那份。所以 §34.1 的 `git status` / `git diff --cached --stat` 仍然要做。
- 钩子文件**必须入库且带可执行位**（`git update-index --chmod=+x .githooks/pre-commit`；Windows 上本机无所谓，但 Linux/macOS 克隆要靠它）。

## 34.7 真的泄漏了怎么办（止血顺序，别跳步）

1. **先改口令**（最高优先）：泄漏的口令比什么都急；CAS 密码没见到明文，但**票据泄漏 = 有效期内可被冒用**。
2. **工作树脱敏补丁**（本轮做法：显式映射表逐个值替换，保持 LF、保持长度，见 §34.4）→ 提交 → 推送。这一步**不能**撤下已公开的数据，只是止血。
3. **历史改写**：`git filter-repo --replace-text <规则文件> --replace-message <规则文件> --force`。四个坑：
   - 仓库里若留有 `.git/filter-repo/already_ran`（上一次改写留下的），它会弹**交互式 continuation 提示** → 无 stdin 时 `EOFError` → 先把它移走；
   - 不加 `--force` 会报 `Refusing to destructively overwrite repo history since this does not look like a fresh clone`；
   - 它**会删掉 `origin`** → 跑完要 `git remote add origin …`；
   - 正则按 **bytes** 编译：`\u4e00` 直接报 `re.PatternError: bad escape \u` → 汉字边界写成 `(?<![\x80-\xbf])名(?![\x80-\xbf])`。
4. **强推 + 验收**：`git push --force-with-lease origin main`（9 个本地分支与 tag 都要覆盖），然后 `git log --all -S'<敏感串>'` 必须为 0；再用 `filter-repo` 之外的独立脚本全历史扫一遍（本轮的 `verify_rewrite.py`：2756 个文本 blob，IDCARD / TGT / ST / SESSION_UUID / JSESSIONID_LONG / OPENID / CARDINFO **全 0**）。
5. **改写 ≠ 彻底清除**：GitHub 会保留不可达对象，旧 SHA 仍能取到内容（实测 `contents/test/network_service_data_test.dart?ref=ef8038b…` 仍回清洗前的真实口令与真证件号；`commits/81ea406a…` 仍 200）。**唯一彻底办法 = 删除并重建同名仓库**（账号权限动作），重建后 `git push -u origin main --tags` + 覆盖其余分支。
6. **动手前先备份**：`git bundle create --all <备份>.bundle` + 一份 mirror clone（本轮备份在 `%TEMP%\backup\`）。

## 34.9 已知边界（写清楚，免得被当成「已经安全」）

- 钩子不跑全量测试（4 分钟），也不是安全边界 —— 它挡的是**手滑**，不是**对手**。
