# 33. 横向地基件（跨模块唯一实现）

> 2026-09-20 立。由来 = 四路只读架构审计的结论：**纵向切得干净（feature-first + 模块 README +
> 逆向笔记 + 守卫测试），横向没有地基（凡跨模块共用的事都在每个 feature 里各写一遍）**。
> 本轮先把「同一件事被抄成 N 份」的三处收口，并记下**哪些看着像重复、其实不该统一**。

## 33.5 异常体系：一个基类 + 一个「会话失效」标记（2026-09-20 收敛）

**问题（审查 ③「错误体系双轨」）**：本仓有**两条并行的失败表达**——
`Failure`（`Either<Failure, T>` 的**返回值**侧，dartz 风格，13 个文件在用）与
**29 个站点异常**（`implements Exception` 的**抛出**侧）。两条并存本身是既定架构、**不要合并**；
真正的问题是抛出侧**没有公共类型**：29 个类各自写 `final String message;` 与
`String toString() => message;`，于是

- 「把异常文案说给用户听」这件事在 29 处各写一遍；
- 界面层**无法按类型分支**（「这是会话失效 → 给重新登录入口」），只能退回
  「在 `e.toString()` 里搜关键字」这种「拿文案当类型」的写法；
- `TgcExpiredException.toString()` 原本是 `'TgcExpiredException: TGC 已过期，需要重新登录'`，
  而 `lib/features/auth/data/auth_repository.dart:453` 又用 `'统一登录已失效，请重新登录：$e'`
  把它**直接插给用户** → 用户看到的文案里带着**类名**。

**决策**：新建 `lib/core/errors/app_exception.dart`，全族只留两个类型。

| 类型 | 契约 | 谁用它 |
|---|---|---|
| `AppException`（`abstract`） | `const AppException(this.message)`；`final String message`；`toString() => message` | 29 个站点异常**全部**改为 `extends AppException` |
| `SessionExpiredException`（`abstract extends AppException`） | 只管「按类型分支」这一个语义 | 会话失效那 **9** 个 |

**会话失效族的成员与判据**：判据 = **名字里有 Expired + 补救动作都是「重新换票 / 重新登录」**。
成员 = `JwSessionExpiredException`（教务）、`TgcExpiredException`（CAS 统一认证）、
`ChaoxingSessionExpiredException`（学习通）、`TsgxsSessionExpiredException`（入馆教育）、
`ReadCreditSessionExpiredException`（阅读学分）、`LibspSessionExpiredException`（图书馆）、
`SspSessionExpiredException`（综合服务）、`DzjSessionExpiredException`（数据中台）、
`SelectionSessionExpired`（选课）。

**刻意不进族**（换票没用，混进去会让界面给错建议）：

- `ChaoxingChallengedException`（**风控**：要等约 120 s 冷却，重试只会延长窗口，见 §30）、
  `ChaoxingPageException`（页面拿到了但不是业务页）；
- `TsgxsAccessDeniedException`（业务状态：未解锁 / 被顶下线）、`TsgxsChapterPassedException`（章节已通过）；
- `CxstarSessionException` / `LibspSessionException`（**会话「建立」失败**，不是「已失效」）。

**迁移时必须保住的特殊形态**（都有守卫钉住）：`TgcExpiredException([responseBody])` 保留
`responseBody` 附加字段（`toString()` 归一成 `message`，即去掉类名前缀，**这是有意的用户可见改进**）；
`ElectricityApiException(code, message)` 两参；`NetworkServiceException(message, {needGuid})` 保持
`const` 构造（被 `test/network_service_data_test.dart` 钉住）；`SelectionSessionExpired()` 由无参改成
`([super.message = '选课会话已失效'])`（**加默认值 = 放宽**，`const SelectionSessionExpired()` 照旧可编译）；
`ChaoxingSessionExpiredException extends ChaoxingSessionException implements SessionExpiredException`
—— **父类不动**（仓库里按 `on ChaoxingSessionException` catch 的地方不许漏），只额外挂标记接口。

**顺带修掉的两处真问题**：

1. `lib/core/errors/failures.dart` 的 **8 个 `Failure` 子类各自重复声明 `final String? message;`**，

### 33.5.1 「异常 → 上屏文案」的唯一出口 `friendlyErrorText`

```dart
String friendlyErrorText(Object error) {
  if (error is AppException) return error.message;          // typed：本来就干净

```

#### 33.6.1.1 「跳转缝」的适用边界（为什么这次可以用、以及它**不是**通用路由器）

`lib/core/navigation/service_nav.dart` 只做两件事：`registerServiceScreen(id, builder)`（**只有组装根 `lib/main.dart` 调**）+ `openServiceScreen` / `resetToServiceScreen`（业务代码喊 id）。与既有的 `mfaReloginService.setFallback`（§33.5 同源套路）**同一形状**：组装根本来就知道所有模块，feature 之间因此少一条边。

- ✅ **该用**：目标页属于**外壳职责**（「切换账号 → 回主页」= `resetToServiceScreen(kServiceHome)`）。这不是 zongce/ims 该知道的事。
- ⚠ **可以用但要记账**：**跨页快捷入口**（综测卡的「去材料库录入」）。代价是**牺牲编译期可见性** —— 读 `openServiceScreen(context, kServiceMaterials)` 的人得知道它落到哪一页，所以：
  1. seam **必须保持极小**（现在只有 3 个 id：home / materials / settings），**不许**把它扩成通用路由器；
  2. 每个 id 的**唯一注册点** = `lib/main.dart` 的 `_installServiceScreens()`，守卫会断言这三条注册都在；
  3. 未注册时**静默返回**（单测只 pump 一个页面时不会走组装根）—— 这也是「不许拿它当业务依赖」的护栏：真正的数据依赖不可能靠静默 no-op 活着。
- ❌ **不该用**：为了少几条环，把「页面 A 正常依赖页面 B 的数据/组件」也塞进来 —— 那只是把依赖藏起来。判定口径：**问「这条依赖是数据/口径，还是纯导航？」** 后者才可以进 seam。
