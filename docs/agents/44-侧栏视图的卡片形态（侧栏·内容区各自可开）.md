## 44.1.1 间距口径：卡片↔卡片 = a、卡片↔窗口边 = a（三轮立 · **十七轮改口径**）

用户三轮原话：「我希望卡片与卡片之间的距离为 **2a**、卡片与窗口之间（**卡片与标题栏之间的距离不受此限制**）的距离为 **a**；然后 a 可以通过设置调」。
**十七轮修订**：「我希望现在的卡片与卡片之间的间距不再是 2a，而是 a」→ 两处同值（见 §44.1.11）。

| 量 | 值 | 说明 |
|---|---|---|
| `CardGapMetrics.edge` | **a** | 卡片与窗口**左 / 右 / 底**边的距离（**顶边不适用**：主体贴着标题栏，`top: 0`） |
| `CardGapMetrics.between` | **a**（十七轮前是 2a） | 两块之间那道缝（只在该侧也是卡片时给，否则是 1px 的空隙） |
| `CardGapMetrics.gutter` | a + 8 | **七轮起页面不再直接用它**（原先是"整块主体统一缩一圈"的 padding，已被用户否掉，见 §44.1.2）。现在它只剩 **"阴影呼吸位"这个概念**：`edge` 与阴影铺开半径（约 9px）的关系由它表达，守卫仍钉着 `gutter > edge` 且差值 ≥ 8 |

⚠ **`a` 与阴影的关系**（八轮起按逐边口径）：卡片外沿那道 `a` 是**可见**距离，阴影从卡片边缘往外铺约 9px —— `a` 调到 2~6 时阴影会在**另外一侧**（卡片之间那道缝、或底边）铺开，靠窗口那侧则被窗口边裁掉一部分。这是可接受的（用户就是要"卡片离窗口近一点"），不要再为了"阴影完整"去加 `gutter`。
`a` 默认 **8**（十七轮前是 6 —— 那时 `between = 2a`，取 6 是为了让间距正好等于改造前的 12）；范围 **2~24**，滑杆按 `kCardGapStops` 吸附、落盘整数文本；NaN / 无穷 → 回落默认值，越界 → 夹回（`parseCardGap` 对盘上脏数据同样容错）。

实测（1280×720，`HomeSidebar` 外框矩形 / 逻辑像素）。⚠ 下表是**三轮~十六轮（`between = 2a`）**那次实测的留档，
十七轮之后 `between == edge`，旧数值**不再适用**，要重新量：

| a | edge | between | gutter | 侧栏卡 x 区间（旧口径） |
|---|---|---|---|---|
| 2 | 2 | 4 | 10 | `11 .. 243` |
| 6（旧默认） | 6 | 12 | 14 | `15 .. 247` |
| 24 | 24 | 48 | 32 | `33 .. 265` |

## 44.1.2 留白**逐边按卡片给**（2026-10-09 七轮修订）

用户原话：「我发现除了设置里可调的那个卡片边距，是不是只要内容和侧边栏不都处于非卡片状态，就会有一个整体相对于窗口的边距，我希望取消」——**是的**，七轮之前那一版是给**整块主体**套了一层统一 `AnimatedPadding`（`a + 8`，四边都缩），于是：

- 顶部（卡片↔标题栏）白留了一条 ~14px 的带子（明明卡片该贴着标题栏）；
- 一侧不是卡片时，那一侧也被缩了一圈 —— 明明是通栏色块，却跟窗口边有一条缝。

现行口径（`home_screen.dart` 的 `_buildSidebarBody`；`_paneCard` 已于二十一轮删除）：

| 边 | 留多少 | 谁来留 |
|---|---|---|
| 侧栏左 / **底** | **a**，只要**侧栏是卡片**（十八轮起收起也留；底边是二十三轮补的） | 侧栏外面那层 `AnimatedPadding` |
| 两块之间 | **a**（十七轮起与边距同值），只要**两块都是卡片**（十九轮起收起也留；否则是 1px 空隙） | 中间的间隔件 |
| 内容区右 / 底 | **a**，仅当**内容区是卡片** | 右栏那层 `AnimatedPadding`（二十一轮起与 `CardFrame` 同在 `AnimatedSwitcher` 外） |
| 顶（贴标题栏） | **恒 0** | —— |

实测（1280×720，`a = 6`，`HomeSidebar` 矩形）：

| 卡片形态 | 侧栏矩形 |
|---|---|
| 两块都是卡片 | `6, 0 .. 240, 720`（距窗口左 6、上 0） |
| 只有内容区是卡片 | `0, 0 .. 232, 720`（侧面**贴窗口边**，没有缝） |
| 只有侧栏是卡片 | `6, 0 .. 240, 720` |
| 两块都不是卡片 | `0, 0 .. 232, 720` |
| 两块都是卡片 + 侧栏收起 | `0, 0 .. 46, 720`（窄轨贴窗口边） |

⚠ `CardGapMetrics.gutter`（`a + 8`）**仍然存在**，但它现在的用途只剩「阴影呼吸位」这个**概念**：现行实现里外圈补白 = `a + 8` 只用于「单侧卡片时的外沿」——见右栏与侧栏那两层 padding 的注释；`gutter` 本身不再被页面直接使用（守卫仍钉着 `gutter > edge` 且差值 ≥ 8）。

## 44.1.3 侧栏可收起（2026-10-09 七轮 · 十一轮改口径）

用户七轮原话：「我希望侧边栏可收起」；十一轮改口径：「侧边栏折叠也要显示图标，只是不显示每一项的文本了，高亮什么的照旧」。

- **状态** = `home_screen.dart` 的 `_sidebarCollapsed`（**只活在页面 State**，不进 Hive —— 与 `_selectedService` 同口径：切走再回来是展开的）。
- **收起形态 = 同一条侧栏、只是窄了且不画文字**（**不是**另一棵子树）：宽度 = `HomeSidebar.collapsedWidth`（**40** = `pillInset 4` + `pillHorizontalPadding 6` + 图标 18 + 6 + 4），
  `_overviewRow` / `_row` / `HomeSidebarFooterRow` 里的文本**整个不画**（连 `SizedBox(width: 10)` 的缝也不留），图标照画、**选中胶囊照旧**（圆角 / 底色 / 描边都不变，只是窄）。
  分组标题改成**一条与图标同宽的 `Divider`**（40 宽的轨道里放不下文字，也不该硬挤）。
- ⚠ **收起态不是另一棵树**，这一点有两层好处：① 从根上避免「换子树 → 滚动位置归零」那类问题（见 §44.4 ②）；② 收起 / 展开时列表不重建。
- ⚠ **工具行（展开/收起按钮所在那 36 高）两种形态都占**：收起时按钮搬进这一行**居中**、展开时在行尾右对齐。**别在收起时把整行去掉** —— 列表会整体上移 18px，「收起 / 展开」那一下会跳（实测）。
- **收起时 `card` 不再自动为 false（十八轮改）**：收起后那条 40 宽的窄轨**仍然是卡片**
  （圆角 / 描边 / 阴影都在），所以 `home_screen` 传的是 `card: sidebarCard`；
  左边那道 `a` 同理只看"是不是卡片"（`left: sidebarCard ? gap.edge : 0`）。
  详见 §44.1.12。
- **块间那道缝只看"两块是不是卡片"**（十九轮改）：`sidebarCard && contentCard` 就留 `a`，**侧栏收起也留**（详见 §44.1.13）；只有一侧是卡片时才回落到 1px 空隙。
- 右栏自动占满腾出来的宽度（`Row` + `Expanded` 天然如此），不用手写宽度动画。

守卫 = `test/home_sidebar_test.dart`「可收起」组：
未收起时画按钮 / 点了要回调；收起态**宽度 = 40、图标与行与底部固定区照旧、文本全不画**、分组标题不画文字；收起态下**选中胶囊照旧**（圆角 + 底色）；收起态也能是卡片；未给回调时不画按钮。


## 44.1.4 卡片背后露出来的背景 = **标题栏色**（2026-10-09 八轮）

用户原话：「我希望卡片后露出来的窗口背景色要与标题栏一致」。

七轮之前那版露的是**页面底**（`AppColors.page` = `scheme.surface`）：深色下页底 `#121212`、
标题栏 `#1A1A1A` —— 卡片四周于是有一圈**比标题栏更深**的带子，顶栏与侧栏的「视觉连续」
被它打断（逐像素实测：缝里 `#121212`、标题栏 `#1A1A1A`）。

- **取值** = `lib/design/card_frame.dart` 的 `cardFrameBackdropColor(context)`

  —— 也就是 `windowTitleBarColor` 的同一个式子（自绘标题栏用它画那条带子）。

## 44.1.5 侧栏选中态 = **圆角胶囊高亮**（2026-10-09 十轮）

用户原话：「我希望更改侧边栏高亮方式，我希望改成圆角高亮，侧边条改成短的圆角的」。

- **取代**原来那条**通高 3px 左侧指示条**（`HomeSidebar.indicatorWidth` 从此只作为「别再拿它画东西」的具名引用留着）。
- 唯一实现 = `lib/features/home/presentation/home_sidebar.dart` 的 `sidebarPillDecoration(context, accent, {selected})`，
  **四类行共用**：目录行 / 分组里的行（都走 `HomeSidebar._rowShell`）、顶部「数据一览」、底部固定区两行（`HomeSidebarFooterRow`）。
- 三个几何口径（常量都在 `HomeSidebar` 上）：

| 常量 | 值 | 作用 |
|---|---|---|
| `pillRadius` | 8 | 胶囊圆角 |
| `pillInset` | 4 | 胶囊**左右各退 4**（不切侧栏边缘；侧栏是卡片时那圈落在卡片底色上，通栏时是同色留白 —— **简单退固定 4，不按卡片形态分档**） |
| `pillVerticalInset` | 4 | 胶囊**上下各留 4**（行高 38 → 胶囊高 30）—— 不缩的话圆角贴边看不出来，读起来还是"整条色块" |
| `pillHorizontalPadding` | 6 | 胶囊内留白；**`pillInset + pillHorizontalPadding = rowPadding(18)`** —— 所以图标 / 文字仍在原来的 x 上，只有高亮块自己缩了进来 |

- 配色：底色 `AppColors.tint(accent, 0.12)`（原来 0.10）；**描边**见下。
  ⚠ **描边那一笔是本轮唯一超出「只用填充色」的地方**，理由记在 `sidebarPillDecoration` 的注释里：
  浅色下 `primary @ 12%` 叠在**纯白卡**（本应用默认的侧栏卡片形态）上几乎看不出边界，
  加一圈很淡的同色描边圆角才读得出来（深色下是 `accent @ 30%`，本来就够分界，也照给保持一致）。
  用户否掉的话删掉 `sidebarPillDecoration` 里那一行 `border:` 即可。
- 底部工具行（展开 / 收起按钮）与底部固定区**都跟着 `pillInset` 缩**，所以胶囊的左右缘与按钮点击区右缘对齐。
- 守卫 = `test/home_sidebar_test.dart`「选中行是圆角胶囊高亮（不再是左边条）」：圆角 = `pillRadius`、有底色、
  **有描边时四边同宽**（出现"只加粗左边"就是旧指示条复活）、未选中无底色、行高契约不变（38）、胶囊上下留白 = `pillVerticalInset`。

## 44.1.6 侧栏收起 / 展开是**补间**的（2026-10-09 十二轮）

用户原话：「展开收起侧边栏要有动画」。

- 实现 = 侧栏本体那层是 `AnimatedContainer`（`HomeSidebar.collapseDuration` 200ms / `easeOutCubic`），
  宽度在 `width(232)` 与 `collapsedWidth(40)` 之间补间；**与 `home_screen` 那两层
  `AnimatedPadding`（左缝 + 下边 `a`、块间缝 `a`）同长同时长** → 收起来是「整块缩回去、右栏同时让开」。
- **两种形态仍然是同一个组件类型、不换 key**（九轮的教训，见 §44.4 ②）。
- ⚠⚠ **行的内容按「本行此刻有多宽」决定画不画文字，判据不是 `collapsed` 这个布尔**
  （十二轮 · 逐帧实测把这条钉死了）：宽度是补间的，动画中途会出现 **`room = 20`** 这种帧，
  而 **图标 18 + 缝 10 = 28 就已经超过 20** —— 光把文字夹成 0 宽度**不管用**，
  那 8px 是图标 + 缝本身撑出去的（实测 `RenderFlex overflowed by 8.0 pixels`，
  5 行就是 5 个异常，`takeException` 直接判失败）。
  试过并**否掉**的三种兜法：① `Flexible` + `LayoutBuilder`（`Row` 分配额度看的是子件固有宽度，
  窄到极限也给不出 0）；② `OverflowBox`（无界约束 → 文字自己撑成 `Infinity`，更糟）；
  ③ 外层 `ClipRect`（裁得住"画"，裁不住 `RenderFlex` 的溢出上报）。
  **最终口径**：`_iconAndLabel` 与 `HomeSidebarFooterRow` 都用 `LayoutBuilder` 量本行宽度，
  `room < 图标 + 缝 + minLabelWidth(24)` 就**只画图标**（连缝一起收掉），否则按
  `room - 图标 - 缝` 给文字定宽。文字外面再套一层 `Stack(clipBehavior: hardEdge)`
  当第二道保险（裁剪型布局不报溢出）。
- 实测的补间曲线（320 宽宿主、232 → 40）：30ms 155.4 / 60ms 101.8 / 90ms 70.8 /
  120ms 53.7 / 150ms 44.6 / 180ms 40.6 / 210ms 40.0 —— 每帧都不报异常。
- 守卫 = `test/home_sidebar_test.dart`「可收起」组的
  **「★ 收起 / 展开是补间的：中途宽度要在两端之间」**：第一帧必须还等于展开宽（否则就是"没有动画"）、
  中途必须**严格落在两端之间**、走完必须等于目标；展开方向同样过一遍。


## 44.1.7 侧栏不画滚动条、也不画分割线（2026-10-09 十三轮）

用户原话：「我希望侧边栏滚动不显示滚动条；侧边栏不要有边框线」。

### 滚动条

- 侧栏那个 `ListView` 外面套了 `ScrollConfiguration(behavior: _NoScrollbarBehavior())`
  （`home_sidebar.dart` 文件末尾那个私有类）：只覆盖 `buildScrollbar` 让它**原样返回子件**
  → 桌面端默认那层 `Scrollbar` 不再出现；**滚动本身（滚轮 / 拖拽 / 物理）走父类，行为不变**。
- 为什么不全局关：别的页面（设置页、成绩表…）的长列表是需要滚动条的，这一条只针对侧栏。

### 分割线（两处都撤了）

1. **侧栏与内容之间**那道 1px `VerticalDivider`（`home_screen.dart` 的 `_buildSidebarBody`）：
   撤掉，只留 **1px 的空隙**（宽度不能变 0：`AnimatedContainer` 的补间要有落点，且两块
   贴到一起会让圆角互相啃边）。分界改由**底色差**承担（侧栏通栏 = `surfaceContainerLow`）。
2. **底部固定区上方**那条 `Divider`（`home_sidebar.dart`）：撤掉。
   历史：2026-09-17 用户曾报「底部固定项最顶部的分割线太亮」→ 当时把
   `outlineVariant.withValues(alpha: 0.6)` 换成 `hairline`；现在整条撤掉。

⚠ **侧栏卡片形态下你仍会看到一条竖线**，那不是分割线，是 `CardFrame` 自己的
**1px 卡片描边**（`appCardBorderSide` = 深色 10% 白 ≈ `#2C2C2C`）—— 逐像素实测：
`x=366` 整列恒为 `#2B2B2B`（窗口全高），左右分别是侧栏底 `#1A1A1A` 与卡片缝的阴影。
要连它一起去掉＝改 `lib/design/app_card.dart` 的**全局卡片描边契约**（全应用每一张卡都受影响），
得单独拍板，别在这里顺手改。

守卫 = `test/home_sidebar_test.dart`：
「整个侧栏一条分割线都没有」（`find.byType(Divider)` 恒 0 + 底部固定区确实渲染）、
「滚动区不套 Scrollbar（滚轮照旧可用）」（`find.byType(Scrollbar)` 恒 0，
且 `maxScrollExtent > 0` 的前提下拖拽仍能滚动 —— 防的是"把滚动一起关掉"）、

## 44.1.8 卡片间距的步长 = **1**（2026-10-09 十四轮）

## 44.1.15 换页时**卡片框不许动**（2026-10-09 二十一轮 · 也是二十轮那个 bug 的真因）

用户原话：「为什么现在点击切换页面，会导致整个右侧内容卡片出现位置的水平闪动」。

### 真因

`CardFrame` 原本在 `AnimatedSwitcher` 的 **child 里面**（旧 `_paneCard`）：

```
Expanded → AnimatedSwitcher → KeyedSubtree(paneKey) → _paneCard = Padding + CardFrame + 内容
```

`transitionBuilder` 里的 `SlideTransition` 是按**自身宽度的百分比**位移的，于是换页那 220ms 里：

1. **整张卡片**（圆角 / 描边 / 阴影）跟着内容一起横移 → 用户看到的就是"右侧内容卡片水平闪动"；
2. 卡片被外面 `Stack(fit: expand)` 的边界**裁掉一截** → 被裁那一边的**描边整段消失**。

> ⚠ **二十轮我答错了**：当时用户报「圆角处框线断开」，我按"描边与页面底对比度低（44 vs 18）"
> 解释、并加了一层 `radius - 1` 的内缩裁剪。对比度那条**确实成立**（实测数据在 §44.1.14），
> 但**真正的成因是这个**：切换动画期间卡片自己在动、边被裁掉了。
> 教训：**用户话里出现"闪一下""切换时"这类时序词，先怀疑动画，别只看静态对比度。**

### 修法

把卡片层挪到 `AnimatedSwitcher` **外面**，层级变成：

```
Expanded → Padding(右/底 = a) → CardFrame → _paneSwitcher(AnimatedSwitcher)
                                              └ KeyedSubtree(paneKey) → 页内容
```

**框不动，只有页内容滑入 + 淡入。** 内容仍被卡片的圆角裁掉（`CardFrame` 那条
`ClipRRect` 还包在外面）。

### 守卫

- `test/home_pane_switch_card_test.dart`（**单开一个文件**：要按生产装配搭宿主 + 逐帧量矩形）
  —— **「★ 换页全程：卡片矩形一动不动」**：换页后连续 12 帧，每一帧
  `cardFrameContainerKey` 的矩形都必须与换页前**完全相等**，换完也不许变。
- `test/home_sidebar_test.dart` 的源码守卫：必须含 `child: _paneSwitcher(`，
  且非注释行里**不许**再出现旧函数名 `_paneCard(`（它把 CardFrame 包在 switcher 里）。

## 44.1.16 侧栏卡片的**下边**也留 `a`（2026-10-09 二十三轮）

用户原话：「侧边栏以卡片形式显示时，距离页面底部太近，似乎没有应用设置里的卡片间距设置」。

- **真因**：侧栏外面那层 `AnimatedPadding` 从三轮起就**只有 `left`**。于是侧栏卡片
  一路铺到窗口底边（`bottom: 0`），而右边那张内容卡有 `bottom: a` —— 两张卡**下边不齐**。
  用户读到的就是"没应用设置里的卡片间距设置"（其实左缝一直生效，只是下边漏了）。

## 44.1.19 从概览点开的那一页 · **顶部不许有导航栏**（2026-10-10 二十六轮）

用户原话：「我发现点击主页卡片后的效果还是不对，顶部不应该显示标题栏」。

### 真因（是 §44.1.18 那个修法的**副作用**）

概览被改成面板的**首路由**之后，从它点卡片就是往**同一个** Navigator 上压**第二层**：

```
面板 Navigator 栈：[概览]            → 点卡片 → [概览, 电费]（栈顶那层可见）
```

而 [paneIsRoot] 的判据是 `paneEmbedded && !Navigator.of(context).canPop()` ——
**压了第二层就不再成立** → [paneAppBar] 照常画出一条完整导航栏 + 自动返回键。
（从前看不到这个问题，是因为从前概览会退回整页 push，压的根本不是这个 Navigator。）

### 修法：区分"哪个面板"

`PaneScope` 加一个 `sidebarPane` 标记，只有**侧栏右栏那一格**（`home_screen`
的 `_overviewPane()` 新建的那个 `HomeDetailPane`）传 `true`：

```dart
bool paneIsRoot(BuildContext context) {
  if (!paneEmbedded(context)) return false;
  if (PaneScope.isSidebarPaneOf(context)) return true;   // ← 右栏：任何路由都算首路由
  return !Navigator.of(context).canPop();                // ← 其余：老判据不变
}
```

- 右栏这一格上**任何**路由都不画导航栏（用户要的就是内容铺满；
  他明确说「顶部不应该显示标题栏」）；
- **其余调用点一个字没改**：普通 `HomeDetailPane`、以及"内嵌服务页 → 课程详情"那种
  二级页**照旧有导航栏和返回键**（那条老口径是 2026-09-16 用户裁定的，不能顺手改掉）。

⚠ 三者一致的装配：`_buildPaneContent` 的**三个分支**（概览 / 目录条目 / 底部固定区那两页）
都带 `sidebarPane: true` —— 只给概览加会出现"视概览有、视服务没有"的不一致。

## 44.1.20 从概览点开的那一页 · **要记进顶部路由历史**（2026-10-10 二十七轮）

1. 跳转缝 `service_nav.dart` 的三个动作；

## 44.2 三条实测结论（都踩过，别改回去）


### ① 别拿 `AppColors.recessed` 当"卡片外那圈底"

浅色 `recessed` = `surfaceContainer` = **`#F5F5F5`**，而页面底 `surface` = **`#FFFFFF`**。当时想用它铺出"灰底 + 白卡"的层次，实测**缝里看不出任何深浅差**（浅色下两者在 1280×720 全屏里几乎不可分），只会把整屏压成一块灰板。
→ 结论：那圈底**只有一个正确取值 = 标题栏色**（八轮起，见 §44.1.4）；"卡片浮起"靠 **1px 描边 + 阴影**。这也是 vshell 的做法（它那边卡片与底同色系，靠 `sideBar-border` 分界）。
⚠ 本条在 2026-10-09 八轮前写的是「缝里露的就是页面底」—— **已作废**（页面底比标题栏深一档，会露出一圈突兀深带子）。

### ② vshell 的 `shadow-lg` 值**不能直接搬**到 Flutter（逐像素测不到）

vshell 是 `--vscode-shadow-lg: 0 0 12px rgba(0,0,0,0.14)`（`styles/base.css:18`）。原样写成 Flutter 的
`BoxShadow(color: 0x24000000, blurRadius: 12)` 之后，沿卡片外沿**逐行采样全是 `#FFFFFF`**，与"完全没有阴影"一模一样，只在贴边 1~2 行蹭到 `#DBDBDB`（等于不可见）。
**成因**：高斯模糊把这点 alpha 摊到约 19px 半径上 → 峰值强度 `0.14 ÷ 19 ≈ 0.7%`，比 1/255 大不了多少。
→ 修法 = **两层**（Material elevation 那套规模）：`alpha .14 / blur 3 / offset(0,1)` 勾边 + `alpha .12 / blur 12 / offset(0,4)` 撑扩散。深色再抬到 `.34 / .24`（深底吞阴影，见 `AppLadder` 的注释）。
守卫 = `test/home_sidebar_test.dart`「卡片形态 → 有阴影」断言**层数 = 2 且峰值 alpha ≥ 0.14**（单层会被这条挡住）。

### ③ 两张圆角卡**不能只隔 1px**（否则看成一张卡）

最初写法：两块之间沿用原来那道 **1px** `VerticalDivider`。逐像素实测 `x=245..246` 是**两条相邻描边、中间没有缝** —— 圆角 12 的两张卡贴在一起，读起来是「一张卡中间画了根线」。
→ 修法：两块之间的间隔件在卡片形态下换成一道**透明缝**，宽度 = **2a**（三轮起的口径，见 §44.1.1；当时是固定 12）。实测（1280×720、`a = 6`）：侧栏 `6..240`、缝 `241..252`、内容卡 `253..1267`。

## 44.3 阴影在哪儿看得见（别误判为"没生效"）

卡片外沿那圈缝里：**左/右/底部 12px 全部有阴影落点**；两卡之间那道 12px 缝里是两侧阴影叠加（最深）。
⚠ **卡片顶边没有**：`AnimatedPadding` 的 `top` 是 **0**（主体紧贴标题栏下沿，不空一条横带），而阴影 blur 12 的扩散会被裁掉 —— 这是有意的（一条 12px 的横幅空白比"缺上侧阴影"难看），别为了上侧阴影去加 `top` 留白。

## 44.4 工程坑（都踩过）

0. **⚠⚠ 动画 / 补间类改动一定要"逐帧"验**（十二轮最贵的一课）：`AnimatedContainer` 的宽度是
   **RenderObject 层每帧驱动**的，而「文本画不画」是**widget 层**按 build 时的布尔决定的 ——
   两者会在中间的几十帧上**不同步**。这一轮为此连试三种兜法（`Flexible`+`LayoutBuilder`、
   `OverflowBox`、外层 `ClipRect`）全部无效，最后靠**把判据从布尔换成"本行此刻的宽度"**才根治
   （详见 §44.1.6 与 `HomeSidebar._iconAndLabel` 的注释）。
   落到操作上：**改动画不要只 `pump()` 一次**，要 `pump(30ms)` 走完全程 + 断言"中途严格在两端之间"。
1. **`CardFrame` 里不要用 `TweenAnimationBuilder` 做"描边/阴影淡入"**：加了它之后卡片在 **golden 截图里整个消失**（逐像素全白）——隐式动画在 golden 抓帧那条路径上会把 `t` 重算成 0，`alpha × t = 0` 就什么都不画了。现在用自写的 `AnimationController`（`_CardTween`），首帧取终值、后续才补间。
2. **⚠⚠ 形态切换**绝不能**`换组件类型`/换 key**（2026-10-09 九轮 · 用户报的「改卡片样式后设置页跳回顶部」的两个根因，逐帧实测把归因钉死了）：
   - 症状：在内嵌的设置页里点「卡片样式 / 卡片间距」→ 页面**跳回顶部**（`pixels 1200 → 0`）。
   - 根因 A = `CardFrameBackdrop`：原先 `visible == false` 时 `return child`、否则返回 `AnimatedContainer` —— `visible` 一变就**换组件类型**，内嵌页的视口跟着重建，`ListView` 滚动位置归零。
   - 根因 B（同族）= `CardFrame`：原先 `card == false` 时 `return child`，而调用方又挂了 `ValueKey(card ? 'Card…' : 'Plain…')` —— 换 key + 换类型 = 整棵子树重新挂载。
   - **修法**：两者都改成**恒返回同一个组件**（`CardFrame` → 一个 `Container` + 自己补间 decoration；`CardFrameBackdrop` → 恒返回 `ColoredBox`，没卡片时颜色透明），调用方**一律不传 key**。
   - **归因对照（留档，原始探针已删）**：只改 `AnimatedPadding` → 不跳；只改 `CardFrame.card` → 不跳；两者一起 + 背景层 → 跳；把那层背景拿掉 → 不跳。所以凶手是背景层，`CardFrame` 是同族隐患、一并收掉。
   - 守卫 = `test/home_card_style_test.dart` 的「★ 回归：改卡片形态 / 间距都不许把内嵌设置页的滚动带塌」（按**生产装配**搭宿主：背景层 → 逐边 padding → 卡片框 → `HomeDetailPane(设置页)`；用 `ValueNotifier` 原地重建，**不要**靠反复 `pumpWidget` —— 那会换掉整棵 element，测出来的是"重挂载"而不是生产路径）。
3. **测试里放大视口会让"多行卡片"的用例溢出**：`SettingsHomeLayoutCard` 加了四行之后比默认 800×600 高 98px →
   - 只读渲染它的用例必须开高视口（`test/home_card_style_test.dart` 用 800×1400）；
   - 而且这条用例**不要塞进 `test/home_grid_aggregate_test.dart`**：那个文件 2500 行、前后几十个重用例，塞进去会从"单独跑 0.1 秒过"变成"整份文件跑到 24 分钟才失败"。所以卡片样式单独一个 `test/home_card_style_test.dart`。
4. **断言卡片形状要走 `cardFrameContainerKey`**：`CardFrame` 的子树里**不止一个 `Container`**（补间层 + 它自己那层），`widget<Container>()` 会 `Bad state: Too many elements`；`find.descendant(of: CardFrame, matching: byType(Container))` 又会因为**严格后代**规则一个都找不到。Key 在 `lib/design/card_frame.dart` 里公开。
5. **源码守卫里别把换行写进断言**：本仓源码是 **CRLF**，`contains('…(\n            left:')` 永远匹配不上（实测踩过）。
6. **`AnimatedContainer` 不许「`clipBehavior != none` 且 `decoration == null`」**：`container.dart` 的断言 `decoration != null || clipBehavior == none`。所以「不是卡片」那一档给的是**非 null 的占位 decoration**（圆角 0 / 无描边无阴影，逐像素等价于没画）。
