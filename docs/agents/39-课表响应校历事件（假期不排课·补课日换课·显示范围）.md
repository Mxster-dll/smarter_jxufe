## 39. 课表响应校历事件（假期不排课 · 补课日换课 · 显示范围）（2026-10-08 立）

用户原话：

> 我们项目现在有个问题，那就是关于课表的显示，应该响应校历里的事件。具体为如果是假期就不显示
> 课程（除非是移课移到那天），然后还有诸如 xx 天补 xx 周 xx 天课程，这样的课表也要动态响应。
> 并且修改一下课表隐藏周六、周日的逻辑，隐藏生效仅当没课时才生效，如果某周周 x 有课，但是设置
> 又是隐藏周 x，那么此时这天还是显示的。

**生效范围（用户二轮补充）**：课表页 **+** 首页「今日课程」/ 实况窗 / 上课提醒；首页今日课程
**也要显示今日的事件**，**无课时要给出原因**（周末 / 暑假 / 寒假 / 国庆假期）。

### 39.1 三条口径（唯一实现，页面不许再写一份）

| 口径 | 实现 |
|---|---|
| ① 假期不排课（**除非**有课被移/补到那天） | `lib/features/ims/schedule/domain/schedule_board.dart` 的 `_classesForPlan` |
| ② 补课日按「被补的那一周那一星期」上课 | 同上（来源由 `parseMakeupTarget` 从官方原文解析） |
| ③ 隐藏周六 / 周日**只在没课时**生效 | 同文件的 `scheduleDaysWithClass` + `schedule_display_days.dart` 的 `scheduleVisibleDays(daysWithClass:)` |

**判假 / 判班的唯一实现仍是 `lib/features/school_calendar/domain/calendar_day_mark.dart`**
（§8：主源 = 小程序校历官方逐日安排，教务 `workday|nonday` 只兜寒暑假）。本轮**没有**重判一次，
只在它上面加一层语义转译：


### 39.2 补课原文的真实形态（实测台账）

| 原文 | 出现处 | 解析 | 自洽性核对 |
|---|---|---|---|
| `补第4周周五的课` | 261（2026-2027 一学期）**2026-10-10** | `(week: 4, weekday: 5)` | 第 4 周周五 = **10-02**，正在国庆假期（10-01~10-07）内 ✅ |
| `补第10周周一的课程` | 252（2026 二学期）**2026-05-09** | `(week: 10, weekday: 1)` | 第 10 周周一 = 05-04，在劳动节假期（05-01~05-05）内 ✅ |
| `补周五的课` | 旧版整段文字（2018 春 `4月8日…`） | `(week: null, weekday: 5)` | 缺周次 → **按同周**处理（调休补课总是补本周被假期冲掉的那天） |

正则：`补(?:第\s*(?<w>\d{1,2})\s*周)?\s*(?:周|星期|礼拜)\s*(?<d>[一二三四五六日天])`。
**认不出必须返回 null**（= 按普通日处理）：`补（缓）考`、「因法定节假日放假所差课程由教师
自行安排补课」都不是调休补课，实测被这条卡住过。

### 39.3 界面表现（用户二轮选「表头加小字标记」）

- **表头红 / 灰的判据 = 「这一天有没有课」，不按星期几（用户 2026-10-09）**。原话：
  「我希望课表的标题不是固定周一-周五红色、周末灰色，而是按校历来，**如果上课或补课则红色、
  假期或不补课的周末灰色**」。唯一实现 = `ScheduleTone.headerFillOf(context, hasClass:)`
  （红 `#C62828` / 蓝灰 `#455A64`），判据取 `ScheduleColumn.hasClass`（= `courseCount > 0`，
  **已含假期抑制与补课取源**）—— 于是：
  - 国庆假期里的周一（课被校历抑制掉）→ **灰**（旧口径是红 ✗）；
  - 补课日周六（上的是被补那天的课，本来就有课次）→ **红**（旧口径是灰 ✗）；
  - 一周里本来就没排课的工作日 → 灰（数据说了算，不看它是周几）；
  - 两个视图同一判据：竖版 = 表头实心底；横版 = 行首标签（有课 = 主题红字 + `fillSoft` 底、
    没课 = 灰字 + `fill` 分区底），空格子 / 矮列的分区底也一起改判据
    （`ScheduleTone.columnFillOf` / `emptyCellFillOf`）—— 「周末列有分区底」这个说法作废，
    改叫「**没课的列**有分区底」。
  - ⚠ 判据里**不许**再出现 `isWeekend` / `day >= 5`（源码守卫盯着这两个文件）。
- 竖版表头第 3 行 = `plan.effectLabel`：假期名（红 `fp.calendarHoliday`）/ `补第4周周五`
  （绿 `fp.calendarMakeup`，与校历页「假 / 班」同色）；整行 `FittedBox.scaleDown` —— 宁可小一号，
  也不省略成「补第 4…」；悬停 / 长按给 tooltip（日期 + 官方原文 + 「按第 4 周周五的课表」）。
  ⚠ 这一行的红 / 绿是**校历语义**（假 = 红、班 = 绿，与校历页角标同色），与上面表头那层
  「有没有课」是两个维度，别合并。
- 横版行首同样三行，但**行高 < 40dp 时丢掉小字**（`_effectLabelMinRowHeight`）：横版是
  「恒适应高度」，两行本来就把矮行填满了。
- 假期列：常规课次**全部**不显示（含「已调至…」「本次停课」这类占位格）；只有在**本日实际日期**
  上落地的 `moved` / `extra`（被调课 / 补课搬进来的）照常显示 —— 这就是用户说的「除非是移课
  移到那天」，否则那节课会人间蒸发。
- 补课列：本日原本的课**让位**，改显示被补那一周那一星期的课（10-10 周六显示第 4 周周五的课表，
  周六自己的课不再出现）。
- **整学期模板（`week == null`）不按日期过滤**：模板没有具体日期，一列是整学期的汇总 ——
  效应只作用于「有日期的那一列」。它的「有没有课」仍按 §39.4 逐周扫。
- 渲染对照（真实渲染，`simhei` 代系统字体，仅看配色）：
  `docs/design/课表表头-按校历红灰-第5周国庆.png`（周一二三灰 + 补课周六红）、
  `docs/design/课表表头-按校历红灰-普通周.png`（有课的周一到周六红、周日灰）。

### 39.4 隐藏周六 / 周日的新判据（口径修订 · 2026-10-08 定稿为「落定周 + 翻页途中冻结」）

`scheduleDaysWithClass(...)` → `Set<int>`（0 = 周一），再交给
`scheduleVisibleDays(showSaturday:, showSunday:, daysWithClass:)`：

- **粒度 = 一周**（用户 2026-10-08 二轮原话：「如果周六在第 5 周因为补课而有课，但是
  其他周没有，那么在其他周的视图中，周六就不应该显示。只有在第五周的视图中周六显示」）：
  第 5 周周六是补课日 → **第 5 周这一列照常显示，其它周该收就收**；传 `week: null`
  （整学期模板 / 历史学期没有日期）= 逐周扫过 1..lastWeek（拿不到日期时退化为模板列本身）；
- ⚠ **但与分页器不相容的那一半必须处理**：分页器的**静态表头与相邻页共用一份列集合**，
  而补间途中 `onPageChanged` 会逐页回灌周次 → 若判据跟着「正在看第几周」逐页走，列数会在
  飞行中 6↔5、列宽重排（用户同轮报的「一旦切换周数时，起点或终点是本周，就会动画错乱」；
  逐帧探针实测：`cur=5` 时 `t=50ms page=5.65 周六列=0`）。**整学期一刀切**能修好动画，
  但会变成「第 6 周也显示周六」——用户随后明确否决。
- ✅ **定稿口径 = 按入口分开**（用户三轮反馈）：
  - **选周 / 长按回本周**（`_goToWeek`）= 「立刻去那一周」→ 列集合**跟着目标周一起换**：
    `_layoutWeek = clamped` 与 `_week` 同一次 `setState`，换列发生在**补间起手之前**
    （画面还没动、弹窗正在退场）—— 第 5 周的周六列**随第 5 周一起滑进来**。
    用户三轮原话「从第 6 周切到第 5 周，第 6 周是不显示周六的，但是第 5 周显示，此时
    就会导致周六列的突然出现」说的就是上一版「**落定后才换**」留下的那一下；
  - **手势翻页**（没有目标周，落点由松手决定）= 拖动期间冻结，**停稳**才按落点重算
    （`WeekPager.onSettled` ← `SchedulePagedBoard.onSettled` ← `ScheduleGridView.onPagerSettled`，
    实现 = `NotificationListener<ScrollEndNotification>`；**只认滚动结束通知**：`onPageChanged`
    在补间途中逐页触发，用它当判据等于没冻结）—— 否则手指拖动途中列宽会重排；
  - 两个视图都新增 `visibleDays:`（页面按 `_layoutWeek` 算好传进来，口径只此一处），
    不传 = 视图自己按 `week` 现算（直接 pump 视图的既有用例）；
  - ⚠ 不走分页器停稳的另外两条路要**手动跟上**：切学期 / 换学年（`_syncTermContext`，
    分页器被重建）与整学期 ↔ 周视图切换（`_toggleView`）都直接 `_layoutWeek = _week`；
  - 横版同理（它是屏幕自己包的 `WeekPager`，`onSettled` 直接接 `_onPagerSettled`）。
- ⚠ **几何陷阱（2026-10-08 四轮定案 · 这条比口径本身更隐蔽）**：非 compact（桌面 / 宽窗口）
  时列宽被夹在 `[80, 160]` → **列数一变整表总宽就变**（6 列 996 / 5 列 836）。分页器若裹在
  这块宽度里（旧写法 `SizedBox(width: totalWidth)` 包 `SchedulePagedBoard`），换列集合
  （**唯一会换的情形就是起止点是本周**）就会在**补间飞行途中改掉分页器视口宽度** → 正在飞的
  补间像素目标失效 → **落点错周**（实测：选第 11 周落在**第 13 周**；单独实验也证过
  视口 900→700 会让「第 5 → 第 12 周」落在第 15 周）。
  **定案 = 分页视口恒等于可用宽度、表格内容按 `contentWidth` 居中**
  （`SchedulePagedBoard.contentWidth`；紧凑布局本来就等宽，逐像素不变）。
  守卫 = `test/schedule_pick_week_animation_test.dart` 的「桌面宽窗口（非 compact）」组
  （**视口宽度不许变 + 落点必须是选中的那一周**；旧几何下两条都红）。
  ⚠ 复现必须在**桌面平台**下测：widget 测试默认 android，而 android 在 1920×1080 会按
  「手机横屏」挑**横版**视图（横版天数是行，行高变化不影响横向分页视口，复现不出来）；
  `debugDefaultTargetPlatformOverride` 要在**测试体内**复位（tearDown 来不及）。
- 守卫：
  - `test/schedule_display_prefs_test.dart`「★ 列集合按『这一周』算：周六只有第 3 周有课 →
    只有第 3 周画周六列」（第 2 / 3 / 5 周逐周断言）；
  - `test/schedule_pick_week_animation_test.dart` 两条 ★：**逐帧断言「选中后列集合恒为
    目标周的口径」**（`_expectConstantAfterPick`，含飞行中的帧）+ 落定后一致。
    **变异都验过**：改成「跟着 `onPageChanged` 逐页走」→ 红在中途出现另一档值；
    改成「冻结到落定才换」（上一版）→ 红在飞行中前几帧仍是起始周口径；
    改成「整学期口径」→ 红在「第 11 周（周六没课）却仍显示周六列」。

配套改动：设置页「课表」节的**确认框已删除**（`_confirmHide`），副标题 = 「本学期有 N 门课
安排在这一天（**有课的那一周仍会显示**）」—— 隐藏已经不可能让用户看不到课（守卫钉着旧文案
不许复活）。计数仍走 `scheduleDayCourseCount`（**不认校历**的粗计数，只服务这行文案）。

分页板（竖版周视图）的可见天取**页面上停稳的那一周**（不是每页各算各的，也不是整学期一刀切）；
非分页的窄窗口 / 整学期模板走同一函数、由页面传 `visibleDays`，免得同一份课表在两种模式下
长得不一样。

### 39.5 首页今日课程 / 实况窗 / 课前提醒

三处与课表页共用 `effectiveClassesOfDate`（`ScheduleCalendarContext` 一路传下去），
**未传 = 旧行为逐字不变**（既有单测据此保持绿色）：

- `live_session.dart`：`sessionsOfDay` / `resolveLiveSession` 新增可选 `calendar:`；
  实况窗页（`live_class_screen.dart`）每帧 `_calendar = ScheduleCalendarContext(effects: ref.watch(...))`

- `dashboard_providers.dart`：
  - `dashboardTodayCoursesProvider` 现在**认周次 + 认校历 + 认本地调课**（从前只按星期过滤：
    假期、补课、调课全都看不见）；校历与教学周都拿不到时退回旧口径（缓存过旧不至于白屏）；

- 首页卡片：事件列表放在**时间轴上方**（移动端卡片与指标卡区等高，时间轴自己还要滚动，
  事件放下方等于永远看不见）；无课时文案 =「今天没有课 · 国庆节假期」（说不出原因才退回

### 39.6 实测坑（都踩过）

1. **行首日期会折成两行 → 溢出 1.2px**：`10/10`、`12/31` 这类 5 字符日期，8px 字号 + 主题继承的
   `letterSpacing: 0.3` 量出 **41.5dp**，而行首只有 36dp → 折行 → 列高 39dp > 行高（矮窗口实测
   `RenderFlex overflowed by 1.2 pixels`）。修法 = 日期包 `SizedBox(width: …) + FittedBox.scaleDown`
   + `maxLines: 1`（放得下时逐像素不变）。⚠ 这是**修好了的老问题**，不是本轮引入的 —— 只要
   10 月中旬以后打开横版就会遇到。
2. **widget 测试里 `calendarDayEffectIndexProvider` 会去开 Hive**：
   `wxArrangementsProvider → platformGuidProvider → platformGuidBoxProvider → Hive.openBox('wxPlatform')`，
   未 `Hive.init` 时抛 `HiveError: You need to initialize Hive…` 把测试打挂（同一族坑见
   `home_dashboard_layout_test.dart` 里作息表那两条注释）。凡 pump 首页面板 / 课表页的测试都要
   `dashboardTodayCalendarProvider.overrideWithValue(const TodayCalendarInfo())`。
3. **源码守卫按子串匹配，文档注释也算**：设置页那条守卫查 `'仍然隐藏'` /
   `'隐藏后课表里就看不到它们了'`，我在注释里复述旧文案就把守卫弄红了 → 注释改写成
   「关掉之后这些课就看不见了」之类。改文案时先看有没有守卫钉着这句。
4. **`dart analyze` / `flutter test` 在 workspace-write 沙箱下必被拒**（见 §1）：跑本轮验证要
   一次性 `danger-full-access`。
