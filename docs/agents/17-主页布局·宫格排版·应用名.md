### 17.8 仪表盘版式：左指标卡 / 右今日课程（2026-09-18 用户七轮裁定）

**七轮补丁（同日，用户原话：「主页课表卡片两个问题 1. 今天没有第三节晚课，但是组件里第二节晚课后没有空间了 2. 第一条分界线距离上下卡片距离和第二条不一样」）—— 当前口径（这两条是同一个几何模型）：**
- **时间轴全天占位**：`_todayCourseSlots` 返回 `SizedBox(key: Key('dashTodayTimeline'), height: schedulePeriodCount * todayCourseTrackHeight - todayCourseSlotGap + shifted)` —— **末尾没课的节次也留高度**，最后一门课之后始终有余量（当天最后一块 10-11 节 → 时间轴 414dp、块底 380dp、余 34dp = 一个节次）。旧的 `previousEnd == 0 ? 0 : (previousEnd-1)*track + slot`（末尾截断）**已删**，守卫禁止 `previousEnd == 0` 回归。
- **每条分隔线几何完全一致**：空档不足 `dashboardBreakBandHeight`(14) 时**把它撑开**（不是把带压扁）—— `extra = rawGap >= band ? 0 : band - rawGap`、`shifted += extra`，后续课块 `top = (start-1)*track + shifted`。任何一条线都是：带高 14 = 线上留白 4 + 线 2 + 线下留白 8；线底距下一块恒为 `dashboardBreakLineGap`(8)。⚠ 六轮那版「窄空档把带收缩进 4dp、线上下各 1dp」**已废**（与宽空档那条观感不一致，正是七轮报的「不一样」）。
- **几何算式（改代码/写断言照抄）**：`rawGapTop = (prevEnd-1)*track + slot`、`rawGapBottom = (start-1)*track`、`rawGap = rawGapBottom - rawGapTop`；带 `top = rawGapBottom + shifted(含 extra) - band`；**线底距带顶 = band − lineGap = 6**（`band` 已含线高，别再减一次 lineHeight —— 我第一版断言正是这么算错的：期望 4 实得 6）。真实数据（当天 3-5 / 6-7 / 10-11 节：午休 5→6 钟点差 100 分钟、时间轴只差 4dp；7→10 空两节 72dp）→ 午休那条撑到 14dp、7→10 那条仍 72dp、时间轴 414dp。守卫 = `test/home_dashboard_layout_test.dart` 的「两条分隔线几何完全一致 + 最后一门课之后仍留出全天余量（七轮）」例（同时断言 `Key('dashTodayTimeline')` 高度 = `12*34-4+10`）。

**六轮补丁（同日，用户原话：「我希望主页课表卡片内容宽度不够不要显示省略号，而是换行；缩小左右卡片间距；现在分割线有一条不可见，按理说是两条，但是现在只能看见第二条」）—— 栏间距与换行仍是当前口径；分隔线口径见七轮：**
- **栏间距 = `dashboardColumnGap = 10`**（原 16）：`Row[Expanded(flex: 2, child: metrics), SizedBox(width: DashboardPanel.dashboardColumnGap), Expanded(child: today)]`；守卫按 `today.dx - (metrics.dx + metricsSize.width) ≈ 10` 断言，**别写死 16**。

### 17.9 宫格聚合：长按拖动 / 边缘合并 / 异形嵌合（2026-09-21 用户原话立项）

用户原话：「宫格视图下，我希望增加聚合功能。现有的相当于每个宫格都是一个仅包含一个功能的卡片，我希望长按拖动后可以合并宫格，并且，宫格这样显示：宫格可以异形，长按拖动到其他卡片边边上时（必须要在某个边缘处，处于中间则此次拖动松手后不触发合并），松手后，合并到此边相邻的位置，然后并且未松手时，要在相应位置显示虚线框，如果没有与任何卡片相邻，则松手不触发合并。然后我们允许长按卡片调整位置（即使是异形的），并且要允许两个互补的卡片相互嵌套，例如一正一反两个大写 F 形的卡片可以相互插入空隙」。

**领域层（纯函数，全部可单测）**
- `lib/features/home/domain/home_grid_shape.dart`：`typedef GridCell = ({int x, int y})`（record，`Set`/`Map` 的键免费）+ `gridBoundsOf` / `gridWidthOf` / `gridHeightOf` / `gridTranslated` / `gridConnected`（四邻连通）/ `gridTouching` / `gridOverlaps` / `gridShapeKey` / `gridCompare`（行优先）/ `gridSorted`。
- `lib/features/home/domain/home_grid_layout.dart`：
  - `class HomeGridTile { List<String> titles; List<GridCell> cells; }` —— **一个格子放一个服务**（`cells.length == titles.length` 恒成立，`cells[i]` 属于 `titles[i]`，按行优先排序；构造时**按对重排**，脏存档里格子乱序也不会让服务串位）。服务身份 = **标题**（与 `home_screen` 的 `_selectedService`、`Key('homeTile-<title>')` 同口径）。
  - `class HomeGridLayout { int cols; List<HomeGridTile> tiles; }` —— 位置是**绝对格坐标**（不是「顺序 + 自动流式」）：用户要的「合并到此边相邻的位置 / 调整位置 / 互补嵌合」都必须精确落位。`flow`（默认 = 目录顺序一行一行铺，与重构前 `Wrap` 逐格一致）/ `reconcile`（与当前目录对账：在的服务原位保留、删掉的连格子去掉、新加的落到**第一个空隙**，末尾校验不自洽就退回 `flow`）/ `fitTo`（列数一致原样返回，变了才 `packed`）/ `packed`（阅读序首次适配装箱，**会填进前面卡片留下的空隙** → 互补异形自动嵌合；比列数还宽的卡拆成单格）/ `reflowed({anchored})`（**让位**：落点卡片钉死，只把与它撞车的卡片挪到第一个空位）。
  - `homeGridPlanDrop({layout, draggedKey, pointerCell, grabCell, pointerFractionX/Y, edgeBand})` → `HomeGridDropTarget?`（null = 松手什么都不做）。`kHomeGridEdgeBand = 0.34`。
  - `homeGridLayoutJson` / `homeGridLayoutFromJson`（脏 / 旧 / 越界 / 重叠 / 不连通一律 null，由调用方回落默认；**绝不抛异常**）。

**落点口径（逐字对应需求）**
1. 指针落在**别的卡片**上 → 在该格子内按比例找最近的**外露边**（同一张卡内部两个格子之间的缝**不是边**，异形的内凹处才是合法落点）；四条边的最短距离都 > `edgeBand` = **指针在卡片中间 → 不合并**（也不移动）。
2. 选中哪条边，就落在**指针那格的相邻那一格**上（右 → `pointerCell.x + 1`，依此类推），另一轴与指针所在的行 / 列对齐 → 「合并到此边相邻的位置」；落点越界 / 与目标不相接 → null。
3. 落点上原本站着的**卡片一起并进来**（`HomeGridDropTarget.joined` 里带着它挪之后的新位置），并且**整条尾巴沿合并方向往后推开一位**（`pushed` = 只被推开、不进合并的卡片）。用户 2026-09-21 三轮口径（逐字）：「三张并成一张：C 也一起并进来（B + A + C 三格一张卡），虚线框显示这个更大的形状」。实现要点：
   - **为什么会撞车**：落点那格（= C 的格子）要装下被拖的 A，C 又要保住自己的服务 → 合并卡必须**长出来**：C 整体挪到落点外侧（`_pushVector`：`落点右边界 + 1 − C 左边界`，即往右并就右移一位），它的**旧格子接管 A**、新格子装 C → 三格连成一块。
   - **连锁**：C 挪过去的位置上若站着 D，D 跟着挪同一位移（整条尾巴同一向量，保持相对顺序）；再撞再挪，直到不撞。挪**出界**的卡片不硬挪，交给 `apply` 的 `reflowed` 让位（挪到第一个空位 —— 通常正好是被拖卡片空出来的那格）。
   - **兜底**：合并后的形状不连通（`gridConnected` 不过）→ 退回「只并指针压着的那张」，被拖卡片原来的位置由 `reflowed` 让位（老口径）。`cols=3` 那种「C 右边就是网格边界」的情况走的就是这条。
   - 落点若压回目标卡自己身上（同一格要写两个标题、必丢一个服务）→ 整个方案不认（`gridOverlaps(landing, target)` → null）。
4. 指针落在**空格** → 纯移动（不合并）；落点被占 / 越界 → null。「互补嵌合」走的就是这条路：把卡片拖进异形卡片的缺口（`_canPlace` 只看格子空不空）。
5. 未松手时：抬起的那张卡跟着指针（`Opacity .94` + `Transform.scale 1.02` + `drawShadow`），**虚线框画的是「合并后的那张卡」**（`HomeGridDropTarget.mergedResult` = `target ∪ landing ∪ 一起并进来的卡` 的并集形状 → `Key('homeGridPreview')`），参与合并的每张卡各淡染一层（第一张 `Key('homeGridPreviewTarget')`，其余 `Key('homeGridPreviewTarget-<卡片key>')`）；被推开的卡片在**新位置**画一圈细实线（`Key('homeGridPreviewPush-<卡片key>')`，同一个画笔用 `dash: 1e6` 当实线）—— 不提前画出来的话松手后那一跳很突然。用户 2026-09-21 二轮原话：「我希望显示的虚线框是与将要连接的卡片相连的，而不是单纯相邻，换言之，我希望虚线框展示合并后的卡片形状」—— 修复前虚线框只画落点那一格（贴着目标卡的一个独立方框，与松手后的结果不是一回事）。
6. 长按手势挂在**每一格的脸**上 + **格与格之间的缝**上（不是整张卡的包围盒）：异形卡片的包围盒里可能有别人嵌进来的格子，挂外框会把那格的手势吞掉。四轮起两者的含义不同 —— 见 §17.10：脸 = 拖**这一个功能**，缝 = 拖**整张卡**。

**持久化**

**渲染（`presentation/home_grid_card.dart` + `home_grid_metrics.dart`）**
- 排版从 `Wrap` 换成 `Stack` + `Positioned`（位置来自布局的绝对格坐标）；`HomeGridMetrics` 是列数 / 格宽 / 格高 / 格子↔像素换算的唯一出处（列数算法**逐字沿用**重构前实现，`HomeServiceGrid` 的静态常量转发过去，测试仍有运行时引用）。
- 卡片轮廓 = `homeGridShapePath`：**先取形状的轮廓环（`gridOutlineLoops`），再把每个 90° 转角做成半径 `kAppCardRadius` 的圆角 —— 凸角收圆、凹角倒圆**，所以一整块异形看起来仍是一张卡。**不再用「逐格圆角矩形做布尔并」**：那种写法在拐弯内侧、格缝交叉处会留下一个 12×12 的方角突起（用户 2026-09-21 三轮原话：「卡片在拐弯的时候，内侧会有一个突起，我希望做成圆角」）。
- ⚠ **「格线」是两条边，不是一个位置**：同一张卡里相邻两格的 12px 格缝由轮廓环**天然吃掉**（环只沿格线走，缝在环内部），但一条格线在像素上有两个坐标 —— 左格的右边（`k*步距 - 缝`）与右格的左边（`k*步距`）。取哪个取决于**卡片在那一侧有没有格子**，判据来自轮廓环的绕向约定（内部恒在前进方向右手边）：向下走 → 料在左（取 `k*步距 - 缝`）、向上走 → 料在右（取 `k*步距`）；向左走 → 料在上（取 `k*步距 - 缝`）、向右走 → 料在下（取 `k*步距`）。`_outlineVertex` 就是这条：**竖边给 x、横边给 y**。把格线当固定位置会让异形卡片的内拐角整体偏一个缝宽（12px，实测 5 格 P 形拐角后的竖边会画在 212 而不是 224）。
- ⚠ **内部格缝仍然必须填上**：轮廓环不带缝，所以合并卡片中间不会露页面底色（暗色主题下那条黑缝、浅色主题下 `toImage` 扫到的透明列，都是首轮像素守卫抓到的真 bug）；改了轮廓算法之后这两条守卫都照旧保留。
- 卡片内部：每格一张磁贴的脸（与重构前 `_HomeTile` 逐字同款）；**格与格之间默认什么都不画**（`HomeGridCard.showDividers` 默认 false —— 用户 2026-09-21 四轮：「我希望功能与功能之间不显示分割线」）；`kHomeGridDividerInset = 12` 的分隔短线只有拆解模式才由宫格图层画出来（见 §17.10）。

**三个必踩的坑（都实测过，写在代码注释里了）**
1. 拖动中的那张卡**既不能从树里摘掉、也不能临时套一层新壳**：① `if (tile.key != _dragKey)` → 长按识别器随 Element dispose；② 只在 hidden 时才包 `Opacity` → 单子节点 reconciliation 不比 key，`HomeGridCard` 整个子树被重建、识别器同样换新。两种写法都让 move / end 事件再也送不到（卡片卡在半空、松手没反应）。正解 = **恒存**的 `Opacity(opacity: hidden ? 0 : 1, ...)`。
2. `Tooltip` 在触摸端默认**长按**触发，会与拖动抢手势（见 §17.2）→ `triggerMode: manual`。
3. 被拖动卡片**不能从树里删**这一条还有个副作用：拖起来之后原位置那张隐形的卡仍会命中长按（第二根手指按上去会再起一个拖动），可接受。

### 17.10 分割线 · 拆解模式 · 长按功能部分单拖（2026-09-21 四轮）

用户原话（逐字）：
1. 「我希望功能与功能之间不显示分割线」
2. 「我希望可以进入拆解模式，此模式下，才显示分割线，点击分割线后，此边处不连接，分成两部分，因此形成的边界，暂时显示为虚线。退出拆解模式时，如果有些分割线分开的两边没有分开（还在其他地方相连），则恢复此处连接。」
3. 「然后长按卡片也分为长按到功能部分，和卡片其余部分，前者不再移动整个卡片，而是改成后者移动整个卡片，长按到功能部分时，只移动此功能，同样要用虚线展示预期效果」

**模型（`lib/features/home/domain/home_grid_split.dart`，纯函数）**
- `typedef GridSeam = ({GridCell a, GridCell b})` —— 一条缝 = 同一张卡里两个**相邻**格子之间的连接；`gridSeam(a, b)` 规范化成有序对（`gridCompare` 小的当 `a`），所以缝的身份**只由两格坐标决定**、不需要卡片 key 参与，界面层的暂存集合就是 `Set<GridSeam>`；`gridSeamKey` = `"x,y-x,y"`（widget key / 断言用）。
- `gridSeamsOf(cells)` = 这张卡全部相邻对（阅读序）；`gridComponents(cells, {cuts})` = 按「没被剪断的缝」分连通块；`homeGridSplitTile(tile, {cuts})` / `homeGridSplitAll(tiles, cuts)` = 把卡片拆成若干张（**没有真拆开时原样返回同一个对象**，`identical` 可断言）。
- `homeGridEffectiveCuts(tiles, cuts)` —— **退出拆解模式时的结算**：判据 = 把全部缝一起剪断后，这条缝的两格是否落在不同连通块里。串联的两条缝（单独剪任一条都还连着）因此都算数；绕路还连着的缝被丢掉（用户口径 2）。⚠ 2×2 里剪掉上边那条缝 ≠ 断开：A 还能走 A-C-D-B 绕过去 → 一条都不留；两条水平缝一起剪才真的分成左右两列。
- `homeGridExtractCell(tile, cell)` → `({moved, rest})` —— 长按**功能部分**时把那一格抠出来：`moved` = 单格卡、`rest` = 剩下的连通块（**可能不止一张**：抠走 I 形中间那格，两边就断成两张卡）。容错：格子不在卡里 / 卡是空的都不抛异常。

**界面（`presentation/home_service_grid.dart`）**
- 分割线 = 缝图层，只在 `editMode` 打开时渲染（该字段原名 `splitMode`，用户 2026-09-21 九轮把整个模式改名为**编辑模式**，见 §17.13）：每个缝一条 `Key('homeGridSeam-<a>-<b>')` 的命中带（缝 12px + 两侧各 `kHomeGridSeamHitPad = 4` → 20px 宽），**点一下剪断 / 再接回**（`_toggleCut`）。没断开 = 卡片描边同色的细实线（`kHomeGridDividerInset` 两端缩进 12）；断开 = 主题红虚线（`dash 5 / gap 4`，通长不缩进）—— 「形成的边界暂时显示为虚线」。
- 剪断后**当场**把卡片按连通块拆成几张卡渲染（`_displayLayout`）；退出拆解模式时 `didUpdateWidget` 把 `_cuts` 快照交给 `_commitCuts` → 只有 `homeGridEffectiveCuts` 认的缝才落盘（`onLayoutChanged` → store），其余接回去。
- ⚠ **`_commitCuts` 必须挪到帧末**（`WidgetsBinding.instance.addPostFrameCallback`）：`didUpdateWidget` 发生在父级 build 期间，而此刻当前构建目标是宫格下面的手势识别器（**不是父级的祖先**）→ 父级同步 `setState` 会被框架拒：`setState() or markNeedsBuild() called during build`（实测报在 `_Host` 上）。
- ⚠ **手势带不能因为「开始拖动」而从树里摘掉**：`_bodyHandle` 必须**恒存**（原来写成 `else if (_dragKey == null)` → 拖动一开始就把带子摘掉 → 长按识别器随 Element dispose → `move` / `end` 再也送不到 → 松手无反应、`onLayoutChanged` 一次都不回调）。这是本模块第三次踩同一类坑（前两次见 §17.9 的坑 1 与「抠格」那条）。
- ⚠ **拖单格时不能在渲染布局里抠格**：抠格会让源卡片的 key 变掉（原卡换成「抠出来那格 + 剩下的部分」）→ 那张卡（手势挂在它的脸上）整个子树被重建 → 识别器换新、拖动断在半路。正解 = 抠格只进**落点方案**（`_baseLayout`）与**抬起的卡**（`_dragTile`），松手才真的改写布局（`_displayLayout` 用 `_savedLayout`）。
- 长按口径（用户口径 3）：**脸** → `_startDrag(tile, cell, …)` = 只拖这一格（抬起的卡就是那张单格卡；落点方案在「已抠出这一格」的布局上算，落点虚线框照旧画合并后的形状）；**缝**（`_bodyHandle`，`HitTestBehavior.translucent` → 轻点仍穿透到脸，只有长按起手）→ `_startDrag(tile, null, …)` = 拖整张卡（老行为）。~~拆解模式里拖动整体关闭（`_startDrag` 直接 return），模式内只做断开 / 接回~~ —— **这条口径九轮已作废**：编辑模式里按下即拖、点击拿起再点放下（见 §17.13）。⚠ 六轮起「脸」收窄成「功能内容块」，见 §17.11。
- 入口 = **设置页**「主页布局 → 宫格聚合」卡里的 `Switch(key: Key('homeEditModeSwitch'))`（**十三轮起从主页顶栏搬来**，见 §17.17），拨动时弹一条 `Key('homeGridEditHint')`（原名 `homeGridSplitHint`）的说明。状态 = `homeEditModeProvider`（`lib/features/home/data/home_edit_mode.dart`，**一次性编辑动作，不进 Hive**）；主页 `_buildGridBody` `ref.watch` 它并喂给宫格的 `editMode`。

**守卫**

### 17.10.1 ⚠ 带 action 的 SnackBar 默认**永不消失**（用户 2026-09-21 五轮：「合并后，底部的提示信息不消失」）

根因不在本模块，在框架默认值 —— 本机 Flutter 两处源码对读即可确认：

- `<FLUTTER_ROOT>\packages\flutter\lib\src\material\snack_bar.dart:303`：`persist = persist ?? action != null;` —— **只要给了 `action`，`persist` 就默认 true**。
- `<FLUTTER_ROOT>\packages\flutter\lib\src\material\scaffold.dart:618-625`：自动消失计时器 `Timer(snackBar.duration, () { … if (snackBar.persist) return; hideCurrentSnackBar(reason: SnackBarCloseReason.timeout); })` —— **计时器照常建，回调第一句就返回**。
  （计时器只在 `ScaffoldMessengerState.build` 里创建，条件 `_snackBars.isNotEmpty && (route == null || route.isCurrent) && _snackBarController!.isCompleted && _snackBarTimer == null`；`AnimationStatus.completed` 会 `setState` 触发这次 build，所以 `persist` 之外没有别的坑。）

结论：**页面上写的 `duration:` 对带 action 的提示形同虚设**。修法 = 显式 `persist: false`。

### 17.11 功能的抓取区不要太大（2026-09-21 六轮）

用户原话（逐字）：「我们希望每个卡片内，功能的点击区不要太大，不然就很难移动整个卡片」。

**口径**：「功能部分」从**整格**收窄到**功能的内容块**。
- 每格只有内容块（图标 / 标题 / 副标题那一块）长按才拖**这一个功能**；格子减去内容块的那一圈 + 格与格之间的缝都算「卡片其余部分」= 长按拖**整张卡**。桌面 212×88 的一格：内容块 180×56、四周留 16px 的圈；相邻两个功能的内容块之间因此有 `16 + 12 + 16 = 44px` 的整卡抓取走廊（此前整卡只能抓缝上那 20px 的带）。
- **脸的视觉与轻点区照旧占满整格**（点整格任何位置都能打开功能、水波纹与 hover 也照旧）—— 收窄的只是「长按 → 起手拖动」的判定区。

**实现**
- 内容块内边距的**唯一出处** = `lib/features/home/presentation/home_grid_card.dart` 的 `EdgeInsets homeGridFaceContentPadding({required bool compact})`（紧凑 `8 / 14`，宽屏 `16`）—— `HomeGridTileFace` 自己的 `Padding` 与界面层的抓取区**共用这一个函数**，否则「看得见的功能」和「抓得住的功能」会差一条边。
- 三个手势层**同格内自上而下 = 抓取区 → 卡片其余部分 → 脸**，都挂在 `home_service_grid.dart` 的 `faceWrapper` 里（`Stack`）：
  - 抓取区 `Key('homeGridGrip-<服务名>')` = `Positioned.fill` + `Padding(content)` + `GestureDetector(translucent, 长按 → _startDrag(tile, cell, …))`；
  - 卡片其余部分 `Key('homeGridCardBody-<服务名>')` = 整格 `GestureDetector(translucent, 长按 → _startDrag(tile, null, …))`（整格覆盖，但抓取区压在它上面 → 实际只有那一圈生效）；
  - 两层都 `HitTestBehavior.translucent`：轻点继续穿透到脸的 `InkWell`（打开功能 / 水波纹 / hover 全保留），长按则靠 **hit-test 顺序**（topmost 先入 arena）让「抓取区」赢过「卡片其余部分」。
- ⚠ **层序是硬的**（写错过一次，实测症状 = 长按空白处 `homeGridLifted` 根本不出现）：脸的 `InkWell` 是 `HitTestBehavior.opaque`，会把手势吞在它自己身上 → 「卡片其余部分」那一层**必须压在脸之上**；而抓取区又**必须压在它之上**（否则两者都在 arena 里、更靠前的整卡层会赢，单拖功能就没法触发）。曾试过「整张卡一层 `bodyWrapper` 罩住 + 抓取区 translucent」——**不可行**：整卡层在 Stack 里必然在「脸（含抓取区）」之上，两条手势都会先落到它手里。
- 缝上的 `_bodyHandle`（`kHomeGridSeamHitPad` 20px 带）在几何上与卡片自己的手势层重合（同一张卡、同一动作），保留它作兜底（轮廓裁剪在极端异形上万一判掉某条缝，缝上仍有得抓）。
- **原地长按松手 = 什么都不改**（本轮顺带修掉的真 bug）：`_finishDrag` 在 `notify(next)` 之前比一次**语义指纹** `_layoutSignature(layout)`（每个服务 → 它占的那一格，排序后 join），一样就直接 return。**不能直接比 `HomeGridLayout`**：它的值相等连「分卡方式」与「卡片顺序」一起比，而拖单格时基准布局（`_baseLayout`）里那一格已经被抠成单独一张卡，落点又把它放回原处 → 服务位置全一样、值却不相等。修之前：**长按某一格不动就松手**会把那张卡真拆成「这一格 + 其余」两张并写盘（真机实测：原地长按一下，存档就多一次改写）。守卫 = 该组的「长按不动就松手：什么都不落盘」1 例（同时按功能内容块与卡片空白圈各来一下，断言 `saved` 为空）；**已反向验证**（把守卫改成恒不成立 → 该例立刻失败）。

- **`kHomeGridEditTouchSlop = 2`**：pan 默认要 `kPanSlop = kTouchSlop × 2 = 36` 才起手（`events.dart:2566` `computePanSlop` 触摸走 `settings?.panSlop ?? kPanSlop`），而**祖先滚动视图只要 18px 就先赢**（宫格长在主页滚动视图里）→ 手机上「按下即拖」会变成滚页面。修法 = 编辑模式下把宫格自己的子树包一层
  ```dart
  MediaQuery(
    data: MediaQuery.of(context).copyWith(
      gestureSettings: const DeviceGestureSettings(touchSlop: kHomeGridEditTouchSlop),
    ),
    child: grid,
  )
  ```
  （`touchSlop` 2 → `panSlop` 4）。**只包自己的子树**：祖先滚动视图读的是它自己的 MediaQuery，阈值仍是 18。⚠ `DeviceGestureSettings` 不在 `material.dart` 的导出面里 → 需要 `import 'package:flutter/gestures.dart' show DeviceGestureSettings;`。鼠标不受此限（`computePanSlop(mouse)` 恒为 `kPrecisePointerPanSlop`），且桌面端鼠标拖动本来就不会滚页面。
- 抓手偏移按**按下那一刻**算：pan 起手时指针已经移过一个阈值了，用 `onPanDown` 记下的 `_pressGlobal` 才不会让卡片相对手指错位（§17.9 的幽灵卡渲染 `pointer - _grabPixel`）。

**③ 点击拿起 / 再点放下**
- `_tapGrab(tile, cell, …)`：手上没东西 → `_startDrag(…, byTap: true)`（拿起，同一套抬起渲染 + 虚线框）；手上已有 → `_tapDrop(global)`。
- `_tapDrop(global)`：把指针位置换算成落点 —— **优先复用拖动那套** `homeGridPlanDrop`（贴边 → 合并、空格 → 移动；虚线框一直显示的就是它），`_plan == null`（指针压在别的卡片**中间 / 内缝**）时退化成 `homeGridPlanTapDrop`（**纯移动**：抓手格落到点中那一格，原主人由 `apply` 的 `reflowed(anchored:)` 让位）→ 然后 `_finishDrag()`。
- `homeGridPlanTapDrop({required layout, required draggedKey, required pointerCell, required grabCell})`（`lib/features/home/domain/home_grid_layout.dart`，纯函数）：拖动版对「中间」返回 null 是用户口径（「处于中间则此次松手后不触发合并」），而「点一下放下」必须有个结果，否则点哪儿都没反应；落点越界 → null（这次点击等于取消）。
- 点回自己原来的位置 = `_layoutSignature` 不变 → 不落盘（等于取消），卡片也不会被拆成两张（§17.11 那条语义指纹早退照旧生效）。
- 桌面端**鼠标跟随**：编辑模式在最上层加一层 `MouseRegion(key: Key('homeGridEditHover'), hitTestBehavior: translucent, opaque: false, onHover: (e) => _updateDrag(e.position))` —— 拿着东西时虚线框与幽灵卡跟着鼠标走。⚠ 必须 `translucent` + `opaque: false`：它既不能吃掉下面卡片 / 分割线的指针事件，也不能挡住下面分割线的手势光标。
- **点空白处放下**：`Positioned.fill(GestureDetector(key: Key('homeGridEditBackground'), translucent, onTapUp: …))` 垫在 Stack **最底下**（只有没点到任何卡片 / 分割线时才轮得到它；没拿着东西时是空操作）。
- 缝：没拿着东西时点 = 断开 / 接回；**拿着东西时点 = 先放下**（不切换断开，否则「拿起 → 点到缝上」会顺手改坏分卡方式）。
- 退出编辑模式 / 顶栏重置：`didUpdateWidget` 里 `_clearDrag()`（手上还拿着的就地放下 = 取消，不落盘），**不能 `setState`** —— 那一刻本来就在 build 里，直接改字段即可。

**④ ⚠ 踩到的坑（同一次按下里 `onPanCancel` 先于 `onTapUp`）**
- 症状：**「点一下拿起 → 再点一下放下」的第二下反而重新拿起**（幽灵卡一直在，布局不动）。
- 机制：同一次按下里 tap 与 pan 都进 arena；指针抬起时 pan 先被判负 —— `DragGestureRecognizer.handleEvent(PointerUpEvent)` → `_giveUpPointer` → `resolvePointer(rejected)` → **`onPanCancel` 立即回调**；而 tap 要等 `GestureArenaManager.sweep`（同一个 `GestureBinding.handleEvent` 里 `route` 之后）才 `acceptGesture` → `_checkUp` → `onTapUp`。于是顺序是 `onPanCancel` → `onTapUp`：不区分来源的话，`_cancelDrag` 会先把「刚拿起的」清掉、紧接着 `_tapGrab` 又把它拿起来。
- 修法：`bool _tapPicked`（`_startDrag(…, {bool byTap = false})` 里落值，`_clearDrag` 复位），`_cancelDrag()` 改成 `if (_dragKey == null || _tapPicked) return;` —— **只清「拖起来的」那一次拖动**；点起来的东西留在手上等第二下。
- 对照组：点空白处放下（背景层**只有** tap、没有 pan）从来不会中招 —— 这也是为什么第一版用例里「点空格子放下」全绿、而「再点同一张卡放下」全红。

### 17.14 悬停提示要停留一会 / 按下不提示 + 拖某一格时原位留空（2026-09-21 十轮）

用户原话（逐字）：
1. 「不要功能的悬停显示不要立刻显示，只有鼠标停留一会后才显示，但是如果是鼠标按下的状态，则不显示」
2. 「我希望长按组合卡片的某一个功能时，此时原位置卡片的此功能不显示，而是只显示被我拖动的状态」

**① 悬停提示：两档 `waitDuration`（不是摘 Tooltip）**
- 脸（`HomeGridTileFace`）的 `Tooltip` **一直在树里**，只改一个属性：
  ```dart
  waitDuration: showTooltip ? kHomeGridTooltipWait : kHomeGridTooltipSuppressed,
  ```
  `kHomeGridTooltipWait = Duration(milliseconds: 600)`（`lib/features/home/presentation/home_grid_card.dart`；框架默认是 `Duration.zero`，所以才「一碰就弹」）、`kHomeGridTooltipSuppressed = Duration(days: 1)`（等于不显示）。
- ⚠ **为什么不能「按下时把 Tooltip 从树里摘掉」**：摘掉会让 `Tooltip` 与脸之间的父子结构变化 → 脸的 `InkWell`（它才是「轻点打开功能」的识别器）随 Element 一起重建 → **按下那一刻正在进行的这次点击被丢掉**。改 `waitDuration` 只是**属性**变化，树形与 Element 都不动。本模块已经三次踩过「手上的识别器被 dispose，拖动断在半路」。
- 框架侧的两条免费保险（读源码确认）：① `Tooltip.waitDuration` 只在**鼠标进入悬停那一刻**读一次（`tooltip.dart` `_handleMouseEnter` → `_scheduleShowTooltip(withDelay: _waitDuration)`）→ 所以「按着时进悬停」读到的是被抑制的那档；② 任何 `PointerDownEvent` 都会让框架把已排队的显示计时器**取消**、把已经显示的**收掉**（`_handleGlobalPointerEvent` → `_handleTapToDismiss` → `_scheduleDismissTooltip(withDelay: Duration.zero)` → `_timer?.cancel()`）。
- 网格侧两个门控（`home_service_grid.dart`）：`bool _pointerDown`（根上挂一层 `Listener(behavior: translucent, onPointerDown/Up/Cancel: …)`，**不参与手势竞技场、不吃事件**）+ `_dragKey != null`；脸收到的是 `showTooltip: !_pointerDown && _dragKey == null`。被抬起的幽灵卡永远 `showTooltip: false`（它就在指针底下，否则拖到一半会在手指上弹出来）。
- `_startDrag` 里再补一句 `Tooltip.dismissAllToolTips()`：「点一下拿起」是**抬起之后**才起手的，那一刻没有 `PointerDownEvent`，框架那条保险不生效。
- 语义上的取舍（有意）：鼠标离开某个功能再回来才会重新计时；**松开之后不会在原地补弹**（`enabled` 只影响「以后进入悬停时读到的值」）。
- 触摸端没有变化：`triggerMode: TooltipTriggerMode.manual` 照旧（§17.9 的坑：默认的长按触发会抢拖动的手势）。

**② 拖某一格时，原位不再显示这个功能**
- `HomeGridCard` 新增 `Set<GridCell> blankCells`（默认空集）：`_faces()` 里命中的格子给 `faceWrapper` 传一个 `const SizedBox.expand()` 当 `face` —— **卡片形状 / 底色不动，只是那一格空着**。
- ⚠ **只能换 `faceWrapper` 收到的那个 `face`**：两条手势带（`homeGridGrip-*` / `homeGridCardBody-*`）是它的**兄弟**，拖动识别器就挂在它们身上 —— 把整格从树里摘掉等于让识别器随 Element dispose（本模块三次同款坑）。
- 界面层怎么算：`_extractFrom == tile.key && _extractCell != null` → `blankCells = {_extractCell}`（`_card()` 里）。抬起的幽灵卡有自己的 key，不受影响。
- 覆盖两种拿法：普通模式长按某一格、编辑模式「点一下拿起」（同一套 `_extractFrom/_extractCell`）；松手 / 放下后 `_clearDrag` 复位 → 空位补回来。
