### 17.6 Logo（**第三轮 5 版已交付、等用户挑**；前两批均已被否）

- **已安装的 logo 设计 skill（用户在 `~/.dsh/skills/`，2026-09-16 装）**：`logo-design`（rampstackco，23 KB + `references/` 7 篇：architectures-explained / symbol-approaches / typographic-registers / application-contexts / category-conventions / client-package / example-variant-spec）、`logo-designer`（neonwatty，SVG 迭代 + `scripts/`）、`logo-designer-svg`（luongnv89，7 变体 + showcase + `references/`）、`logo-design-brief`（seb1n）。**画 logo 前先读 `logo-design` 与其 references**。

### 17.7 侧栏点击 = 内嵌右侧面板（master-detail，2026-09-16 用户裁定第 2 条）

  - `homeGridLayoutJson` / `homeGridLayoutFromJson`（脏 / 旧 / 越界 / 重叠 / 不连通一律 null，由调用方回落默认；**绝不抛异常**）。

**落点口径（逐字对应需求）**
1. 指针落在**别的卡片**上 → 在该格子内按比例找最近的**外露边**（同一张卡内部两个格子之间的缝**不是边**，异形的内凹处才是合法落点）；四条边的最短距离都 > `edgeBand` = **指针在卡片中间 → 不合并**（也不移动）。
2. 选中哪条边，就落在**指针那格的相邻那一格**上（右 → `pointerCell.x + 1`，依此类推），另一轴与指针所在的行 / 列对齐 → 「合并到此边相邻的位置」；落点越界 / 与目标不相接 → null。
3. 落点上原本站着的**卡片一起并进来**（`HomeGridDropTarget.joined` 里带着它挪之后的新位置），并且**整条尾巴沿合并方向往后推开一位**（`pushed` = 只被推开、不进合并的卡片）。用户 2026-09-21 三轮口径（逐字）：「三张并成一张：C 也一起并进来（B + A + C 三格一张卡），虚线框显示这个更大的形状」。实现要点：
   - **为什么会撞车**：落点那格（= C 的格子）要装下被拖的 A，C 又要保住自己的服务 → 合并卡必须**长出来**：C 整体挪到落点外侧（`_pushVector`：`落点右边界 + 1 − C 左边界`，即往右并就右移一位），它的**旧格子接管 A**、新格子装 C → 三格连成一块。
   - **连锁**：C 挪过去的位置上若站着 D，D 跟着挪同一位移（整条尾巴同一向量，保持相对顺序）；再撞再挪，直到不撞。挪**出界**的卡片不硬挪，交给 `apply` 的 `reflowed` 让位（挪到第一个空位 —— 通常正好是被拖卡片空出来的那格）。
   - **兜底**：合并后的形状不连通（`gridConnected` 不过）→ 退回「只并指针压着的那张」，被拖卡片原来的位置由 `reflowed` 让位（老口径）。`cols=3` 那种「C 右边就是网格边界」的情况走的就是这条。
   - 落点若压回目标卡自己身上（同一格要写两个标题、必丢一个服务）→ 整个方案不认（`gridOverlaps(landing, target)` → null）。
4. 指针落在**空格** → 纯移动（不合并）；落点被占 / 越界 → null。「互补嵌合」走的就是这条路：把卡片拖进异形卡片的缺口（`_canPlace` 只看格子空不空）。
5. 未松手时：抬起的那张卡跟着指针（`Opacity .94` + `Transform.scale 1.02` + `drawShadow`），**虚线框画的是「合并后的那张卡」**（`HomeGridDropTarget.mergedResult` = `target ∪ landing ∪ 一起并进来的卡` 的并集形状 → `Key('homeGridPreview')`），参与合并的每张卡各淡染一层（第一张 `Key('homeGridPreviewTarget')`，其余 `Key('homeGridPreviewTarget-<卡片key>')`）；被推开的卡片在**新位置**画一圈细实线（`Key('homeGridPreviewPush-<卡片key>')`，同一个画笔用 `dash: 1e6` 当实线）—— 不提前画出来的话松手后那一跳很突然。用户 2026-09-21 二轮原话：「我希望显示的虚线框是与将要连接的卡片相连的，而不是单纯相邻，换言之，我希望虚线框展示合并后的卡片形状」—— 修复前虚线框只画落点那一格（贴着目标卡的一个独立方框，与松手后的结果不是一回事）。
6. 长按手势挂在**每一格的脸**上 + **格与格之间的缝**上（不是整张卡的包围盒）：异形卡片的包围盒里可能有别人嵌进来的格子，挂外框会把那格的手势吞掉。四轮起两者的含义不同 —— 见 §17.10：脸 = 拖**这一个功能**，缝 = 拖**整张卡**。

**持久化**
- `lib/features/home/data/home_grid_prefs.dart`：Hive box **`homeGridPrefs`** / key `gridLayout`（单 key JSON 整表）；`HomeGridStore extends ChangeNotifier with BoxReloadWatcher` + `homeGridStoreProvider`（照 `home_layout_prefs.dart` 范式，改动即时通知 → 松手即见）；`reset()` = 删 key → 回默认流式布局；`HomeGridStore({persist: false})` 供测试完全不碰 Hive。

**渲染（`presentation/home_grid_card.dart` + `home_grid_metrics.dart`）**
- 排版从 `Wrap` 换成 `Stack` + `Positioned`（位置来自布局的绝对格坐标）；`HomeGridMetrics` 是列数 / 格宽 / 格高 / 格子↔像素换算的唯一出处（列数算法**逐字沿用**重构前实现，`HomeServiceGrid` 的静态常量转发过去，测试仍有运行时引用）。
- 卡片轮廓 = `homeGridShapePath`：**先取形状的轮廓环（`gridOutlineLoops`），再把每个 90° 转角做成半径 `kAppCardRadius` 的圆角 —— 凸角收圆、凹角倒圆**，所以一整块异形看起来仍是一张卡。**不再用「逐格圆角矩形做布尔并」**：那种写法在拐弯内侧、格缝交叉处会留下一个 12×12 的方角突起（用户 2026-09-21 三轮原话：「卡片在拐弯的时候，内侧会有一个突起，我希望做成圆角」）。
- ⚠ **「格线」是两条边，不是一个位置**：同一张卡里相邻两格的 12px 格缝由轮廓环**天然吃掉**（环只沿格线走，缝在环内部），但一条格线在像素上有两个坐标 —— 左格的右边（`k*步距 - 缝`）与右格的左边（`k*步距`）。取哪个取决于**卡片在那一侧有没有格子**，判据来自轮廓环的绕向约定（内部恒在前进方向右手边）：向下走 → 料在左（取 `k*步距 - 缝`）、向上走 → 料在右（取 `k*步距`）；向左走 → 料在上（取 `k*步距 - 缝`）、向右走 → 料在下（取 `k*步距`）。`_outlineVertex` 就是这条：**竖边给 x、横边给 y**。把格线当固定位置会让异形卡片的内拐角整体偏一个缝宽（12px，实测 5 格 P 形拐角后的竖边会画在 212 而不是 224）。
- ⚠ **内部格缝仍然必须填上**：轮廓环不带缝，所以合并卡片中间不会露页面底色（暗色主题下那条黑缝、浅色主题下 `toImage` 扫到的透明列，都是首轮像素守卫抓到的真 bug）；改了轮廓算法之后这两条守卫都照旧保留。
- 卡片内部：每格一张磁贴的脸（与重构前 `_HomeTile` 逐字同款）；**格与格之间默认什么都不画**（`HomeGridCard.showDividers` 默认 false —— 用户 2026-09-21 四轮：「我希望功能与功能之间不显示分割线」）；`kHomeGridDividerInset = 12` 的分隔短线只有拆解模式才由宫格图层画出来（见 §17.10）。

**三个必踩的坑（都实测过，写在代码注释里了）**
1. 拖动中的那张卡**既不能从树里摘掉、也不能临时套一层新壳**：① `if (tile.key != _dragKey)` → 长按识别器随 Element dispose；② 只在 hidden 时才包 `Opacity` → 单子节点 reconciliation 不比 key，`HomeGridCard` 整个子树被重建、识别器同样换新。两种写法都让 move / end 事件再也送不到（卡片卡在半空、松手没反应）。正解 = **恒存**的 `Opacity(opacity: hidden ? 0 : 1, ...)`。
2. `Tooltip` 在触摸端默认**长按**触发，会与拖动抢手势（见 §17.2）→ `triggerMode: manual`。
3. 被拖动卡片**不能从树里删**这一条还有个副作用：拖起来之后原位置那张隐形的卡仍会命中长按（第二根手指按上去会再起一个拖动），可接受。

### 17.10 分割线 · 拆解模式 · 长按功能部分单拖（2026-09-21 四轮）

用户原话（逐字）：
1. 「我希望功能与功能之间不显示分割线」
2. 「我希望可以进入拆解模式，此模式下，才显示分割线，点击分割线后，此边处不连接，分成两部分，因此形成的边界，暂时显示为虚线。退出拆解模式时，如果有些分割线分开的两边没有分开（还在其他地方相连），则恢复此处连接。」
3. 「然后长按卡片也分为长按到功能部分，和卡片其余部分，前者不再移动整个卡片，而是改成后者移动整个卡片，长按到功能部分时，只移动此功能，同样要用虚线展示预期效果」

**模型（`lib/features/home/domain/home_grid_split.dart`，纯函数）**
- `typedef GridSeam = ({GridCell a, GridCell b})` —— 一条缝 = 同一张卡里两个**相邻**格子之间的连接；`gridSeam(a, b)` 规范化成有序对（`gridCompare` 小的当 `a`），所以缝的身份**只由两格坐标决定**、不需要卡片 key 参与，界面层的暂存集合就是 `Set<GridSeam>`；`gridSeamKey` = `"x,y-x,y"`（widget key / 断言用）。
- `gridSeamsOf(cells)` = 这张卡全部相邻对（阅读序）；`gridComponents(cells, {cuts})` = 按「没被剪断的缝」分连通块；`homeGridSplitTile(tile, {cuts})` / `homeGridSplitAll(tiles, cuts)` = 把卡片拆成若干张（**没有真拆开时原样返回同一个对象**，`identical` 可断言）。
- `homeGridEffectiveCuts(tiles, cuts)` —— **退出拆解模式时的结算**：判据 = 把全部缝一起剪断后，这条缝的两格是否落在不同连通块里。串联的两条缝（单独剪任一条都还连着）因此都算数；绕路还连着的缝被丢掉（用户口径 2）。⚠ 2×2 里剪掉上边那条缝 ≠ 断开：A 还能走 A-C-D-B 绕过去 → 一条都不留；两条水平缝一起剪才真的分成左右两列。
- `homeGridExtractCell(tile, cell)` → `({moved, rest})` —— 长按**功能部分**时把那一格抠出来：`moved` = 单格卡、`rest` = 剩下的连通块（**可能不止一张**：抠走 I 形中间那格，两边就断成两张卡）。容错：格子不在卡里 / 卡是空的都不抛异常。

**界面（`presentation/home_service_grid.dart`）**
- 分割线 = 缝图层，只在 `splitMode` 打开时渲染：每个缝一条 `Key('homeGridSeam-<a>-<b>')` 的命中带（缝 12px + 两侧各 `kHomeGridSeamHitPad = 4` → 20px 宽），**点一下剪断 / 再接回**（`_toggleCut`）。没断开 = 卡片描边同色的细实线（`kHomeGridDividerInset` 两端缩进 12）；断开 = 主题红虚线（`dash 5 / gap 4`，通长不缩进）—— 「形成的边界暂时显示为虚线」。
- 剪断后**当场**把卡片按连通块拆成几张卡渲染（`_displayLayout`）；退出拆解模式时 `didUpdateWidget` 把 `_cuts` 快照交给 `_commitCuts` → 只有 `homeGridEffectiveCuts` 认的缝才落盘（`onLayoutChanged` → store），其余接回去。
- ⚠ **`_commitCuts` 必须挪到帧末**（`WidgetsBinding.instance.addPostFrameCallback`）：`didUpdateWidget` 发生在父级 build 期间，而此刻当前构建目标是宫格下面的手势识别器（**不是父级的祖先**）→ 父级同步 `setState` 会被框架拒：`setState() or markNeedsBuild() called during build`（实测报在 `_Host` 上）。
- ⚠ **手势带不能因为「开始拖动」而从树里摘掉**：`_bodyHandle` 必须**恒存**（原来写成 `else if (_dragKey == null)` → 拖动一开始就把带子摘掉 → 长按识别器随 Element dispose → `move` / `end` 再也送不到 → 松手无反应、`onLayoutChanged` 一次都不回调）。这是本模块第三次踩同一类坑（前两次见 §17.9 的坑 1 与「抠格」那条）。

### 17.10.1 ⚠ 带 action 的 SnackBar 默认**永不消失**（用户 2026-09-21 五轮：「合并后，底部的提示信息不消失」）

根因不在本模块，在框架默认值 —— 本机 Flutter 两处源码对读即可确认：

- `<FLUTTER_ROOT>\packages\flutter\lib\src\material\snack_bar.dart:303`：`persist = persist ?? action != null;` —— **只要给了 `action`，`persist` 就默认 true**。
- `<FLUTTER_ROOT>\packages\flutter\lib\src\material\scaffold.dart:618-625`：自动消失计时器 `Timer(snackBar.duration, () { … if (snackBar.persist) return; hideCurrentSnackBar(reason: SnackBarCloseReason.timeout); })` —— **计时器照常建，回调第一句就返回**。
  （计时器只在 `ScaffoldMessengerState.build` 里创建，条件 `_snackBars.isNotEmpty && (route == null || route.isCurrent) && _snackBarController!.isCompleted && _snackBarTimer == null`；`AnimationStatus.completed` 会 `setState` 触发这次 build，所以 `persist` 之外没有别的坑。）

结论：**页面上写的 `duration:` 对带 action 的提示形同虚设**。修法 = 显式 `persist: false`。
